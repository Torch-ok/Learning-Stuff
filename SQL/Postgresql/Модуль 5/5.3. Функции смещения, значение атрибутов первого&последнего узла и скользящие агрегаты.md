#### Теоретический фундамент и архитектура

Оконные функции смещения и доступа к значениям позволяют архитектору БД обращаться к данным в строках, находящихся в определенной позиции относительно текущей записи, без выполнения ресурсоемких операций `SELF JOIN`,.

**Функции доступа к смещенным строкам:**

- **`LAG(expression, offset, default)`**: Позволяет извлечь значение из строки, которая «отстает» от текущей на указанное количество позиций (`offset`),,. Если смещение выходит за границы таблицы или партиции, функция возвращает значение `default` (по умолчанию `NULL`).
- **`LEAD(expression, offset, default)`**: Работает зеркально, предоставляя доступ к данным из «будущих» строк, следующих за текущей,,.
- **Применение**: Эти функции являются ключевым инструментом анализа временных рядов для расчета динамики продаж (Month-over-Month), вычисления интервалов между событиями и анализа «восхождений» или «спусков» в данных,.

**Функции выборки граничных значений:** Данная группа функций обеспечивает позиционный доступ к строкам внутри сформированного оконного фрейма,.

- **`FIRST_VALUE(expression)`**: Возвращает значение выражения для первой строки во фрейме,.
- **`LAST_VALUE(expression)`**: Возвращает значение для последней строки фрейма.
- **Ловушка дефолтного фрейма**: При использовании `ORDER BY` без явного указания границ фрейма PostgreSQL применяет рамку `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`,. В этом случае `LAST_VALUE()` всегда будет возвращать значение текущей строки (так как она является последней во фрейме на данный момент), что часто является логической ошибкой. Для корректной работы функции необходимо расширять верхнюю границу до `UNBOUNDED FOLLOWING`.
- **`NTH_VALUE(expression, n)`**: Позволяет получить значение из n-й по счету строки фрейма,.

**Накопительные и скользящие агрегаты:**

- **Накопительный итог (`Running Total`)**: Вычисляется как сумма всех значений от начала партиции до текущей строки включительно с помощью `SUM(...) OVER(ORDER BY ...)`,,.
- **Скользящий агрегат (`Moving Average`)**: Используется для сглаживания временных рядов,. Для расчета среднего значения за период (например, за последние 3 дня) применяется рамка физического смещения `ROWS BETWEEN n PRECEDING AND CURRENT ROW`,,.

#### Практическая реализация и синтаксис

**Расчет помесячной динамики выручки (MoM %):**

```
WITH MonthlyRevenue AS (
    SELECT
        DATE_TRUNC('month', created_at) AS sale_month,
        SUM(total_amount) AS revenue
    FROM orders
    GROUP BY 1
)
SELECT
    sale_month,
    revenue,
    LAG(revenue) OVER (ORDER BY sale_month) AS prev_month_revenue,
    -- Расчет прироста: (Текущий - Прошлый) / Прошлый * 100
    ROUND((revenue - LAG(revenue) OVER (ORDER BY sale_month)) /
          NULLIF(LAG(revenue) OVER (ORDER BY sale_month), 0) * 100, 2) AS growth_pct
FROM MonthlyRevenue;
```

,.

**7-дневное скользящее среднее (Moving Average):**

```
SELECT
    sale_date,
    daily_sales,
    AVG(daily_sales) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS rolling_avg_7d
FROM daily_revenue_stats;
```

,,.

**Корректный поиск последнего значения в партиции через `LAST_VALUE()`:**

```
SELECT
    product_id,
    price,
    -- Явное расширение фрейма до конца партиции
    LAST_VALUE(price) OVER (
        PARTITION BY category_id
        ORDER BY price
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS category_max_price
FROM products;
```

,.

#### Глоссарий терминов

- **Offset Window Functions (LAG / LEAD)** — функции, предоставляющие доступ к данным из строк, предшествующих текущей или следующих за ней,.
- **Value Extraction Functions (FIRST_VALUE / LAST_VALUE)** — функции для извлечения значений из строк, занимающих крайние позиции в оконном фрейме.
- **Frame Boundary Trap in LAST_VALUE** — архитектурная особенность, при которой функция `LAST_VALUE` возвращает текущую строку из-за дефолтных границ фрейма при наличии сортировки,.
- **Running Total (Cumulative Aggregation)** — вычисление накопленной суммы значений от начала набора данных до текущей точки,.
- **Moving Average (Rolling Window)** — статистический метод сглаживания данных путем усреднения значений в скользящем окне фиксированного размера,.
- **Positional Value Access (NTH_VALUE)** — возможность извлечения атрибута строки, находящейся на произвольной позиции (n) внутри фрейма,.

#### Практический кейс: Расчет сессий активности пользователей и времени между действиями

**Сценарий**: Необходимо выполнить сегментацию логов активности пользователей на сессии (Sessionization). Сессия считается завершенной, если между двумя последовательными действиями пользователя прошло более 30 минут.

**Реализация**:

1. Используем функцию `LAG(created_at) OVER(PARTITION BY user_id ORDER BY created_at)` для получения времени предыдущего действия,.
2. Вычисляем разницу между текущим и предыдущим таймстампом.
3. С помощью `CASE WHEN` проверяем, превышает ли интервал 30 минут. Если да — помечаем строку как начало новой сессии (флаг 1),.
4. Выполняем накопительную сумму этих флагов (`Running Total`), формируя уникальный идентификатор сессии для каждого пользователя внутри его партиции,.

#### Вопросы и задания для самопроверки

1. **Вопрос**: Почему запрос `LAST_VALUE(salary) OVER (ORDER BY hired_at)` возвращает зарплату текущего сотрудника, а не самого последнего нанятого по дате?,.
    - _Ответ: Потому что при наличии `ORDER BY` фрейм по умолчанию ограничен текущей строкой (`CURRENT ROW`)._
2. **Задача**: Напишите запрос для вычисления накопительного итога платежей. Как изменится результат при использовании `RANGE` против `ROWS`, если в таблице есть несколько платежей за одну и ту же секунду?,.
3. **Практика**: Составьте запрос, рассчитывающий время (в минутах), прошедшее между текущим и предыдущим заказом клиента. Для самого первого заказа клиента вместо `NULL` должно выводиться значение 0 (используйте третий аргумент функции `LAG`).
