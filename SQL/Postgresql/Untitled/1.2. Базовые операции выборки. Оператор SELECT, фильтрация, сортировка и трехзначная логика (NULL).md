
#### Теоретический фундамент и архитектура

В PostgreSQL понимание процесса выполнения запроса начинается не с того, как он написан, а с того, как его видит execution engine. Существует строгий **логический порядок обработки (Logical Query Processing Order)**: `FROM` -> `WHERE` -> `SELECT` -> `ORDER BY` -> `LIMIT` / `OFFSET` [Advanced SQL — Chapter 02 — Video #04 — SELECT/FROM/WHERE](https://notebooklm.google.com/notebook/36), [Advanced SQL — Chapter 02 — Video #11 — SQL reading vs. evaluation order, CTEs (WITH)](https://notebooklm.google.com/notebook/43).

Именно из-за этой последовательности псевдонимы (алиасы), определенные в блоке `SELECT`, недоступны в блоке `WHERE`. На момент фильтрации строк через `WHERE` проекция `SELECT` еще не выполнена, и система «не знает» о существовании новых имен столбцов [Advanced SQL — Chapter 02 — Video #04 — SELECT/FROM/WHERE](https://notebooklm.google.com/notebook/36), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).

**Фильтрация данных через `WHERE`**:

- **Операторы сравнения**: Используются для базовых условий (` = `, `<>`, `<`, `>`) [Шилдс Уолтер SQL.pdf](https://notebooklm.google.com/notebook/49).
- **Членство в множестве и диапазоны**: Оператор `IN` позволяет сопоставлять значение со списком, а `BETWEEN` — проверять вхождение в диапазон (включая границы) [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45), [Шилдс Уолтер SQL.pdf](https://notebooklm.google.com/notebook/49).
- **Сопоставление с шаблоном**: Оператор `LIKE` использует символы маски (`%` для любой последовательности и `_` для одного символа) [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45). В PostgreSQL для регистронезависимого поиска применяется специфичный оператор `ILIKE` [Advanced SQL — Chapter #03 — Video #13 — PostgreSQL built-in data types, CAST, casting text literals](https://notebooklm.google.com/notebook/1).

**Трехзначная логика SQL (Three-Valued Logic)**: В отличие от языков программирования с бинарной логикой, SQL оперирует тремя состояниями: `TRUE`, `FALSE` и `UNKNOWN` (`NULL`) [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).

- `NULL` — это не ноль и не пустая строка, а индикатор отсутствия значения или неопределенности [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45), [Шилдс Уолтер SQL.pdf](https://notebooklm.google.com/notebook/49).
- **Сравнение с NULL**: Любая попытка прямого сравнения `column = NULL` всегда вернет `UNKNOWN` (что трактуется как `FALSE` в `WHERE`), так как неизвестность не может быть равна чему-то [Advanced SQL — Chapter 02 — Video #04 — SELECT/FROM/WHERE](https://notebooklm.google.com/notebook/36), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45). Для проверки необходимо использовать специальные операторы `IS NULL` или `IS NOT NULL` [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).
- **Логические операции**: `TRUE OR UNKNOWN` дает `TRUE`, но `FALSE AND UNKNOWN` дает `FALSE`. При этом `NOT UNKNOWN` остается `UNKNOWN` [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).

**Сортировка и пагинация**: Предложение `ORDER BY` сортирует результаты в порядке `ASC` (по возрастанию) или `DESC` (по убыванию). Поскольку `NULL` считается неопределенным, в PostgreSQL можно явно управлять его позицией с помощью `NULLS FIRST` или `NULLS LAST`, чтобы пустые значения не нарушали логику интерфейса [Advanced SQL — Chapter 02 — Video #06 — ORDER BY/OFFSET/LIMIT/DISTINCT [ON]](https://notebooklm.google.com/notebook/38), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).

> [!warning] Актуализация синтаксиса 
> Использование `OFFSET` для глубокой пагинации на больших таблицах (сотни тысяч строк) является антипаттерном. База данных вынуждена сканировать и отбрасывать все предыдущие строки, прежде чем вернуть нужные, что ведет к деградации производительности [Advanced SQL — Chapter 02 — Video #06 — ORDER BY/OFFSET/LIMIT/DISTINCT [ON]](https://notebooklm.google.com/notebook/38).

#### Практическая реализация и синтаксис

Ниже приведен пример запроса с комплексной фильтрацией и обработкой `NULL`, а также современный подход к пагинации.

```sql
-- Выборка товаров с фильтрацией и учетом NULL-логики
SELECT product_id, name, price, description
FROM products
WHERE (category_id IN (1, 5, 10))
  AND (price BETWEEN 100 AND 5000)
  -- Регистронезависимый поиск по шаблону
  AND (name ILIKE 'premium%')
  -- Обработка строк, где описание не заполнено
  AND (description IS NOT NULL);

-- Детерминированная сортировка с NULLS LAST
SELECT ename, sal, comm
FROM emp
ORDER BY comm DESC NULLS LAST, ename ASC;

-- Keyset Pagination (вместо медленного OFFSET)
-- Предположим, мы на странице 10 и последний ID был 54321
SELECT id, created_at, username
FROM users
WHERE (created_at, id) < ('2026-07-30 02:00:00', 54321)
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

- **Three-Valued Logic (True/False/Unknown)** — логическая система SQL, где результат сравнения с `NULL` порождает неопределенность [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).
- **NULL Handling & IS NULL Operator** — специальные методы работы с отсутствующими значениями, исключающие использование оператора ` = ` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45).
- **Pattern Matching (LIKE / ILIKE)** — поиск по строковым шаблонам с использованием специальных символов подстановки [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45).
- **Deterministic Sorting (NULLS LAST)** — гарантированно повторяемый порядок строк, при котором `NULL` значения выносятся в конец списка [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).
- **Offset Pagination vs Keyset Pagination** — выбор между пропуском строк по номеру (`OFFSET`) и переходом к конкретной точке через сравнение ключей (`WHERE id > ...`) [Advanced SQL — Chapter 02 — Video #06 — ORDER BY/OFFSET/LIMIT/DISTINCT [ON]](https://notebooklm.google.com/notebook/38).

#### Практический кейс: Построение высокопроизводительной пагинации для каталога

При разработке каталога товаров e-commerce со 100 млн позиций использование `OFFSET` привело к тому, что 500-я страница загружалась более 5 секунд [Advanced SQL — Chapter 01 — Video #01 — Introduction](https://notebooklm.google.com/notebook/34). Анализ плана выполнения показал, что система выполняет `Sequential Scan` и отбрасывает 499 предыдущих страниц из памяти [Advanced SQL — Chapter 02 — Video #11 — SQL reading vs. evaluation order, CTEs (WITH)](https://notebooklm.google.com/notebook/43).

Решением стал переход на **Keyset Pagination (Seek Method)**. Вместо запроса `OFFSET 10000 LIMIT 20`, приложение стало запоминать последний увиденный `ID` и значение сортировки на странице. Новый запрос использовал `WHERE (price, id) < (last_price, last_id)`. Это позволило оптимизатору использовать индексный поиск (`Index Scan`), снизив время отклика до миллисекунд независимо от номера страницы [Advanced SQL — Chapter 02 — Video #06 — ORDER BY/OFFSET/LIMIT/DISTINCT [ON]](https://notebooklm.google.com/notebook/38), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/46).
