#### Сквозной практический кейс: Проектирование высоконадежного платежного процессинга

**Постановка задачи:** Реализовать логику перевода средств между балансами пользователей (`Double-Spending protection`) в высоконагруженной системе.

**Пошаговый алгоритм выполнения:**

1. **Стратегия блокировок:** Для предотвращения гонки условий (Race Condition) выбирается уровень `READ COMMITTED` в сочетании с явным `SELECT FOR UPDATE`. Это гарантирует, что пока одна транзакция рассчитывает новый баланс, никто другой не сможет изменить состояние счета.
2. **Исключение Deadlock:** Чтобы избежать взаимных блокировок при встречных платежах (А переводит Б, Б переводит А), вводится правило: захват ресурсов всегда происходит в порядке возрастания `user_id`. Это устраняет циклические зависимости в графе ожиданий.
3. **Использование SAVEPOINT:** При интеграции с внешними шлюзами платеж разбивается на этапы. Перед вызовом внешнего API создается `SAVEPOINT external_call`. Если шлюз возвращает ошибку, выполняется `ROLLBACK TO SAVEPOINT`, что позволяет сохранить локальную комиссию системы за попытку транзакции, не откатывая всю операцию.
4. **Организация Audit-лога:** Фиксация исторического следа выполняется через модифицирующее CTE с `RETURNING`. Это позволяет одним атомарным запросом обновить баланс и сразу вставить запись в таблицу `audit_log`, гарантируя целостность финансовой отчетности,.

#### Комплексный контрольный тест для самопроверки

1. **Анализ `Write Skew`:** В системе дежурств два врача. Правило: «Минимум один врач на связи». Оба одновременно проверяют `COUNT(*)` (видят 2) и уходят в оффлайн (`UPDATE`). Какой уровень изоляции PostgreSQL предотвратит этот сценарий без использования `LOCK TABLE`?
    - _Ответ: `SERIALIZABLE` [2026 Architect Standard]._
2. **Логика `SAVEPOINT`:** Транзакция выполнила: `INSERT (1)`, `SAVEPOINT s1`, `INSERT (2)`, `SAVEPOINT s2`, `INSERT (3)`, `ROLLBACK TO s1`, `COMMIT`. Сколько строк останется в таблице?.
    - _Ответ: 1 строка (первый инсерт)._
3. **Устранение Race Condition:** Напишите SQL-запрос для списания 5 единиц товара со склада (`stock`), где `id = 100`, так чтобы исключить «уход в минус» при одновременных покупках.
    - _Подсказка: Используйте `UPDATE stock SET qty = qty - 5 WHERE id = 100 AND qty >= 5` и проверку количества затронутых строк._
4. **Мониторинг блокировок:** Какой системный вид (`VIEW`) в PostgreSQL следует использовать инженеру для выявления PID процесса, который удерживает `ExclusiveLock` на строку, блокируя выполнение других транзакций?
    - _Ответ: `pg_locks` в связке с `pg_stat_activity` [2026 Architect Standard]._
5. **Настройка OLTP:** Объясните, почему в высоконагруженной системе рекомендуется устанавливать `lock_timeout` (например, на 5s), и как это значение соотносится с `deadlock_timeout` (по умолчанию 1s).
