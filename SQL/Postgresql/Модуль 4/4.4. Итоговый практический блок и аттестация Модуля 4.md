#### Сквозной практический кейс: Проектирование и обход древовидной оргструктуры и подчинения крупного холдинга

**Постановка задачи:** Необходимо реализовать систему управления персоналом крупного холдинга. Система должна позволять строить полную карту подчиненности, агрегировать финансовые показатели (ФОТ) по ветвям оргструктуры и обеспечивать безопасную реорганизацию подразделений с сохранением истории изменений [Advanced SQL — Video #42](https://notebook.google.com/notebook/30), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/179).

**Пошаговый алгоритм выполнения:**

1. **Построение дерева оргструктуры:** Используем `WITH RECURSIVE` для вычисления иерархии. Анкорная часть выбирает генерального директора (`parent_id IS NULL`), а рекурсивная часть присоединяет подчиненных, инкрементируя `level` [Advanced SQL — Video #39](https://notebook.google.com/notebook/27), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/181).
    
    ```
    WITH RECURSIVE org_tree AS (
        SELECT emp_id, ename, parent_id, 1 AS level, ARRAY[emp_id] AS path
        FROM employees WHERE parent_id IS NULL
        UNION ALL
        SELECT e.emp_id, e.ename, e.parent_id, ot.level + 1, ot.path || e.emp_id
        FROM employees e
        INNER JOIN org_tree ot ON e.parent_id = ot.emp_id
    ) SELECT * FROM org_tree;
    ```
    
2. **Агрегация ФОТ по ветвям:** Для расчета суммарных затрат подразделения, включая все дочерние структуры, используем массив путей `path`. Мы связываем таблицу сотрудников с иерархической картой, проверяя вхождение ID департамента в массив предков каждого сотрудника [Advanced SQL — Video #42](https://notebook.google.com/notebook/30).
3. **Оптимизация через материализацию:** Если иерархическая карта используется в запросе многократно (например, для сравнения бюджетов разных лет), применяем `AS MATERIALIZED`. Это заставляет PostgreSQL вычислить дерево один раз и сохранить его в памяти, предотвращая повторные рекурсивные обходы [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/185).
4. **Безопасная реорганизация (DML CTE):** При переводе отдела в другой филиал используем модифицирующий CTE. Мы обновляем `parent_id` для группы сотрудников и одновременно через `RETURNING` записываем факт перевода в таблицу аудита в рамках одного атомарного запроса [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/151), [Advanced SQL — Video #11](https://notebook.google.com/notebook/43).

#### Комплексный контрольный тест для самопроверки

1. **Вопрос на производительность:** В чем заключается семантическая опасность использования `NOT IN` по сравнению с `NOT EXISTS`, если подзапрос возвращает хотя бы одно значение `NULL`?
    - _Ответ: `NOT IN` вернет пустой результат для всего запроса из-за трехзначной логики SQL (Unknown), тогда как `NOT EXISTS` корректно обработает наличие строк [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/118), [SQL.
