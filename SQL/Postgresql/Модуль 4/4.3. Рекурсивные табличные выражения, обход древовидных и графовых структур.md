#### Теоретический фундамент и архитектура

Математическая концепция рекурсии в SQL реализуется через расширение обычных табличных выражений конструкцией `WITH RECURSIVE`. Это фундаментальный инструмент для обработки структур данных, глубина вложенности которых заранее неизвестна, таких как деревья подчинения, графы дорог или иерархии категорий товаров [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/3), [SQL. Сборник рецептов](https://notebook.google.com/notebook/489).

**Двухкомпонентная структура рекурсивного запроса:** Любой рекурсивный запрос состоит из двух логических частей, разделенных оператором объединения:

1. **Стартовый элемент / Анкорная часть (Anchor Member):** Одиночный запрос `Q0`, который выполняется ровно один раз. Он формирует базовый набор строк — «семя» рекурсии (например, корневой узел дерева или начальная точка маршрута) [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/5), [Advanced SQL — Chapter #06 — Video #40](https://notebook.google.com/notebook/12).
2. **Рекурсивная часть (Recursive Member):** Запрос, который может ссылаться на результат самого себя. Он выполняется итеративно, используя данные, полученные на предыдущем шаге [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/5).
3. **Операторы UNION vs UNION ALL:** При использовании `UNION` PostgreSQL применяет семантику множеств, автоматически удаляя дубликаты строк, что предотвращает бесконечное зацикливание при обходе графов с петлями [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/7), [Advanced SQL — Chapter #06 — Video #43](https://notebook.google.com/notebook/32). `UNION ALL` сохраняет все строки (семантика мультимножеств) и работает быстрее, но требует ручного контроля завершения [Advanced SQL — Chapter #06 — Video #41](https://notebook.google.com/notebook/17), [Advanced SQL — Chapter #06 — Video #44](https://notebook.google.com/notebook/36).

**Механика выполнения в рабочей памяти (Working Table):** Внутренняя реализация рекурсии в PostgreSQL опирается на модель **Working Table** (промежуточная таблица `T`):

- Сначала выполняется анкор `Q0`, его результат помещается в `Working Table` и итоговый результат `R` [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/9).
- Затем рекурсивная часть вызывается **только** для строк, находящихся в `Working Table` на данный момент [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/10).
- Полученные новые строки заменяют старые в `Working Table` и добавляются к `R`. Процесс повторяется, пока очередная итерация не вернет пустой результат [Advanced SQL — Chapter #06 — Video #39](10, 11), [Advanced SQL — Chapter #06 — Video #40](https://notebook.google.com/notebook/14).

**Стратегии обхода структур:**

- **Вычисление уровней (Level):** Для определения глубины в анкорной части задается константа (например, 0), а в рекурсивной части она инкрементируется: `level + 1` [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/23), [SQL. Сборник рецептов](https://notebook.google.com/notebook/497).
- **Построение путей (Path Enumeration):** Для формирования «хлебных крошек» или детекции циклов используется накопление идентификаторов в массивы: `path || node_id` [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/26).

**Проблема циклических графов:** Если данные содержат петли (например, склад А -> склад Б -> склад А), рекурсия станет бесконечной. Для предотвращения этого в PostgreSQL 14+ внедрен нативный синтаксис `CYCLE`, который отслеживает посещенные узлы и устанавливает флаг `is_cycle` при обнаружении повтора [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/22).

#### Практическая реализация и синтаксис

Построение полной иерархии сотрудников с указанием уровня вложенности:

```
WITH RECURSIVE employee_hierarchy AS (
    -- Anchor Member: выбираем топ-менеджеров
    SELECT emp_id, ename, mgr, 0 AS level
    FROM emp
    WHERE mgr IS NULL

    UNION ALL

    -- Recursive Member: присоединяем подчиненных
    SELECT e.emp_id, e.ename, e.mgr, eh.level + 1
    FROM emp e
    INNER JOIN employee_hierarchy eh ON e.mgr = eh.emp_id
)
SELECT level, ename
FROM employee_hierarchy
ORDER BY level, ename;
```

[SQL. Сборник рецептов](https://notebook.google.com/notebook/497), [SQL. Сборник рецептов](https://notebook.google.com/notebook/509).

Сбор полного пути категорий (Breadcrumbs) от дочернего элемента к корню:

```
WITH RECURSIVE breadcrumbs AS (
    -- Начинаем с целевой подкатегории
    SELECT category_id, name, parent_id, name::TEXT AS path
    FROM categories
    WHERE category_id = 505

    UNION ALL

    -- Идем вверх к родителю
    SELECT c.category_id, c.name, c.parent_id,
           c.name || ' > ' || b.path
    FROM categories c
    INNER JOIN breadcrumbs b ON b.parent_id = c.category_id
)
SELECT path FROM breadcrumbs WHERE parent_id IS NULL;
```

[SQL. Сборник рецептов](https://notebook.google.com/notebook/497), [SQL. Сборник рецептов](https://notebook.google.com/notebook/503).

Защита от бесконечных циклов в графе дорог:

```
WITH RECURSIVE path_finder AS (
    SELECT source, target, ARRAY[source] AS full_path
    FROM routes
    WHERE source = 'Warehouse_A'

    UNION ALL

    SELECT r.source, r.target, pf.full_path || r.source
    FROM routes r
    INNER JOIN path_finder pf ON pf.target = r.source
    -- PostgreSQL 14+ встроенная защита
) CYCLE source SET is_cycle USING path
SELECT * FROM path_finder WHERE NOT is_cycle;
```

#### Глоссарий терминов

- **Recursive CTE (WITH RECURSIVE)** — именованное табличное выражение, способное итеративно ссылаться на собственные результаты [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/3).
- **Anchor Member** — начальный запрос рекурсивного блока, определяющий базис индукции [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/5).
- **Recursive Member** — часть запроса, выполняющая шаг рекурсии путем объединения с предыдущим состоянием [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/5).
- **Working Table Execution Model** — внутренний алгоритм PostgreSQL, при котором на каждой итерации обрабатываются только новые данные из временного буфера [Advanced SQL — Chapter #06 — Video #39](https://notebook.google.com/notebook/9).
- **Tree Traversal (BFS / DFS)** — методы систематического посещения всех узлов иерархической структуры [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/18).
- **Cycle Detection (CYCLE Clause)** — механизм предотвращения бесконечных циклов путем отслеживания истории посещений в рамках одного пути [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/22).
- **Path Enumeration Array** — техника хранения полной цепочки предков узла в виде массива для быстрой навигации и поиска циклов [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/26).

#### Практический кейс: Развертывание дерева категорий интернет-магазина

В highload e-commerce системе каталог имеет неограниченную вложенность. Задача — вывести дерево категорий и для каждой ветки посчитать, сколько товаров находится в ней и во всех её дочерних элементах [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/18). **Решение:** Сначала с помощью `WITH RECURSIVE` строится иерархия, где для каждого узла генерируется массив всех его предков. Затем выполняется `JOIN` с таблицей товаров и группировка. Благодаря массиву путей, товар, привязанный к «Смартфонам», автоматически учитывается в статистике родительских категорий «Электроника» и «Все товары» без необходимости многократного пересчета [SQL. Сборник рецептов](https://notebook.google.com/notebook/508), [Advanced SQL — Chapter #06 — Video #42](https://notebook.google.com/notebook/21).
