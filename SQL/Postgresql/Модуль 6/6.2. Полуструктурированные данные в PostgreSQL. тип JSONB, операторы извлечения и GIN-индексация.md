#### Теоретический фундамент и архитектура

В современной архитектуре баз данных PostgreSQL предоставляет мощные инструменты для работы с полуструктурированными данными, предлагая два основных типа: `JSON` и `JSONB`.

**Сравнение типов JSON и JSONB:**

- **`JSON`**: Хранит точную копию входного текста, включая избыточные пробелы и порядок ключей. Это приводит к необходимости повторного синтаксического анализа (парсинга) при каждом обращении, что замедляет выполнение запросов.
- **`JSONB` (JSON Binary)**: Сохраняет данные в разобранном бинарном формате. При записи выполняется нормализация: удаляются лишние пробелы, ключи могут быть переупорядочены для оптимизации, а дубликаты ключей удаляются (оставляется только последнее значение). Основное преимущество `JSONB` — значительно более быстрый доступ к элементам и поддержка специализированных индексов.

**Специализированные операторы для работы с JSONB:** Для навигации по глубоко вложенным структурам используются специальные операторы доступа.

- **Операторы извлечения**:
    - `->` — возвращает поле объекта или элемент массива в формате `JSONB`, что позволяет строить длинные цепочки вызовов.
    - `->>` — извлекает значение в виде обычного текста (`text`). Этот оператор является «терминальным», так как после него нельзя продолжать навигацию по структуре JSON, но полученный результат можно привести (через `CAST`) к числу или дате.
- **Операторы поиска по пути**: Операторы `#>` и `#>>` позволяют обращаться к объектам, указывая массив ключей (путь), что избавляет от необходимости писать длинные цепочки из операторов `->`.
- **Проверка содержаемости**: Оператор `@>` (информация из внешних источников, не представленная в предоставленных материалах, но являющаяся стандартом для `JSONB`) проверяет, содержит ли левый `JSONB` объект структуру, описанную в правом. Оператор `?` проверяет наличие ключа в объекте.

**Трансформация данных:** PostgreSQL позволяет легко переходить от реляционной модели к `JSON` и обратно. Функция `jsonb_array_elements()` «взрывает» (explode) массив, превращая каждый его элемент в отдельную строку результирующего набора. Для преобразования объектов в записи используются функции `jsonb_to_record()` или `jsonb_populate_record()`, которые сопоставляют ключи JSON со столбцами таблицы на основе типов данных SQL.

**Индексация JSONB (GIN):** Для обеспечения высокой производительности на больших объемах данных используются инвертированные индексы (GIN). Хотя предоставленные источники не содержат детального разбора классов операторов, архитектурно `jsonb_ops` позволяет искать по любым ключам и значениям, в то время как `jsonb_path_ops` оптимизирован для поиска по вложенным путям и занимает меньше места на диске.

#### Практическая реализация и синтаксис

Создание таблицы с динамическими атрибутами и фильтрация данных:

```
-- DDL таблицы с JSONB атрибутами
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    attributes JSONB
);

-- Фильтрация по значению внутри JSONB
-- Используем ->> для получения текста и приведения к числу
SELECT name, attributes->>'brand' as brand
FROM products
WHERE (attributes->>'price')::NUMERIC > 1000;

-- Поиск с использованием оператора содержаемости
SELECT * FROM products
WHERE attributes @> '{"color": "red", "size": "XL"}';
```

.

Обновление вложенного значения (используя функции модификации, такие как `jsonb_set` — информация об этой функции является общепринятой для PostgreSQL, источники подтверждают наличие таких «мостов»):

```
-- Обновление скидки в метаданных
UPDATE products
SET attributes = jsonb_set(attributes, '{discount}', '15')
WHERE attributes->>'category' = 'electronics';
```

.

Профилирование индексированного поиска:

```
-- Создание эффективного GIN индекса (информация о классах операторов из внешних источников)
CREATE INDEX idx_prod_attr_path ON products USING GIN (attributes jsonb_path_ops);

-- Проверка использования индекса
EXPLAIN ANALYZE
SELECT * FROM products WHERE attributes @> '{"material": "leather"}';
```

.

#### Глоссарий терминов

- **JSON vs JSONB Storage** — различие между хранением данных в виде текста (медленно, но сохраняет формат) и в бинарном разобранном виде (быстро, эффективно для поиска).
- **JSON Extraction Operators (`->` vs `->>`)** — способы получения вложенных данных: как `JSONB` для продолжения поиска или как `text` для вывода и расчетов.
- **Containment Operator (`@>`)** — логический оператор проверки вхождения одного JSON-документа в другой.
- **Path Access Operators (`#>` / `#>>`)** — синтаксический сахар для извлечения данных по массиву ключей.
- **In-place JSONB Modification (`jsonb_set`)** — функциональный метод обновления части документа без перезаписи всего поля вручную.
- **GIN Indexing for JSONB** — использование обобщенных инвертированных индексов для ускорения поиска по ключам и значениям внутри документов.
- **JSON Unnesting Functions (`jsonb_array_elements`)** — функции для разворачивания JSON-массивов в стандартные строки таблицы.

#### Практический кейс: Проектирование гибкой схемы характеристик товаров e-commerce

**Сценарий**: Интернет-магазин продает товары разных категорий, у каждой из которых свой набор характеристик (у смартфонов — ОЗУ, у одежды — состав ткани). **Решение**: Вместо создания сотен колонок для каждого свойства, используется одна колонка `attributes JSONB`. Для поиска товаров по бренду или цвету создается GIN-индекс. Благодаря оператору `jsonb_array_elements`, можно легко строить отчеты, например, считая среднюю цену товаров в разрезе брендов, даже если эти бренды хранятся внутри JSON-поля, превращая полуструктурированные данные в реляционный вид «на лету».

#### Вопросы и задания для самопроверки

1. **Вопрос**: Почему попытка выполнить расчет `(attributes->'price') * 1.1` приведет к ошибке, и как использование `->>` исправляет ситуацию?.
    - _Ответ: Оператор `->` возвращает тип `jsonb`, который нельзя использовать в арифметике. Нужно использовать `->>` для получения текста и выполнить `CAST` к числовому типу._
2. **Задача**: Напишите запрос, который из поля `meta` (JSONB) извлекает массив `tags` и превращает его в список строк.
3. **Практика**: Сравните планы выполнения (`EXPLAIN`) для поиска значения ключа в таблице на 1 млн строк с индексом `jsonb_ops` и без него. В каком случае индекс может не сработать?.
