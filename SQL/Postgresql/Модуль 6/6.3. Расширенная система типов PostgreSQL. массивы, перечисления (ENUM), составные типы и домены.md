#### Теоретический фундамент и архитектура

В современной архитектуре PostgreSQL система типов выходит далеко за рамки стандартных скалярных значений, позволяя инженеру проектировать схемы с высокой степенью вложенности и строгим контролем целостности.

**Использование массивов (Arrays) в столбцах таблицы:** Массивы в PostgreSQL (`Array Data Type`) позволяют хранить коллекции однородных элементов непосредственно в ячейках таблицы,. Хотя таблицы остаются первичным способом организации данных, массивы играют элегантную и эффективную роль при представлении сложных структур без избыточных соединений.

- **Объявление:** Массивы определяются с помощью квадратных скобок (например, `INTEGER[]`, `TEXT[]`). PostgreSQL поддерживает многомерные массивы, однако на практике чаще всего используются одномерные.
- **Литералы и конструкторы:** Значения могут быть заданы через конструктор `ARRAY[...]` или текстовые литералы в фигурных скобках. Пустые массивы требуют явного приведения типа (например, `ARRAY[]::integer[]`), так как они полиморфны.
- **Трансформация:** Функция `unnest()` является фундаментальным инструментом для разворачивания массива в набор строк, что позволяет применять к элементам всю мощь SQL: фильтрацию, группировку и агрегацию. Использование `WITH ORDINALITY` позволяет извлечь не только значения, но и их порядковые позиции в массиве.

**Перечисления (ENUM Types):** Типы `ENUM` позволяют расширять стандартную систему типов пользовательскими наборами значений.

- **Механика:** Инженер создает новый тип данных `tau`, которому принадлежит строго определенный набор строковых констант.
- **Целостность:** Использование `ENUM` на уровне базы данных работает как встроенное проверочное ограничение (`CHECK constraint`), гарантируя, что в столбец не попадут недопустимые значения,. Это обеспечивает более компактное хранение по сравнению с обычным `TEXT` и строгий контроль данных на уровне ядра СУБД.

**Позиционные и пользовательские типы данных:** PostgreSQL позволяет создавать сложные структуры данных, объединяющие несколько полей в одну логическую единицу.

- **Составные типы (Composite Types):** По сути, это типы строк (`Row types`), которые могут использоваться в качестве типов столбцов или аргументов функций,. Это приближает ячейку таблицы по возможностям к самой таблице, но с соблюдением типизации.
- **Пользовательские домены (Domains):** Хотя синтаксис `CREATE DOMAIN` является расширением, концепция базируется на наложении проверочных ограничений (`CHECK`) на существующие типы для валидации данных (например, форматы почтовых индексов или email).

> [!warning] Актуализация синтаксиса 
> Использование массивов для замены реляционных связей (`1:N`) может привести к нарушению первой нормальной формы (1NF), если данные внутри массива требуют независимого обновления или индексации. Применяйте массивы только для атомарных коллекций метаданных,.

#### Практическая реализация и синтаксис

Пример работы с массивом тегов и его разворачивание:

```
-- Создание таблицы с массивом
CREATE TABLE articles (
    id SERIAL PRIMARY KEY,
    title TEXT,
    tags TEXT[] -- Массив текстовых элементов
);

-- Использование unnest для анализа тегов
SELECT title, unnest(tags) AS tag
FROM articles; -- Превращает массив в строки

-- Поиск пересечения (используя логику стандартных операторов)
SELECT * FROM articles
WHERE tags && ARRAY['postgres', 'sql']; -- && проверяет наличие общих элементов
```

Создание и модификация типа `ENUM` для управления жизненным циклом заказа:
```sql
-- Определение типа перечисления
CREATE TYPE order_status AS ENUM ('draft', 'paid', 'shipped', 'cancelled');

-- Использование типа в DDL таблицы
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    current_status order_status DEFAULT 'draft'
);

-- Добавление нового значения в существующий ENUM
ALTER TYPE order_status ADD VALUE 'returned' AFTER 'shipped';
```.

Реализация домена для положительных чисел:
```sql
-- Создание домена с проверочным ограничением
CREATE DOMAIN positive_numeric AS NUMERIC
CHECK (VALUE > 0);

-- Применение в таблице
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    price positive_numeric -- Теперь отрицательная цена невозможна на уровне типа
);
```

#### Глоссарий терминов
* **Array Data Type** — встроенный тип данных PostgreSQL для хранения упорядоченных наборов элементов одного типа внутри одной ячейки.
* **Array Unnesting (unnest)** — функция преобразования массива в реляционный набор строк для итеративной обработки.
* **Array Overlap Operator (&&)** — оператор проверки наличия хотя бы одного общего элемента между двумя массивами.
* **ENUM Types (CREATE TYPE ... AS ENUM)** — пользовательский тип данных, состоящий из статического набора разрешенных строковых значений.
* **Composite Types** — структура данных, определяющая набор именованных полей, которая может использоваться как тип столбца.
* **Custom Domains (CREATE DOMAIN)** — именованный тип данных с встроенными правилами валидации (`CHECK`), расширяющий базовые типы.
* **Structural Data Integrity** — обеспечение корректности данных за счет использования строгой типизации и ограничений на уровне схемы БД.

#### Практический кейс: Проектирование схемы финтех-платформы
**Сценарий:** При проектировании системы банковских счетов необходимо обеспечить хранение адресов клиентов и валидацию идентификаторов счетов (IBAN/валют).
**Решение:**
1.  **Адреса:** Вместо добавления 5-6 колонок (`city`, `street`, `zip`) в таблицу `customers`, создается составной тип `address_type`. Это позволяет передавать адрес в функции как единый объект,.
2.  **Валюты:** Для кодов валют (USD, EUR, RUB) используется `ENUM`, что предотвращает ввод несуществующих кодов без обращения к справочникам.
3.  **Валидация:** Создается домен `iban_code` на базе `TEXT` с `CHECK`-ограничением, использующим регулярное выражение (`REGEXP`), гарантирующее соблюдение международного формата с самого момента вставки данных,.

#### Вопросы и задания для самопроверки
1. **Вопрос:** Почему удаление значения из `ENUM` в PostgreSQL является сложной операцией?
    *   *Ответ: Значения ENUM хранятся в системных каталогах как числовые идентификаторы; физическое удаление может нарушить целостность уже записанных данных, поэтому требуется пересоздание типа или использование ALTER TYPE.*
2. **Задача:** Напишите запрос, который находит все статьи, где в массиве `tags` одновременно присутствуют 'postgres' и 'sql'. Используйте оператор содержаемости `@>`.
3. **Практика:** Создайте домен `email_address` и примените его к таблице пользователей. Используйте регулярное выражение для проверки наличия символа '@' и доменной зоны.
