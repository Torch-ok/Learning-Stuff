#### Сквозной практический кейс: Проектирование гибридной схемы данных

**Постановка задачи:** Спроектировать архитектуру БД для маркетплейса, где финансовые транзакции требуют строгой нормализации, а каталог товаров — гибкости из-за различий в характеристиках (электроника vs одежда) [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/9), [Advanced SQL — Video #20](https://notebook.google.com/notebook/8).

**Пошаговый алгоритм выполнения:**

1. **Создание реляционного ядра (Relational Core):** Проектируем таблицы `sellers` и `orders` в 3NF. Это исключает аномалии обновления: имя продавца хранится только один раз, а заказы ссылаются на него через `FK` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/9), [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/498).
    
    ```
    CREATE TABLE sellers (
        seller_id SERIAL PRIMARY KEY,
        name TEXT NOT NULL,
        email TEXT UNIQUE
    );
    ```
    
2. **Внедрение пользовательских типов:** Используем `CREATE DOMAIN` для гарантии корректности e-mail и `ENUM` для жизненного цикла заказа [Advanced SQL — Video #16](https://notebook.google.com/notebook/4), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/251).
    
    ```
    CREATE TYPE delivery_status AS ENUM ('PENDING', 'SHIPPED', 'DELIVERED', 'CANCELLED');
    CREATE DOMAIN email_type AS TEXT CHECK (VALUE ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$');
    ```
    
3. **Гибкий каталог (JSONB):** Характеристики товаров (размер, вольтаж, автор) выносятся в `attributes JSONB`. Это позволяет добавлять новые категории товаров без изменения схемы (`DDL`) [Advanced SQL — Video #20](https://notebook.google.com/notebook/8).
    
    ```
    CREATE TABLE products (
        product_id SERIAL PRIMARY KEY,
        title TEXT NOT NULL,
        attributes JSONB -- Хранение вариативных свойств
    );
    ```
    
4. **Оптимизация производительности:** Для реляционных связей используем B-Tree индексы. Для поиска внутри `JSONB` создаем GIN-индекс с классом `jsonb_path_ops` для ускорения фильтрации по конкретным свойствам [Advanced SQL — Video #20](https://notebook.google.com/notebook/8), [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/545).

#### Комплексный контрольный тест для самопроверки

1. **Вопрос на нормализацию:** К какой нормальной форме относится таблица, если в ней нет повторяющихся групп, но один из неключевых атрибутов зависит только от части составного первичного ключа? [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/500).
    - _Ответ: Это нарушение 2NF (частичная зависимость)._
2. **Задача на типы данных:** Для реализации системы тегов, где один товар может иметь до 50 меток, по которым часто ищут пересечения, какой тип данных эффективнее: `TEXT` (через LIKE), `TEXT[]` (массив) или `JSONB`? Обоснуйте использование GIN-индекса [Advanced SQL — Video #24](https://notebook.google.com/notebook/2), [Advanced SQL — Video #20](https://notebook.google.com/notebook/8).
3. **Поиск ошибок в GIN:** Почему запрос `SELECT * FROM products WHERE attributes->>'color' = 'red'` может не использовать GIN-индекс, созданный как `USING GIN (attributes)`?
    - _Подсказка: GIN-индексы по умолчанию поддерживают операторы вхождения (@>), а не извлечения текста (->>) [Advanced SQL — Video #20](https://notebook.google.com/notebook/8)._
4. **Конвертация в ENUM:** Опишите последовательность команд для превращения текстовой колонки `status` в тип `ENUM` на таблице с миллионом строк. Почему нельзя просто выполнить `ALTER COLUMN TYPE` без дополнительных шагов? [Advanced SQL — Video #16](https://notebook.google.com/notebook/4).
5. **Проектирование OLAP:** Спроектируйте представление (`VIEW`), которое преобразует гибридную таблицу `products` (с JSONB) в плоскую витрину данных для BI-системы, используя функции `jsonb_to_record` или операторы `->>` [SQL.
