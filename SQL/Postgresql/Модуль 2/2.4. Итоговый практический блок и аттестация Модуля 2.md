#### Сквозной практический кейс: Построение консолидированного финансового отчета предприятия из 5+ таблиц

**Постановка задачи:** Необходимо спроектировать структуру и составить аналитический SQL-запрос для сбора данных о платежах предприятия. Отчет должен объединять информацию об организациях, контрактах, инвойсах, фактических оплатах и банковских счетах в разных валютах [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/224), [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/723).

**Пошаговый алгоритм выполнения:**

1. **Проектирование связей (DDL):** Устанавливаем отношения между таблицами через внешние ключи (`FOREIGN KEY`). Связь между `contracts` и `organizations` строится по схеме «многие-к-одному», где внешние ключи гарантируют, что контракт не может быть привязан к несуществующей организации [Вся база SQL за 1 час](https://notebook.google.com/notebook/646), [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/665).
2. **Сборка данных через LEFT JOIN:** Для того чтобы отчет включал даже те контракты, по которым еще не выставлены счета или не прошли оплаты, используем последовательную цепочку `LEFT JOIN`. Это позволяет избежать потери данных, которые не имеют полной «пары» во всех таблицах финансового контура [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/351), [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/713).
    
    ```
    SELECT
        org.name AS organization,
        c.contract_no,
        inv.invoice_id,
        p.amount AS payment_amount,
        cur.code AS currency
    FROM organizations org
    LEFT JOIN contracts c ON org.org_id = c.org_id
    LEFT JOIN invoices inv ON c.contract_id = inv.contract_id
    LEFT JOIN payments p ON inv.invoice_id = p.invoice_id
    LEFT JOIN bank_accounts ba ON p.account_id = ba.account_id
    LEFT JOIN currencies cur ON ba.currency_id = cur.currency_id;
    ```
    
3. **Исключение системных счетов через EXCEPT:** Если в организации есть внутренние транзитные счета, которые не должны попадать в итоговую ведомость, применяем оператор `EXCEPT`. Это вычтет идентификаторы заблокированных или технических счетов из общего списка транзакций [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/293), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/490).
4. **Устранение дублирования и группировка:** При многократных соединениях (особенно при связи «один-ко-многим») строки могут дублироваться. Для корректного расчета итогов используем `DISTINCT` или `GROUP BY` по ключевым полям контракта и инвойса, чтобы агрегатные функции (например, `SUM`) не учитывали одну и ту же оплату несколько раз [Advanced SQL — Video #06](https://notebook.google.com/notebook/156), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/305).

#### Комплексный контрольный тест для самопроверки

1. **Вопрос на JOIN:** Таблица А имеет 10 строк, таблица B — 5 строк. Какое максимальное количество строк может вернуть `CROSS JOIN`, и сколько строк вернет `INNER JOIN`, если ни одно значение ключей не совпадает?
    - _Ответ: CROSS JOIN вернет 50 строк (10 * 5) [Advanced SQL — Video #02](https://notebook.google.com/notebook/37). INNER JOIN вернет 0 строк, так как отсутствуют совпадения [Шилдс Уолтер SQL.pdf](https://notebook.google.com/notebook/704)._
2. **Задача на DDL:** В DDL-скрипте внешние ключи объявлены без `ON DELETE CASCADE`. К чему приведет попытка удаления родительской организации, имеющей активные контракты?
    - _Ответ: СУБД заблокирует операцию и выдаст ошибку нарушения ссылочной целостности [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/223), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/402)._
3. **Практика Self-Join:** Напишите запрос к таблице `categories`, который выведет название подкатегории и название ее родительской категории в одной строке.
    
    ```
    SELECT child.name AS subcategory, parent.name AS parent_category
    FROM categories child
    INNER JOIN categories parent ON child.parent_id = parent.category_id;
    ```
    
    [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/271), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/602).
4. **Рефакторинг UNION:** Почему замена `UNION` на `UNION ALL` в запросе, объединяющем данные из двух огромных архивных таблиц, может существенно ускорить выполнение?
    - _Ответ: UNION ALL просто объединяет наборы данных, тогда как UNION выполняет ресурсоемкую сортировку для удаления дубликатов [Advanced SQL — Video #09](https://notebook.google.com/notebook/182), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebook.google.com/notebook/285)._
5. **Анализ логики фильтрации:** Объясните результат запроса `SELECT * FROM a LEFT JOIN b ON a.id = b.id WHERE b.status = 'paid'`.
    - _Ответ: Этот запрос фактически работает как INNER JOIN. Условие в WHERE отсекает все строки, где b.status IS NULL (т.е. те, для которых не нашлось пары), что ломает логику внешнего соединения [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/573), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebook.google.com/notebook/574)._
