#### Теоретический фундамент и архитектура

Математическая природа агрегации в реляционных базах данных заключается в выполнении операций над множеством входных строк для получения единого итогового значения (скалярного свертывания). В отличие от обычных функций, которые обрабатывают каждую строку по отдельности, агрегатные функции (`Aggregate Functions`) просматривают всю коллекцию записей или определенную группу.

**Базовые функции и их применение:**

- `SUM()` — вычисляет арифметическую сумму значений в столбце.
- `AVG()` — находит среднее арифметическое.
- `COUNT()` — подсчитывает количество элементов.
- `MAX()` и `MIN()` — определяют экстремумы (наибольшее и наименьшее значения) в наборе.

**Влияние `NULL`-значений на результаты агрегации:** В SQL реализовано специфическое поведение агрегатов при встрече с неопределенными значениями (`NULL`):

1. **Игнорирование:** Функции `SUM()`, `AVG()`, `MIN()` и `MAX()` полностью игнорируют `NULL`. Они ведут расчет только по фактически существующим значениям.
2. **Разница в COUNT:** Существует принципиальное различие между `COUNT(*)` и `COUNT(expression)`. `COUNT(*)` подсчитывает общее количество строк в таблице, включая те, что содержат `NULL` или дубликаты. В то же время `COUNT(column_name)` учитывает только те строки, где значение в указанной колонке не является `NULL`.
3. **Искажение логики AVG:** Прямой расчет `AVG(column)` может привести к архитектурным ошибкам. Если колонка содержит `NULL`, функция разделит сумму на количество ненулевых элементов. Если бизнес-логика требует учитывать пропуски как нулевые показатели, результат будет завышен. В таких случаях правильнее использовать `SUM(column) / COUNT(*)` или предварительно обрабатывать данные через `COALESCE(column, 0)`.

**Модификатор `DISTINCT` внутри агрегатов:** Использование ключевого слова `DISTINCT` внутри вызова функции (например, `COUNT(DISTINCT user_id)`) заставляет СУБД сначала устранить дубликаты в наборе данных и только затем выполнить агрегацию. Это гарантирует учет только уникальных вхождений, но создает дополнительную нагрузку на ресурсы (Memory Overhead), так как требует сортировки или хэширования данных в оперативной памяти перед расчетом.

**Защита от деления на ноль и нейтрализация `NULL`:** Для обеспечения надежности вычислений применяются следующие инструменты:

- `COALESCE()` — позволяет подставить значение по умолчанию (например, 0) вместо `NULL`, чтобы избежать исключения из расчета.
- Условная логика `CASE` — используется для предотвращения критических ошибок `division by zero`. Если знаменатель равен нулю, выражение должно возвращать `NULL` или альтернативное значение, чтобы не прерывать выполнение запроса.

#### Практическая реализация и синтаксис

Пример, демонстрирующий разницу в поведении различных вариантов подсчета на таблице заказов (`orders`), где поле `discount` может быть не заполнено:

```
-- Демонстрация логики COUNT и NULL
SELECT
    COUNT(*) AS total_rows,           -- Все заказы
    COUNT(discount) AS orders_w_disc, -- Только заказы со скидкой (не NULL)
    COUNT(DISTINCT user_id) AS unique_users -- Количество уникальных покупателей
FROM orders;
```

.

Безопасный расчет среднего чека и финансовой конверсии с защитой от пустых значений и деления на ноль:

```
-- Расчет среднего чека с учетом всех транзакций (включая нулевые через COALESCE)
-- и защита от деления на ноль через CASE
SELECT
    SUM(amount) / NULLIF(COUNT(*), 0) AS avg_check_safe, -- Стандартный подход
    AVG(COALESCE(amount, 0)) AS avg_check_with_nulls,    -- Альтернатива через COALESCE
    -- Расчет конверсии с защитой знаменателя
    CAST(SUM(CASE WHEN status = 'PAID' THEN 1 ELSE 0 END) AS NUMERIC) /
    CASE WHEN COUNT(*) = 0 THEN 1 ELSE COUNT(*) END * 100 AS conversion_rate
FROM transactions;
```

.

#### Глоссарий терминов

- **Aggregate Functions** — встроенные функции SQL для выполнения вычислений над набором значений и возврата одиночного результата.
- **Scalar Aggregation** — процесс преобразования множества строк в одно скалярное значение без использования группировки `GROUP BY`.
- **NULL Ignorance in Aggregates** — стандартное поведение большинства функций (кроме `COUNT(*)`), при котором неопределенные значения исключаются из математической обработки.
- **COUNT(*) vs COUNT(expression)** — различие между физическим подсчетом строк в отношении и логическим подсчетом определенных (не-NULL) значений в атрибуте.
- **Aggregate DISTINCT Modifier** — инструкция внутри агрегатной функции для предварительной дедупликации данных перед выполнением расчета.
- **Division by Zero Safe Calculation** — методы построения запросов (через `CASE` или специализированные функции), предотвращающие аварийную остановку при обнулении знаменателя.

#### Практический кейс: Корректный расчет среднего чека и суммарных продаж в ритейле

**Сценарий:** Аналитический отдел торговой сети ставит задачу рассчитать средний чек. База данных содержит таблицу транзакций, где часть записей о скидках (`discount_amount`) содержит `NULL` (если карта лояльности не применялась), а некоторые суммы возврата (`refund_amount`) также не заполнены.

**Проблема:** Использование `AVG(discount_amount)` покажет среднюю скидку только среди тех, кто её получил, игнорируя бóльшую часть покупателей без скидок. Это приведет к неверному планированию бюджета маркетинговых акций.

**Решение:**

1. Для получения честного среднего значения скидки по всей сети применяется `AVG(COALESCE(discount_amount, 0))`. Это приравнивает отсутствие данных к нулевой скидке и дает корректную аналитическую картину.
2. При расчете чистой выручки (`SUM(amount - COALESCE(refund_amount, 0))`) исключается потеря строк: если бы мы просто вычитали `amount - refund_amount`, то строки с `NULL` в возвратах превратили бы итоговую сумму в `NULL`, и данные о продажах «испарились» бы из отчета.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему при наличии `NULL` в столбце `bonus` результат `AVG(bonus)` будет математически больше, чем результат `SUM(bonus) / COUNT(*)`?
    - _Ответ: `AVG` делит сумму на количество не-NULL строк, в то время как `COUNT(*)` учитывает все строки, что дает больший знаменатель и, соответственно, меньший итог._
2. **Задача:** Составьте запрос для таблицы `sales`, который вычисляет процент возвратов. Используйте `COALESCE` для обработки пустых сумм и обеспечьте защиту от деления на ноль, если продаж за период не было.
