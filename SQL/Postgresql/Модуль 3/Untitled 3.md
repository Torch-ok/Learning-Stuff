#### Теоретический фундамент и архитектура

Условная логика в SQL реализуется через выражение `CASE`, которое позволяет внедрять логику `IF-THEN-ELSE` непосредственно в тело запроса для преобразования данных «на лету».

**Условная логика `CASE WHEN`:**

- **Две формы синтаксиса:** Простая форма (`Simple CASE`) сравнивает выражение с набором значений через равенство. Поисковая форма (`Searched CASE`) является более гибкой, так как позволяет использовать любые логические условия, включая сравнения и операторы `BETWEEN`, `IN`, `AND/OR`.
- **Порядок вычисления (Short-circuit evaluation):** Блоки `WHEN` обрабатываются строго сверху вниз. Как только условие принимает значение `TRUE`, возвращается результат соответствующего блока `THEN`, а остальные условия игнорируются.
- **Обработка ветки `ELSE`:** Секция `ELSE` определяет значение, если ни одно из условий не было выполнено. Если `ELSE` опущена, результатом выражения станет `NULL`, что может привести к потере данных в арифметических операциях.

**Выборочная агрегация через предложение `FILTER`:** В PostgreSQL продвинутым способом агрегации является спецификация `FILTER (WHERE condition)`, которая ограничивает набор строк, попадающих в конкретную агрегатную функцию.

- **Сравнение подходов:** Традиционный метод `SUM(CASE WHEN condition THEN val ELSE 0 END)` требует обработки каждой строки внутри функции. Использование `SUM(val) FILTER (WHERE condition)` отделяет логику фильтрации от вычислений, что делает код нагляднее.
- **Эффективность:** Оптимизатор PostgreSQL может более эффективно обрабатывать `FILTER`, особенно при использовании нескольких агрегатов с разными условиями в одном запросе, так как это снижает накладные расходы на вычисление логики `CASE` для каждого столбца.

**Техника транспонирования данных (Pivoting):** Транспонирование (Pivoting) — это процесс разворачивания данных из строк в колонки (поворот на 90 градусов). В PostgreSQL это достигается путем комбинирования агрегатных функций (`SUM`, `COUNT`) и условных выражений. Данный метод позволяет преобразовывать наборы значений (например, годы или статусы) в заголовки столбцов итогового отчета без использования специализированных расширений.

#### Практическая реализация и синтаксис

Пример сегментации клиентов по объему трат с использованием поисковой формы `CASE`:

```
SELECT
    customer_id,
    total_spent,
    CASE
        WHEN total_spent > 10000 THEN 'VIP'
        WHEN total_spent BETWEEN 5000 AND 10000 THEN 'Regular'
        ELSE 'Low'
    END AS customer_rank
FROM customer_sales
ORDER BY total_spent DESC;
```

.

Расчет суммы продаж по кварталам в виде отдельных колонок через `FILTER`:

```
SELECT
    EXTRACT(YEAR FROM sale_date) AS sale_year,
    SUM(amount) FILTER (WHERE EXTRACT(QUARTER FROM sale_date) = 1) AS Q1,
    SUM(amount) FILTER (WHERE EXTRACT(QUARTER FROM sale_date) = 2) AS Q2,
    SUM(amount) FILTER (WHERE EXTRACT(QUARTER FROM sale_date) = 3) AS Q3,
    SUM(amount) FILTER (WHERE EXTRACT(QUARTER FROM sale_date) = 4) AS Q4
FROM sales
GROUP BY sale_year;
```

.

Комбинированный подсчет заказов в разных статусах за один проход:

```
SELECT
    COUNT(*) AS total_orders,
    COUNT(*) FILTER (WHERE status = 'completed') AS successful,
    COUNT(*) FILTER (WHERE status = 'cancelled') AS failed,
    COUNT(*) FILTER (WHERE status = 'new') AS pending
FROM orders;
```

.

#### Глоссарий терминов

- **Conditional Expressions (`CASE WHEN`)** — конструкции SQL для выполнения логических проверок и ветвления внутри запроса.
- **Short-Circuit Evaluation** — механизм прекращения вычислений условного выражения сразу после нахождения первого истинного условия.
- **Selective Aggregates (`FILTER Clause`)** — спецификация агрегатной функции в PostgreSQL для выборочной обработки строк на основе условия.
- **SQL Pivoting Logic** — метод трансформации данных, при котором уникальные значения атрибута строки становятся именами столбцов.
- **Conditional Aggregation** — паттерн использования `CASE` или `FILTER` внутри агрегатных функций для создания сложных аналитических отчетов.

#### Практический кейс: Построение сводной матрицы продаж по регионам и статусам

Для руководства e-commerce проекта необходимо построить отчетную матрицу, где в строках указаны регионы (`region`), а в столбцах — количество заказов в разных статусах. Вместо выполнения множества запросов и их объединения через `JOIN`, используется техника `Pivoting`. Реализация строится на группировке по региону и применении `COUNT(*) FILTER (WHERE status = ...)` для каждого статуса. Это позволяет базе данных выполнить всего одно сканирование таблицы (`Sequential Scan`), распределяя записи по соответствующим колонкам агрегата «на лету», что критически важно для производительности в высоконагруженных системах.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему запрос `COUNT(CASE WHEN status = 'active' THEN 1 ELSE 0 END)` вернет неверный результат (общее количество строк), а вариант без `ELSE 0` сработает корректно?
    - _Ответ: Агрегатные функции (кроме `COUNT(*)`) игнорируют `NULL`. В первом случае `0` считается как валидное не-NULL значение и инкрементирует счетчик для каждой строки._
2. **Задача:** Перепишите запрос `SUM(CASE WHEN category = 'Electronics' THEN price END)` на синтаксис `FILTER`, объяснив преимущество в читаемости.
3. **Практика:** Составьте SQL-запрос для расчета Churn Rate (оттока), используя `COUNT` с условием для активных пользователей и `COUNT` для ушедших пользователей в рамках одной строки.
