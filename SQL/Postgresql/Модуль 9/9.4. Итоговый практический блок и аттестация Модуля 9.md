#### Сквозной практический кейс: Проектирование универсальной системы автоматического аудита изменений

**Постановка задачи:** Создать централизованную систему логирования для таблиц финансового ядра. Требуется сохранять кто, когда и как изменил данные, используя `JSONB` для гибкости. [Advanced SQL #26](https://notebook.google.com/notebook/4).

**Пошаговый алгоритм решения:**

1. **Создание таблицы логов:** Используем `JSONB` для хранения снимков строк, что позволяет одной таблице обслуживать разные структуры данных.
    
    ```
    CREATE TABLE audit_logs (
        id BIGSERIAL PRIMARY KEY,
        table_name TEXT NOT NULL,
        operation TEXT NOT NULL,
        old_row_data JSONB,
        new_row_data JSONB,
        db_user TEXT DEFAULT CURRENT_USER,
        changed_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
    );
    ```
    
2. **Универсальная триггерная функция:** Применяем функции `to_jsonb()` для конвертации псевдопеременных `OLD` и `NEW`. [PostgreSQL Official Docs](https://www.postgresql.org/docs/current/functions-json.html).
    
    ```
    CREATE OR REPLACE FUNCTION fn_generic_audit_tracker()
    RETURNS TRIGGER AS $$
    BEGIN
        IF (TG_OP = 'DELETE') THEN
            INSERT INTO audit_logs(table_name, operation, old_row_data)
            VALUES (TG_TABLE_NAME, TG_OP, to_jsonb(OLD));
        ELSIF (TG_OP = 'UPDATE') THEN
            INSERT INTO audit_logs(table_name, operation, old_row_data, new_row_data)
            VALUES (TG_TABLE_NAME, TG_OP, to_jsonb(OLD), to_jsonb(NEW));
        ELSIF (TG_OP = 'INSERT') THEN
            INSERT INTO audit_logs(table_name, operation, new_row_data)
            VALUES (TG_TABLE_NAME, TG_OP, to_jsonb(NEW));
        END IF;
        RETURN NULL; -- В AFTER триггерах результат игнорируется
    END;
    $$ LANGUAGE plpgsql VOLATILE;
    ```
    
3. **Связывание с объектами:** Назначаем триггер на критичные таблицы (например, `accounts`).
    
    ```
    CREATE TRIGGER tr_audit_accounts
    AFTER INSERT OR UPDATE OR DELETE ON accounts
    FOR EACH ROW EXECUTE FUNCTION fn_generic_audit_tracker();
    ```
    
4. **Аналитическое ускорение:** Создаем `MATERIALIZED VIEW` для ежедневных отчетов СБ, чтобы не сканировать растущую таблицу логов напрямую. [SQL. Сборник рецептов](https://notebook.google.com/notebook/173).
    
    ```
    CREATE MATERIALIZED VIEW daily_audit_summary AS
    SELECT table_name, operation, COUNT(*) as change_count
    FROM audit_logs
    WHERE changed_at > CURRENT_DATE
    GROUP BY table_name, operation;
    ```
