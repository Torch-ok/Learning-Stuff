#### Теоретический фундамент и архитектура

Модификация данных в реляционной модели осуществляется с помощью языка манипулирования данными (**DML**). В PostgreSQL эти операции тесно интегрированы с архитектурой управления конкурентным доступом посредством многоверсионности (**MVCC**), где каждое изменение создает новую версию строки, а не перезаписывает старую [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/472).

**Вставка данных (`INSERT`):** Оператор `INSERT` используется для добавления новых кортежей в отношение. PostgreSQL поддерживает как точечные вставки одиночных строк, так и массовую вставку (**Bulk Insert**), которая значительно эффективнее за счет снижения накладных расходов на выполнение запроса [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/649). При возникновении конфликтов уникальности (например, попытке вставки существующего `PRIMARY KEY`) PostgreSQL предоставляет механизм **Upsert**. С помощью конструкции `ON CONFLICT (target) DO NOTHING` можно игнорировать ошибку, а `ON CONFLICT (target) DO UPDATE` позволяет обновить существующую строку, используя значения из виртуальной таблицы `EXCLUDED`, которая содержит данные, предложенные для вставки [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/506), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/648).

**Обновление данных (`UPDATE`):** Оператор `UPDATE` изменяет значения атрибутов в существующих строках. Для обеспечения атомарности и предотвращения потери данных при параллельных запросах используются инкрементальные обновления вида `SET counter = counter + 1` [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/663). PostgreSQL расширяет стандартный синтаксис конструкцией `UPDATE ... FROM`, позволяющей связывать обновляемую таблицу с другими источниками данных для сложной фильтрации или вычислений на основе связей [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/671).

**Удаление данных (`DELETE`):** `DELETE` удаляет строки, соответствующие предикату в блоке `WHERE`. Массовое удаление строк через DML-команду `DELETE` без ограничений приводит к значительному накоплению «мертвых» кортежей (**dead tuples**) в рамках **MVCC**, так как строки помечаются как удаленные, но физическое место на диске освобождается только после очистки процессом `VACUUM` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/382), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/472).

**Особенность PostgreSQL: Конструкция `RETURNING`:** Это мощное расширение позволяет возвращать данные непосредственно в момент выполнения DML-запроса. С помощью `RETURNING id` или `RETURNING *` можно мгновенно получить значения сгенерированных последовательностей (`IDENTITY`) или финальное состояние измененной строки без выполнения дополнительного запроса `SELECT`, что критично для производительности в высоконагруженных системах [Advanced SQL — Chapter #03 — Video #21](https://notebooklm.google.com/notebook/45), [Advanced SQL — Chapter #04 — Video #26](https://notebooklm.google.com/notebook/82).

**Архитектурное сравнение `DELETE` vs `TRUNCATE`:**

- `DELETE` — это DML-операция, которая обрабатывает каждую строку индивидуально, генерируя записи в журнале предзаписи (**WAL**) и проверяя ограничения [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/683).
- `TRUNCATE` — это DDL-утилита. Она не сканирует таблицу, а мгновенно освобождает страницы данных, обходя механизмы **MVCC**. Операция требует эксклюзивной блокировки таблицы (`AccessExclusiveLock`) и позволяет сбросить счетчики автоинкремента с помощью `RESTART IDENTITY` [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/683).

> [!warning] Актуализация синтаксиса 
> Использование команды `REPLACE` является специфичным для MySQL. В PostgreSQL для реализации логики «вставь или обнови» следует использовать стандарт `INSERT ... ON CONFLICT`, так как он корректно работает с внешними ключами и каскадными удалениями [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/507).

#### Практическая реализация и синтаксис

Пример реализации **Upsert** для синхронизации остатков товаров:

```sql
-- Вставка новой записи или обновление остатка в случае конфликта по SKU
INSERT INTO warehouse_stocks (sku, quantity, updated_at)
VALUES ('PRO-SQL-2026', 100, NOW())
ON CONFLICT (sku)
DO UPDATE SET
    quantity = warehouse_stocks.quantity + EXCLUDED.quantity,
    updated_at = EXCLUDED.updated_at
RETURNING quantity;
```

[Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/506), [Advanced SQL — Chapter #03 — Video #21](https://notebooklm.google.com/notebook/45).

Сложное обновление с использованием корреляции таблиц:

```sql
-- Обновление баланса пользователей на основе суммы последних заказов
UPDATE users u
SET balance = balance - sub.total_sum
FROM (
    SELECT user_id, SUM(amount) as total_sum
    FROM orders
    WHERE status = 'NEW'
    GROUP BY user_id
) AS sub
WHERE u.user_id = sub.user_id
RETURNING u.user_id, u.balance;
```

[SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/671), [Advanced SQL — Chapter 02 — Video #05](https://notebooklm.google.com/notebook/276).

Атомарный перенос данных в архивную таблицу:

```sql
-- Перенос старых логов в архив через Common Table Expression
WITH deleted_rows AS (
    DELETE FROM system_logs
    WHERE created_at < NOW() - INTERVAL '30 days'
    RETURNING *
)
INSERT INTO logs_archive
SELECT * FROM deleted_rows;
```

[Advanced SQL — Chapter #04 — Video #26](https://notebooklm.google.com/notebook/82), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/640).

#### Глоссарий терминов

- **DML (Data Manipulation Language)** — подмножество SQL для работы с данными внутри структур: `INSERT`, `UPDATE`, `DELETE` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/364).
- **Bulk Insert Performance** — преимущество массовой вставки данных одним оператором для минимизации транзакционных издержек [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/649).
- **Upsert Pattern (ON CONFLICT)** — стратегия обработки вставок, предотвращающая ошибки дублирования путем перевода операции в `UPDATE` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/508).
- **PostgreSQL RETURNING Clause** — механизм возврата модифицированных данных из DML-запроса «на лету» [Advanced SQL — Chapter #03 — Video #21](https://notebooklm.google.com/notebook/45).
- **DELETE vs TRUNCATE Mechanism** — различие между строковым удалением (DML) и полной очисткой хранилища таблицы (DDL) [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/683).
- **Table Access Locks (AccessExclusiveLock)** — тип блокировки, предотвращающий любой доступ к таблице во время выполнения операций типа `TRUNCATE` [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/683), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/472).

#### Практический кейс: Реализация безаварийного обновления остатков товаров и очистки таблиц

В сценарии высоконагруженного интернет-магазина обновление остатков часто страдает от **Race Condition**. Использование простого `UPDATE` с расчетом значения на стороне приложения может привести к некорректным данным. Решением является выполнение вычислений внутри БД: `UPDATE stocks SET quantity = quantity - 1 WHERE id = 500 AND quantity > 0`. Это гарантирует, что база данных сама проверит условие и изменит значение атомарно [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/475).

Для системных таблиц логов, объем которых достигает терабайт, выполнение `DELETE FROM logs` приведет к гигантскому росту **WAL**-файлов и блокировкам из-за долгого сканирования. Использование `TRUNCATE TABLE logs RESTART IDENTITY` мгновенно обнуляет таблицу и сбрасывает счетчики, обеспечивая минимальное время простоя системы [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/683).
