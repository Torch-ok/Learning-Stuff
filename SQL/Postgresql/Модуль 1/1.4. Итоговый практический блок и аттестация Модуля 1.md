#### Сквозной практический кейс: Проектирование реляционной схемы базы данных каталога товаров e-Commerce

**Постановка задачи:** Необходимо спроектировать и реализовать структуру хранения для каталога высоконагруженного интернет-магазина. Схема должна поддерживать строгую целостность финансовых данных, корректную работу со временем и обеспечивать высокую производительность при пагинации сотен тысяч товаров [Advanced SQL — Video #01](https://notebooklm.google.com/notebook/193).

**Пошаговый алгоритм выполнения:**

**1. Создание схемы данных (DDL):** Применяем оптимальное выравнивание полей (`Alignment Padding`), группируя 8-байтовые типы (`BIGINT`, `TIMESTAMPTZ`) в начале для экономии места на диске [Advanced SQL — Video #14](https://notebooklm.google.com/notebook/2).

```sql
CREATE TABLE categories (
    category_id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE products (
    -- Первичный ключ с современным IDENTITY
    product_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,

    -- Группировка фиксированных 8-байтовых типов (Padding Optimization)
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    price NUMERIC(15, 2) NOT NULL DEFAULT 0.00,

    category_id INTEGER NOT NULL,
    sku TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    description TEXT,

    -- Ограничения целостности
    CONSTRAINT chk_price_positive CHECK (price >= 0),
    CONSTRAINT fk_category FOREIGN KEY (category_id) REFERENCES categories(category_id)
);
```

[Advanced SQL — Video #21](https://notebooklm.google.com/notebook/52), [Advanced SQL — Video #14](https://notebooklm.google.com/notebook/14).

**2. Наполнение данными (Bulk Insert):** Выполняем массовую вставку и используем `RETURNING` для получения сгенерированных `ID` и меток времени без повторных запросов [Advanced SQL — Video #21](https://notebooklm.google.com/notebook/56).

```sql
INSERT INTO categories (name)
VALUES ('Electronics'), ('Home & Kitchen')
RETURNING category_id, name;

INSERT INTO products (category_id, sku, title, price)
VALUES
    (1, 'ELEC-9920', 'Smartphone X', 899.99),
    (1, 'ELEC-1102', 'Laptop Air', 1200.00),
    (2, 'HOME-0044', 'Coffee Maker', 45.50)
RETURNING product_id, created_at;
```

[SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/644), [Advanced SQL — Video #21](https://notebooklm.google.com/notebook/54).

**3. Поиск и эффективная пагинация:** Используем регистронезависимый поиск `ILIKE` и метод `Keyset Pagination` (Seek Method) через сравнение кортежей для стабильной скорости на больших данных [Advanced SQL — Video #06](https://notebooklm.google.com/notebook/276).

```sql
SELECT product_id, title, price, created_at
FROM products
WHERE title ILIKE '%phone%'
  AND (created_at, product_id) < ('2026-07-30 12:00:00+00', 500)
ORDER BY created_at DESC, product_id DESC
LIMIT 20;
```

[Advanced SQL — Video #06](https://notebooklm.google.com/notebook/274), [Advanced SQL — Video #13](https://notebooklm.google.com/notebook/1).

**4. Безопасный импорт (Upsert):** Обновляем цены и названия при конфликте `SKU` (артикула), используя виртуальную таблицу `EXCLUDED` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/506).

```sql
INSERT INTO products (category_id, sku, title, price)
VALUES (1, 'ELEC-9920', 'Smartphone X PRO', 949.99)
ON CONFLICT (sku)
DO UPDATE SET
    price = EXCLUDED.price,
    title = EXCLUDED.title,
    created_at = NOW() -- обновляем дату изменения
WHERE products.price <> EXCLUDED.price; -- обновляем только если цена изменилась
```

[SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/671), [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/506).

#### Комплексный контрольный тест для самопроверки

1. **Вопрос:** В каком логическом порядке PostgreSQL обрабатывает фазы запроса?
    
    - A) SELECT -> FROM -> WHERE -> ORDER BY
    - B) FROM -> WHERE -> SELECT -> ORDER BY -> LIMIT
    - C) WHERE -> FROM -> SELECT -> LIMIT
    - _Ответ: B. Процессор запросов сначала определяет источник данных, фильтрует их и только потом формирует результат и сортирует его [Advanced SQL — Video #04](https://notebooklm.google.com/notebook/36)._
2. **Задача на исправление DDL:** Исправьте ошибки в коде: `CREATE TABLE logs (id SERIAL, msg VARCHAR(255), price FLOAT, ts TIMESTAMP);`
    
    - _Решение:_
        1. Заменить `SERIAL` на `BIGINT GENERATED ALWAYS AS IDENTITY` (стандарт ANSI).
        2. Заменить `VARCHAR(255)` на `TEXT` (минимизация ограничений).
        3. Заменить `FLOAT` на `NUMERIC` (точность для денег).
        4. Заменить `TIMESTAMP` на `TIMESTAMPTZ` (поддержка часовых поясов).
        5. Переместить `ts` и `price` выше `msg` для оптимизации выравнивания [Advanced SQL — Video #14](https://notebooklm.google.com/notebook/2).
3. **Задание на Three-Valued Logic:** Что вернет запрос `SELECT * FROM users WHERE NOT (is_banned = TRUE);`, если в таблице есть строки, где `is_banned` имеет значение `NULL`?
    
    - _Ответ: Строки с NULL не будут возвращены, так как `NOT UNKNOWN` дает `UNKNOWN`, а условие WHERE пропускает только `TRUE` [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/45), [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/549)._
4. **Практика Upsert:** Напишите запрос, который вставляет товар, но если `SKU` уже существует, обновляет цену только в том случае, если новая цена выше старой.
    
    ```sql
    INSERT INTO products (sku, price, title, category_id)
    VALUES ('SKU-100', 500.00, 'Test', 1)
    ON CONFLICT (sku)
    DO UPDATE SET price = GREATEST(products.price, EXCLUDED.price);
    ```
    
    [Alan_Beaulieu-Learning_SQL-RU.pdf](https://notebooklm.google.com/notebook/506).
    
5. **Вопрос по обслуживанию:** Почему для мгновенной очистки таблицы логов размером 1 ТБ предпочтительнее использовать `TRUNCATE`, а не `DELETE`?
    
    - _Ответ: `DELETE` будет построчно помечать каждую запись как удаленную, генерируя огромный объем WAL и оставляя «мертвые кортежи». `TRUNCATE` является DDL-командой, которая освобождает страницы данных на уровне файловой системы практически мгновенно [SQL. Сборник рецептов, 2-е издание.pdf](https://notebooklm.google.com/notebook/683)._
