#### Теоретический фундамент и архитектура

В современной веб-разработке 2026 года потребность в мгновенном обновлении данных без перезагрузки страницы (Real-time) реализуется двумя основными способами: двунаправленным протоколом **WebSocket** и однонаправленным потоком **Server-Sent Events (SSE)**.

**Протокол WebSocket (WS/WSS):** В отличие от стандартного HTTP, работающего по принципу «запрос-ответ», WebSocket обеспечивает постоянное дуплексное соединение. Оно начинается с процесса «рукопожатия» (**Handshake**), когда клиент отправляет HTTP-запрос с заголовком `Upgrade: websocket`. Если сервер подтверждает переход, соединение переключается на бинарный протокол с минимальными накладными расходами на заголовки. FastAPI обрабатывает такие соединения через декоратор `@app.websocket()`, предоставляя доступ к методам `accept()`, `receive_text()`, `send_json()` и др.. Важной частью архитектуры является обработка исключения `WebSocketDisconnect`, которое возникает при штатном или аварийном разрыве связи со стороны клиента.

**Архитектурный паттерн ConnectionManager:** Так как WebSocket-соединения хранят состояние (Stateful), приложению необходимо централизованно управлять списком активных сокетов. Паттерн **ConnectionManager** позволяет агрегировать объекты `WebSocket`, реализовывать логику точечной рассылки сообщений конкретному `user_id` или широковещательного вещания (**Broadcast**) для всех участников чата или комнаты.

**Масштабирование и Redis Pub/Sub:** При запуске нескольких воркеров ASGI-сервера (например, через `uvicorn --workers`) или в кластере Kubernetes, разные клиенты могут быть подключены к разным физическим процессам. Для их синхронизации используется **Redis Pub/Sub**: сообщение, отправленное в один процесс, публикуется в канал Redis, откуда его вычитывают остальные ноды и транслируют своим подключенным клиентам.

**Server-Sent Events (SSE) как альтернатива:** SSE — это стандарт передачи данных от сервера к клиенту поверх обычного HTTP. В FastAPI 0.135.0+ реализована первоклассная поддержка SSE через `response_class=EventSourceResponse`. SSE идеально подходит для сценариев типа новостных лент, AI-чатов или дашбордов, так как он проще в реализации (не требует сложного управления состоянием на бэкенде) и нативно поддерживает автоматическое переподключение браузером.

#### Практическая реализация и синтаксис

**Реализация ConnectionManager для управления сессиями:**

```
from fastapi import WebSocket, WebSocketDisconnect

class ConnectionManager:
    def __init__(self):
        # Список активных соединений
        self.active_connections: list[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):
        self.active_connections.remove(websocket)

    async def send_personal_message(self, message: str, websocket: WebSocket):
        await websocket.send_text(message)

    async def broadcast(self, message: str):
        # Рассылка всем подключенным
        for connection in self.active_connections:
            await connection.send_text(message)

manager = ConnectionManager()
```

**Эндпоинт WebSocket с валидацией:**

```
from typing import Annotated
from fastapi import Depends, Query

@app.websocket("/ws/{client_id}")
async def websocket_endpoint(
    websocket: WebSocket,
    client_id: int,
    token: Annotated[str | None, Query()] = None # Валидация через Query
):
    await manager.connect(websocket)
    try:
        while True:
            # Ожидание сообщения от клиента
            data = await websocket.receive_text()
            await manager.broadcast(f"Client #{client_id} says: {data}")
    except WebSocketDisconnect:
        manager.disconnect(websocket)
        await manager.broadcast(f"Client #{client_id} left the chat")
```

from typing import AsyncIterable

@app.get("/notifications")
async def sse_notifications() -> AsyncIterable[ServerSentEvent]:

#### Глоссарий терминов

- **[WebSocket Protocol & Handshake](https://fastapi.tiangolo.com/advanced/websockets/)** — стандарт полнодуплексной связи, начинающийся с HTTP-запроса на смену протокола (Upgrade).
- **`WebSocketDisconnect` Exception** — специфическое исключение FastAPI/Starlette, сигнализирующее о закрытии сокета.
- **ConnectionManager Pattern** — объектно-ориентированный подход к хранению и фильтрации активных WebSocket-клиентов.
- **Broadcast Messaging** — технология одновременной отправки уведомления всем активным подписчикам.
- **Redis Pub/Sub Pattern** — механизм издатель-подписчик для координации сообщений между независимыми экземплярами приложения.
- **[Server-Sent Events (SSE) / EventSource](https://fastapi.tiangolo.com/tutorial/server-sent-events/)** — технология потоковой передачи данных от сервера к клиенту в формате `text/event-stream`.

#### Практический кейс: Разработка отказоустойчивого сервиса уведомлений и чата

**Сценарий:** Сервису электронной коммерции требуется отправлять пользователю мгновенное уведомление, когда статус его заказа меняется в Celery-воркере.

**Реализация:**

1. **Аутентификация:** Так как WebSockets не всегда удобно работают с кастомными заголовками `Authorization` в браузере, JWT-токен передается в Query-параметре `/ws?token=...`. Зависимость `get_current_user` валидирует его перед вызовом `websocket.accept()`.
2. **Интеграция с очередью:** Когда Celery-воркер завершает задачу, он делает `publish` в канал Redis `user_notifications_{user_id}` [8.2 draft].
3. **Обработка в FastAPI:** Каждый инстанс FastAPI слушает (через `aioredis`) сообщения из Redis. Если в текущем процессе есть активный сокет данного пользователя, `ConnectionManager` отправляет ему `send_json()` с деталями заказа.
4. **Устойчивость:** Для предотвращения накопления «мертвых» соединений (например, при потере сети без отправки Close frame), реализуется механизм **Heartbeat** (Ping-Pong), который очищает `manager.active_connections`.

#### Вопросы и задания для самопроверки

1. **Вопрос:** В какой ситуации вы выберете Server-Sent Events (SSE) вместо WebSockets для реализации real-time дашборда котировок акций?
    - _Ответ: Если клиенту нужно только получать обновления от сервера без отправки данных обратно по тому же каналу. SSE легче проходит через прокси-серверы, потребляет меньше ресурсов и автоматически восстанавливает соединение._
2. **Задача:** Вы заметили, что оперативная память сервера постоянно растет. В коде используется `ConnectionManager`, но нет блока `try...except WebSocketDisconnect`. Как это связано с утечкой?
    - _Решение: Если не удалять сокет из списка `active_connections` при разрыве связи, Python-объекты WebSocket будут бесконечно копиться в памяти._
3. **Практическое задание:** Напишите функцию-зависимость для `app.websocket`, которая извлекает токен из параметров запроса, проверяет его срок жизни через `PyJWT` и, в случае ошибки, закрывает соединение с кодом `4003` (Forbidden) до того, как будет вызван `accept()`.
