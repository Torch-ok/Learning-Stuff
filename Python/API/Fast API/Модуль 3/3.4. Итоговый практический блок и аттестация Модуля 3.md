#### Сквозной практический кейс: Сквозная валидация сложных вложенных JSON-структур

**Постановка задачи:** Реализовать систему валидации для оформления страхового полиса. Данные приходят в виде глубоко вложенного JSON, включающего информацию о страхователе, список объектов страхования и финансовые лимиты,. Необходимо гарантировать, что суммарная стоимость объектов не превышает общий лимит договора.

**Пошаговый алгоритм выполнения:**

1. **Проектирование иерархии моделей:** Используйте вложенные Pydantic-модели для описания структуры. Каждое поле должно быть снабжено ограничениями через `Annotated` и `Field`,.
    
    ```python
    from pydantic import BaseModel, Field, field_validator, model_validator, ConfigDict
    from typing import Annotated, List
    
    class InsuredObject(BaseModel):
        name: str
        value: Annotated[float, Field(gt=0)]
    
    class InsurancePolicy(BaseModel):
        model_config = ConfigDict(from_attributes=True, populate_by_name=True)
    
        holder_name: Annotated[str, Field(min_length=2, serialization_alias="holderName")]
        objects: List[InsuredObject]
        total_limit: Annotated[float, Field(gt=0, serialization_alias="totalLimit")]
    ```
    
2. **Реализация валидации данных:** Добавьте `@field_validator` для строгой проверки форматов (например, идентификационных номеров),.
    
    ```python
    @field_validator("holder_name")
    @classmethod
    def name_must_be_clean(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("Holder name cannot be empty")
        return v.strip()
    ```
    
3. **Кросс-полярная валидация всей модели:** Используйте `@model_validator(mode='after')` для проверки логических связей между списками объектов и общим лимитом,.
    
    ```python
    @model_validator(mode='after')
    def check_total_value(self) -> "InsurancePolicy":
        current_total = sum(obj.value for obj in self.objects)
        if current_total > self.total_limit:
            raise ValueError(f"Total value {current_total} exceeds limit {self.total_limit}")
        return self
    ```
    
4. **Сериализация ответа:** Настройте отдачу данных через `response_model` в эндпоинте, чтобы автоматически отфильтровать ненужные поля и применить алиасы для фронтенда,.
    
5. **Обработка ошибок:** При передаче некорректного JSON (например, превышение лимита), FastAPI автоматически вернет статус **422 Unprocessable Entity** с детальным деревом ошибок, указывающим на конкретный индекс объекта в списке,.
    

#### Комплексный контрольный тест для самопроверки

1. **Вопрос:** Какой параметр в `ConfigDict` необходимо установить в `True`, чтобы модель Pydantic могла корректно считывать данные из объектов SQLAlchemy?
    - _Ответ: `from_attributes=True`,._
2. **Задача:** Вы написали `@model_validator`, который внутри вызывает `self.model_dump()`. Почему это может привести к проблемам и как правильно возвращать данные из валидатора с `mode='after'`?
    - _Подсказка: Валидатор должен возвращать `self` (экземпляр модели) [3.2 draft]._
3. **Практическое задание:** Напишите `@field_validator` с `mode='before'`, который принимает строку и удаляет из нее все лишние пробелы с помощью метода `.strip()`, прежде чем Pydantic начнет проверять ее длину,.
4. **Задача на оптимизацию:** Ваше приложение отдает список из 10 000 объектов. Какую функцию Pydantic v2 вы используете для максимально быстрого превращения этого списка в JSON-строку?
    - _Ответ: `model_dump_json()`, так как она работает на уровне Rust-ядра,._
5. **Вопрос:** В чем разница между `validation_alias` и `serialization_alias`?
    - _Ответ: `validation_alias` используется для поиска поля во входящем JSON, а `serialization_alias` — для именования поля в исходящем ответе API._
