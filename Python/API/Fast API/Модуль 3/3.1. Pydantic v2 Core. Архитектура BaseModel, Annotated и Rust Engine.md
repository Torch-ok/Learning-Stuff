#### Теоретический фундамент и архитектура

В FastAPI 2026 года Pydantic v2 является безальтернативным стандартом для работы с данными, претерпевшим фундаментальный архитектурный сдвиг. В отличие от первой версии, ядро новой библиотеки — 'pydantic-core' — полностью написано на языке Rust. Это обеспечивает колоссальный прирост производительности, позволяя выполнять сериализацию и валидацию данных в 5–20 раз быстрее, а также эффективнее управлять оперативной памятью при обработке сложных JSON-структур.

Базовым строительным блоком любой схемы является класс 'BaseModel'. Он реализует механизм декларативного описания данных, где каждый атрибут наделяется типом и правилами валидации. При инициализации модели Pydantic автоматически проверяет входящие данные на соответствие схеме. Существует два основных режима работы: 'Lax mode' (нестрогий), при котором Pydantic пытается конвертировать типы (например, строку '"123"' в 'int'), и 'Strict mode' (строгий), требующий точного соответствия типов.

Современным стандартом описания метаданных является использование 'typing.Annotated'. Этот подход позволяет четко разделить определение типа данных и технические параметры валидации, передаваемые через класс 'Field'. Класс 'Field' предоставляет исчерпывающий инструментарий контроля:

- **Управление значениями:** 'default' для констант и 'default_factory' для динамических объектов (например, 'datetime.now').
- **Документация:** 'title' и 'description' для OpenAPI спецификации.
- **Числовая валидация:** ограничения 'gt' (больше), 'ge' (больше или равно), 'lt' (меньше) и 'le' (меньше или равно).
- **Строковая валидация:** 'min_length', 'max_length' и 'pattern' для проверки по регулярным выражениям.
- **Метаданные и маппинг:** 'examples' для примеров в Swagger и 'alias' для сопоставления полей с именами в JSON (например, 'CamelCase' в 'snake_case').

#### Практическая реализация и синтаксис

Пример современной схемы 'Product' с использованием 'Annotated' и конфигурации модели:

```python
from typing import Annotated
from pydantic import BaseModel, Field, ConfigDict

class ProductSchema(BaseModel):
    # Конфигурация модели v2
    model_config = ConfigDict(
        str_strip_whitespace=True, # Удаление пробелов в строках
        extra='forbid',            # Запрет лишних полей
        from_attributes=True       # Поддержка ORM-моделей
    )

    id: Annotated[int, Field(ge=1)]
    # Поле с алиасом и описанием
    title: Annotated[str, Field(alias="product_name", min_length=2, max_length=100)]
    # Опциональное поле с примером
    description: Annotated[str | None, Field(default=None, examples=["High-end smartphone"])]
    price: Annotated[float, Field(gt=0)]
```

Разница между режимами валидации:

1. **Lax mode (по умолчанию):** Если передать '{"id": "10"}' в схему, где 'id' объявлен как 'int', Pydantic успешно преобразует строку в число '10'.
2. **Strict mode:** При активации 'strict=True' в 'ConfigDict' или 'Field', та же попытка передачи строки вызовет ошибку '422 Unprocessable Entity', так как тип должен быть строго 'integer'.

> [!warning] Актуализация синтаксиса 
> В Pydantic v1 настройки модели задавались через внутренний 'class Config'. В актуальном Pydantic v2 (FastAPI 2026) следует использовать атрибут 'model_config' с экземпляром 'ConfigDict'. Также устаревший параметр 'orm_mode' заменен на 'from_attributes'.

#### Глоссарий терминов

- **[pydantic-core (Rust Engine)](https://fastapi.tiangolo.com/tutorial/response-model/#serialization)** — высокопроизводительное ядро Pydantic v2, написанное на Rust для ускорения обработки данных.
- **[BaseModel](https://fastapi.tiangolo.com/tutorial/body/#import-pydantics-basemodel)** — базовый класс для создания структур данных с автоматической валидацией и типизацией.
- **[typing.Annotated](https://fastapi.tiangolo.com/tutorial/query-params-str-validations/#use-annotated-in-the-type-for-the-q-parameter)** — стандартный механизм Python для добавления метаданных к типам, рекомендуемый для схем Pydantic.
- **[Field](https://fastapi.tiangolo.com/tutorial/body-fields/#body-fields)** — функция для определения детальных ограничений и метаданных конкретного атрибута модели.
- **Strict vs Lax Validation Mode** — режимы валидации, определяющие, разрешено ли Pydantic автоматически приводить типы данных к целевым.
- **[ConfigDict](https://fastapi.tiangolo.com/tutorial/response-model/#response-model-encoding-parameters)** — класс для глобальной настройки поведения модели Pydantic v2.

#### Практический кейс: Проектирование высокопроизводительных DTO схем

**Сценарий:** Разработка системы передачи данных (DTO) для каталога промышленного оборудования. Схема должна исключать ошибки ввода и блокировать попытки передачи вредоносных или избыточных полей.

**Реализация защиты:**

1. **Запрет лишних данных:** Настройка 'extra="forbid"' гарантирует, что если клиент отправит в JSON поле, не описанное в схеме, запрос будет отклонен с ошибкой '422'. Это критически важно для безопасности, чтобы предотвратить атаку "Mass Assignment".
2. **Очистка данных:** 'str_strip_whitespace=True' автоматически удаляет невидимые пробелы в начале и конце строк, предотвращая сохранение некорректных артикулов или имен.
3. **Использование псевдонимов:** 'alias' позволяет принимать данные от внешних систем, использующих другой регистр (например, 'ProductID'), сохраняя внутри Python-кода стандартный 'snake_case' ('product_id').

#### Вопросы и задания для самопроверки

1. **Вопрос:** Каким образом использование Rust в 'pydantic-core' влияет на обработку конкурентных запросов в FastAPI?
    - _Ответ: За счет высокой скорости сериализации CPU-bound операции по валидации JSON занимают меньше времени, освобождая Event Loop для других задач._
2. **Задача:** Найдите ошибку в коде: 'items: Annotated[list[str], Field(default=[])]'.
    - _Подсказка: Для изменяемых типов данных (списки, словари) в параметрах по умолчанию следует использовать 'default_factory', чтобы избежать разделения одного объекта списка между всеми экземплярами модели._
3. **Практическое задание:** Создайте схему 'SecureAccount', которая в 'Strict mode' принимает только 'UUID' в качестве 'id' и запрещает любые строковые представления идентификатора. Примените 'ConfigDict(strict=True)'.
