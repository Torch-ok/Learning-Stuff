#### Теоретический фундамент и архитектура

Механизм сериализации в FastAPI является одной из ключевых функций фреймворка, обеспечивающей автоматическое преобразование объектов Python в формат JSON. Центральную роль в этом процессе играет параметр декоратора эндпоинта `response_model`, который не только определяет структуру ответа для документации OpenAPI, но и выполняет строгую фильтрацию выходящих данных. Если функция возвращает объект, содержащий лишние поля (например, хеш пароля), FastAPI автоматически удалит их, если они не описаны в `response_model`.

Для тонкой настройки процесса преобразования используются специальные параметры сериализации:

- `response_model_exclude_unset`: исключает из итогового JSON те поля, которые не были явно переданы при создании модели. Это критически важно для корректной работы метода PATCH, чтобы избежать случайной перезаписи данных значениями по умолчанию.
- `response_model_exclude_defaults` и `response_model_exclude_none`: позволяют очистить ответ от полей, имеющих значения по умолчанию или `None`.
- `response_model_by_alias`: управляет тем, будут ли в ответе использоваться внутренние имена атрибутов Python или их публичные псевдонимы (алиасы).

Экспорт данных в Pydantic v2 осуществляется через два основных метода: `model_dump()` преобразует модель в стандартный словарь Python (`dict`), а `model_dump_json()` выполняет прямую высокоскоростную сериализацию в JSON-строку. Благодаря ядру `pydantic-core`, написанному на Rust, эти операции выполняются в 5–20 раз быстрее, чем в первой версии библиотеки. Для корректного преобразования моделей ORM (например, SQLAlchemy) в схемы Pydantic необходимо использовать настройку `model_config = ConfigDict(from_attributes=True)`, которая обучает Pydantic считывать данные через точечную нотацию атрибутов.

#### Практическая реализация и синтаксис

Современная архитектура FastAPI-приложения требует четкого разделения моделей для разных этапов жизни запроса.

**Пример разделения схем и использования алиасов:**

```python
from typing import Annotated
from pydantic import BaseModel, Field, ConfigDict, EmailStr

# Базовая модель со спецификацией алиасов для фронтенда
class UserBase(BaseModel):
    # Псевдоним 'emailAddress' для JSON и 'email' для Python
    email: Annotated[EmailStr, Field(validation_alias="emailAddress", serialization_alias="user_email")]
    username: str

class UserCreate(UserBase):
    password: str # Поле только для входа

class UserResponse(UserBase):
    id: int
    # Настройка для работы с ORM-моделями
    model_config = ConfigDict(from_attributes=True)

class UserInDB(UserResponse):
    hashed_password: str # Внутренняя модель для базы данных
```

**Обработка PATCH-запроса с `exclude_unset`:**

```python
@router.patch("/items/{item_id}", response_model=ItemResponse)
async def update_item(item_id: int, item_data: ItemUpdate, db: SessionDep):
    stored_item = await get_item_from_db(item_id)
    # Получаем только те поля, которые прислал клиент
    update_data = item_data.model_dump(exclude_unset=True)

    for field, value in update_data.items():
        setattr(stored_item, field, value)

    await db.commit()
    return stored_item
```

> [!warning] Актуализация синтаксиса 
> В Pydantic v2 метод `.dict()` заменен на `.model_dump()`, а `.json()` на `.model_dump_json()`. Использование старых методов в 2026 году считается устаревшим.

#### Глоссарий терминов

- **[`response_model`](https://fastapi.tiangolo.com/tutorial/response-model/)** — параметр декоратора, определяющий тип возвращаемых данных и обеспечивающий их фильтрацию.
- **[`response_model_exclude_unset`](https://fastapi.tiangolo.com/tutorial/response-model/#use-the-response-model-exclude-unset-parameter)** — инструкция не включать в ответ поля, значения которых не были установлены при инициализации.
- **[`model_dump()` & `model_dump_json()`](https://fastapi.tiangolo.com/tutorial/extra-models/#pydantics-model-dump)** — методы экспорта данных модели в `dict` или JSON-строку соответственно.
- **[`from_attributes`](https://fastapi.tiangolo.com/tutorial/response-model/#response-model-encoding-parameters)** — конфигурация Pydantic (ранее `orm_mode`), позволяющая извлекать данные из объектов через их атрибуты.
- **[`validation_alias` & `serialization_alias`](https://fastapi.tiangolo.com/tutorial/header-param-models/#disable-convert-underscores)** — инструменты переименования полей при получении (валидации) и отдаче (сериализации) данных.

#### Практический кейс: Безопасная сериализация пользовательских данных

**Сценарий:** Приложению необходимо вернуть профиль пользователя. В базе данных объект пользователя содержит `hashed_password`, `secret_token` и `is_admin`. Для клиента эти данные являются приватными и не должны покидать сервер.

**Реализация:**

1. Создается схема `UserOut`, включающая только `username`, `email` и `id`.
2. В эндпоинте указывается `@app.get("/me", response_model=UserOut)`.
3. Даже если функция вернет полный объект пользователя из базы (ORM model), FastAPI применит `UserOut` как маску и отфильтрует все sensitive-поля.

**Производительность:** Прямое использование `model_dump_json()` на уровне приложения позволяет отдавать ответы значительно быстрее, чем традиционная цепочка `json.dumps(model.dict())`, так как Pydantic v2 выполняет сериализацию на низкоуровневом Rust-коде, минуя создание промежуточных тяжелых объектов Python.

#### Вопросы и задания для самопроверки

1. **Вопрос:** В чем заключается преимущество `model_dump_json()` перед `model_dump()` при работе в высоконагруженных ASGI-системах?
    - _Ответ: `model_dump_json()` работает на уровне Rust и не создает промежуточный словарь Python, что снижает нагрузку на CPU и память._
2. **Задача:** Реализуйте логику обновления товара, где клиент может прислать пустую строку в описании, но если поле описания вообще отсутствует в запросе, оно не должно изменяться в базе.
    - _Подсказка: используйте `model_dump(exclude_unset=True)`._
3. **Практическое задание:** Настройте схему `ClientData` так, чтобы она принимала поле `first_name` из JSON как `firstName` (camelCase), но при сериализации в ответ возвращала его как `client_given_name`. Используйте `validation_alias` и `serialization_alias`.
