#### Теоретический фундамент и архитектура

В современной разработке на FastAPI 2026 года тестирование является неотъемлемой частью жизненного цикла ПО, обеспечивая надежность кода и уверенность при деплое. Пирамида тестирования включает три основных уровня: **Unit-тесты** (проверка изолированных функций и методов), **Интеграционные тесты** (проверка взаимодействия компонентов, таких как эндпоинты и база данных) и **End-to-End (E2E)** (симуляция полного пути пользователя).

Для организации тестов используется библиотека 'pytest', ставшая стандартом индустрии благодаря своей мощности и гибкости. В асинхронных приложениях она дополняется плагином 'pytest-asyncio', который позволяет корректно управлять **Event Loop** внутри тестовых функций. Важной концепцией является автоматическое обнаружение тестов: 'pytest' ищет файлы с префиксом 'test_' и функции, начинающиеся с 'test_'.

Для отправки запросов к API в синхронном режиме FastAPI предоставляет 'TestClient', построенный на базе библиотеки 'requests'. Однако для полноценного тестирования асинхронных эндпоинтов, неблокирующего ввода-вывода и потоковых данных (SSE/JSON Lines) в 2026 году обязательным является использование 'httpx.AsyncClient'. Это связано с тем, что стандартные синхронные клиенты могут заблокировать цикл событий, что приведет к некорректным результатам при проверке конкурентных запросов.

Архитектура тестов строится на **Фикстурах** ('fixtures') — функциях, которые подготавливают окружение (создают базу данных, инициализируют клиента) перед выполнением теста и очищают ресурсы после него. Фикстуры имеют различные области видимости (**scope**):

- 'function' (по умолчанию) — выполняется для каждого теста.
- 'module' — один раз на весь файл с тестами.
- 'session' — один раз за весь цикл запуска тестов.

Для сокращения дублирования кода применяется декоратор '@pytest.mark.parametrize', позволяющий запускать один и тот же тест с разными наборами входных данных и ожидаемых результатов.

#### Практическая реализация и синтаксис

Централизованная настройка зависимостей выносится в файл 'conftest.py'.

**Пример настройки асинхронного клиента в 'conftest.py':**

```
import pytest
from httpx import AsyncClient
from typing import AsyncGenerator
from app.main import app

@pytest.fixture(scope="function")
async def client() -> AsyncGenerator[AsyncClient, None]:
    # Инициализация асинхронного клиента для эмуляции запросов
    async with AsyncClient(app=app, base_url="http://test") as ac:
        yield ac # Передача клиента в тестовую функцию
```

[Async Tests](https://fastapi.tiangolo.com/advanced/async-tests/), [Testing Dependencies with Overrides](https://fastapi.tiangolo.com/advanced/testing-dependencies/)

**Модульный тест Pydantic-схемы (Unit Test):** Unit-тесты проверяют логику валидации без запуска всего приложения.

```
from app.schemas import OrderCreate

def test_order_schema_invalid_quantity():
    # Проверка, что Pydantic выбрасывает ошибку при невалидных данных
    with pytest.raises(ValueError):
        OrderCreate(item_id=1, quantity=-10) # Ожидается 422 в API
```

[Python FastAPI Tutorial (Part 4)](https://www.youtube.com/watch?v=PythonFastAPITutorial4), [Body - Fields](https://fastapi.tiangolo.com/tutorial/body-fields/)

**Интеграционный тест эндпоинта (Integration Test):** Для написания тестов рекомендуется подход **Triple A** (Arrange, Act, Assert).

```
@pytest.mark.asyncio
async def test_create_order_success(client: AsyncClient):
    # 1. Arrange (Подготовка данных - в данном случае тело запроса)
    order_data = {"item_id": 1, "quantity": 2}

    # 2. Act (Выполнение действия - отправка POST запроса)
    response = await client.post("/api/v1/orders/", json=order_data)

    # 3. Assert (Проверка результатов)
    assert response.status_code == 201 # Успешное создание
    data = response.json()
    assert data["item_id"] == 1
    assert "id" in data # Проверка наличия сгенерированного ID
```

[Python API Development](https://www.youtube.com/watch?v=PythonAPIDevelopment), [Response Status Code](https://fastapi.tiangolo.com/tutorial/response-status-code/)

> [!warning] Актуализация синтаксиса 
> В старых версиях FastAPI часто использовался только синхронный 'TestClient'. В 2026 году для работы с асинхронными драйверами (SQLAlchemy 2.0 Async, asyncpg) и неблокирующим IO необходимо переходить на 'httpx.AsyncClient', чтобы избежать ошибок 'MissingGreenlet' в тестах.

#### Практический кейс: Тестирование API сервиса заказов

**Сценарий:** Реализация изоляционного тестирования для роутера 'orders_router'. Необходимо проверить сценарии создания заказа, обработку ошибок валидации и фильтрацию списка заказов.

**Алгоритм выполнения:**

1. **Настройка переопределения (Overrides):** В 'conftest.py' используется 'app.dependency_overrides' для подмены реальной сессии БД на тестовую (например, SQLite in-memory), чтобы тесты не влияли на 'production' данные.
2. **Arrange:** Через фикстуру 'setup_db' таблицы создаются перед каждым тестом и удаляются после ('drop_all'), обеспечивая чистоту окружения.
3. **Act:** 'AsyncClient' отправляет запросы к эндпоинтам. Для тестирования защищенных роутов используется фикстура 'authorized_client', которая добавляет JWT-токен в заголовки.
4. **Параметризация фильтров:** С помощью '@pytest.mark.parametrize' проверяются различные комбинации параметров запроса (например, фильтрация заказов по статусу 'pending', 'shipped'), проверяя корректность SQL-фильтров.
5. **Оптимизация:** Асинхронный запуск тестов позволяет выполнять I/O операции (запросы к БД) параллельно, что сокращает время выполнения сюиты в CI/CD пайплайнах.

#### Вопросы и задания для самопроверки

1. **Вопрос:** В чем заключается преимущество 'httpx.AsyncClient' перед синхронным 'TestClient' при проверке работы эндпоинтов, использующих 'BackgroundTasks'?
    - _Ответ: 'AsyncClient' позволяет Event Loop продолжать работу после отправки ответа, что необходимо для корректного выполнения и завершения фоновых задач в тестовом окружении._
2. **Задача:** Тест падает с ошибкой 'ScopeMismatch'. Вы пытаетесь передать фикстуру с 'scope="session"' (например, 'test_engine') в асинхронную фикстуру с 'scope="function"'. Как исправить эту ошибку и соблюсти иерархию зависимостей?.
3. **Практическое задание:** Напишите параметризованный тест для Pydantic-модели 'ProductUpdate', который проверяет, что поле 'price' не может быть меньше 0.01, используя список из 5 различных некорректных значений.
