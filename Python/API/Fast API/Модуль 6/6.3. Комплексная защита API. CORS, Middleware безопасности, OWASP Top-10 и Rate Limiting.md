#### Теоретический фундамент и архитектура

Безопасность современного асинхронного API в 2026 году строится на принципе эшелонированной защиты, начиная от управления доступом на уровне браузера и заканчивая контролем частоты запросов на уровне инфраструктуры.

Механизм **Cross-Origin Resource Sharing (CORS)** — это стандарт безопасности браузеров, который регулирует взаимодействие фронтенд-приложений и API, находящихся на разных доменах или портах. Когда клиент (браузер) пытается выполнить запрос к другому источнику (`Origin`), он сначала может отправить **Preflight-запрос** методом `OPTIONS`, чтобы проверить заголовки `Access-Control-Allow-Origin` и разрешенные методы. В FastAPI настройка осуществляется через `CORSMiddleware`. Критически важным является понимание того, что использование `allow_origins=["*"]` совместно с `allow_credentials=True` является грубым нарушением безопасности, так как позволяет любому вредоносному сайту считывать авторизационные данные пользователя.

**TrustedHostMiddleware** обеспечивает защиту от атак типа **HTTP Host Header Attack**, проверяя заголовок `Host` в каждом входящем запросе и отклоняя те, что не соответствуют белому списку разрешенных доменов.

Защита от угроз из списка **OWASP Top-10** встроена в ядро FastAPI и SQLAlchemy:

- **XSS (Cross-Site Scripting):** Предотвращается за счет использования `HttpOnly` кук для хранения JWT-токенов, что делает их недоступными для вредоносных скриптов на стороне клиента.
- **CSRF (Cross-Site Request Forgery):** Становится актуальной проблемой при переходе с `Bearer` токенов в заголовках на авторизацию через куки. FastAPI требует использования специальных защитных механизмов (например, `SameSite` флаг или токены в формах) для предотвращения подделки запросов.
- **SQL-инъекции:** SQLAlchemy 2.0 по умолчанию использует параметризацию запросов (placeholders), что исключает возможность исполнения произвольного SQL-кода, переданного пользователем в параметрах.

**Rate Limiting** (ограничение частоты запросов) — это первая линия защиты от DoS-атак и автоматизированного перебора паролей. Популярные алгоритмы, такие как **Sliding Window** (скользящее окно) и **Token Bucket**, позволяют гибко настраивать лимиты. В экосистеме FastAPI для этого применяется библиотека `slowapi`, которая может использовать `Redis` в качестве бэкенда для хранения состояний лимитов в распределенных системах.

#### Практическая реализация и синтаксис

**Безопасная конфигурация Middleware:**

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from fastapi.middleware.trustedhost import TrustedHostMiddleware

app = FastAPI()

# Защита Host Header
app.add_middleware(
    TrustedHostMiddleware,
    allowed_hosts=["api.example.com", "*.example.com", "localhost"]
)

# Настройка CORS для конкретного фронтенда
origins = [
    "https://app.example.com",
    "http://localhost:5173", # Dev окружение
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=origins,
    allow_credentials=True, # Разрешает передачу кук и заголовков авторизации
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type", "X-Custom-Header"],
)
```

[CORS Parameters](https://fastapi.tiangolo.com/tutorial/cors/#use-corsmiddleware), [Bigger Applications](https://fastapi.tiangolo.com/tutorial/bigger-applications/#apirouter)

**Настройка Rate Limiting через `slowapi`:**

```python
from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.util import get_remote_address
from slowapi.errors import RateLimitExceeded

# Инициализация лимитера (используется IP клиента)
limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)

@app.post("/login")
@limiter.limit("5/minute") # Ограничение: 5 запросов в минуту
async def login(request: Request):
    return {"message": "Login successful"}
```

[Rate Limiting Logic](https://fastapi.tiangolo.com/tutorial/bigger-applications/#dependencies), [Handling Errors](https://fastapi.tiangolo.com/tutorial/handling-errors/)

**Установка JWT в безопасную куку:**

```python
@app.post("/token")
async def set_auth_cookie(response: Response):
    token = create_access_token(data={"sub": "user_id"})
    response.set_cookie(
        key="access_token",
        value=f"Bearer {token}",
        httponly=True,   # Защита от XSS
        secure=True,     # Только через HTTPS
        samesite="strict", # Защита от CSRF
        max_age=1800
    )
    return {"status": "ok"}
```

[Response Cookies](https://fastapi.tiangolo.com/advanced/response-cookies/), [Security - First Steps](https://fastapi.tiangolo.com/tutorial/security/first-steps/)

#### Глоссарий терминов

- **[CORS & Preflight Requests](https://fastapi.tiangolo.com/tutorial/cors/)** — механизм безопасности, использующий предварительные `OPTIONS` запросы для проверки прав доступа между разными доменами.
- **[TrustedHost Middleware](https://fastapi.tiangolo.com/tutorial/middleware/)** — компонент FastAPI, предотвращающий атаки через подделку HTTP-заголовка `Host`.
- **[HttpOnly / Secure / SameSite Cookies](https://fastapi.tiangolo.com/tutorial/cookie-params/)** — атрибуты HTTP-кук, обеспечивающие защиту от кражи токенов через JavaScript и атак типа CSRF.
- **Rate Limiting (Token Bucket / Sliding Window)** — стратегии контроля трафика для предотвращения перегрузки сервера и защиты от ботов.
- **[OWASP Top-10](https://fastapi.tiangolo.com/tutorial/security/first-steps/)** — перечень наиболее критических рисков безопасности веб-приложений, против которых FastAPI предоставляет встроенные защиты.
- **HTTP Host Header Attack** — уязвимость, возникающая, когда сервер доверяет значению заголовка `Host` для генерации ссылок или редиректов.

#### Практический кейс: Защита публичного API от OWASP-угроз

**Сценарий:** Необходимо подготовить к релизу API сервиса обработки платежей. Требуется исключить утечки данных, DoS-атаки на эндпоинты входа и несанкционированный доступ из сторонних браузерных расширений.

**Реализация:**

1. **Hardening CORS:** Вместо `allow_origins=["*"]` прописываются только доверенные поддомены компании. Это закрывает возможность проведения атак с использованием поддельных интерфейсов.
2. **Защита эндпоинтов:** Для `/auth/token` устанавливается жесткий лимит 3 запроса в минуту на один IP через `slowapi`. В качестве хранилища используется Redis, чтобы лимиты работали синхронно на всех 10 воркерах приложения в Kubernetes.
3. **Security Headers:** Через кастомное Middleware добавляются заголовки `X-Content-Type-Options: nosniff` и `Content-Security-Policy`, минимизирующие риски XSS-инъекций в случае возврата HTML-ответов.
4. **Санитарная обработка:** Все входные строковые параметры Pydantic-моделей проверяются на отсутствие HTML-тегов через регулярные выражения в `Annotated`.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему хранение JWT в `localStorage` считается менее безопасным, чем в `HttpOnly` куках?
    - _Ответ: Любой скрипт (включая вредоносный XSS) может прочитать данные из `localStorage`, тогда как `HttpOnly` куки доступны только серверу._
2. **Задача:** Найдите ошибку: `CORSMiddleware(allow_origins=["*"], allow_credentials=True)`. К каким последствиям она может привести в production?
3. **Практическое задание:** Напишите декоратор для эндпоинта, который использует `slowapi` для установки лимита `100/day` для всех пользователей и `1000/day` для тех, кто передает заголовок `X-VIP-Token`.
