#### Теоретический фундамент и архитектура

В отличие от стандартного протокола HTTP, основанного на модели «запрос-ответ», протокол **WebSocket (RFC 6455)** обеспечивает постоянное полнодуплексное (двунаправленное) соединение между клиентом и сервером через один TCP-сокет. Это критически важно для приложений реального времени, таких как чаты, финансовые тикеры или игровые серверы, где задержка (Latency) должна быть минимальной.

Процесс начинается с **HTTP Upgrade Handshake**. Клиент отправляет стандартный HTTP-запрос с заголовками `Connection: Upgrade` и `Upgrade: websocket`. Если сервер поддерживает протокол, он возвращает статус `101 Switching Protocols`, после чего соединение переходит в режим передачи фреймов (frames).

В FastAPI для обработки таких соединений используется декоратор `@app.websocket()`. В отличие от `async def` эндпоинтов для HTTP, обработчик сокета управляет всем жизненным циклом соединения вручную:

- **`await websocket.accept()`** — подтверждение хэндшейка. До этого вызова соединение не считается установленным, и попытка отправки данных приведет к ошибке.
- **Цикл чтения/отправки** — асинхронный цикл (обычно `while True`), в котором сервер ожидает данные от клиента.
- **Чтение**: Методы `receive_text()`, `receive_bytes()` или `receive_json()`. Последний автоматически десериализует входящую JSON-строку в объект Python.
- **Отправка**: Методы `send_text()`, `send_bytes()` или `send_json()`. Благодаря Pydantic v2 Core, сериализация JSON происходит на уровне Rust, обеспечивая максимальную производительность.

Безопасное завершение сессии требует обработки исключения **`WebSocketDisconnect`**, которое возникает, когда клиент закрывает вкладку браузера или теряет сеть. Для штатного закрытия сокета со стороны сервера используется `await websocket.close(code=1000)`.

#### Практическая реализация и синтаксис

Современный подход требует обязательной валидации данных и аутентификации пользователя до того, как сервер подтвердит установку соединения.

**Базовый WebSocket-эндпоинт с аутентификацией и Pydantic:**

```python
from typing import Annotated
from fastapi import FastAPI, WebSocket, WebSocketDisconnect, Query, Depends, status
from pydantic import BaseModel, ValidationError

app = FastAPI()

# Схема для валидации входящих сообщений
class ChatMessage(BaseModel):
    text: str
    recipient_id: int | None = None

@app.websocket("/ws")
async def websocket_endpoint(
    websocket: WebSocket,
    # Проверка JWT-токена в Query-параметрах до установления связи
    token: Annotated[str, Query()]
):
    # Логика проверки токена (имитация)
    if token != "secret-jwt-token":
        await websocket.close(code=status.WS_1008_POLICY_VIOLATION)
        return

    await websocket.accept() #
    try:
        while True:
            # Ожидание JSON данных от клиента
            data = await websocket.receive_json()

            try:
                # Валидация через Pydantic v2
                message = ChatMessage.model_validate(data)

                # Эхо-ответ в формате JSON
                await websocket.send_json({
                    "status": "received",
                    "echo": message.text,
                    "from_token": token[:5] + "..."
                })
            except ValidationError as e:
                # Отправка ошибки валидации без разрыва сокета
                await websocket.send_json({"error": "Invalid format", "details": e.errors()})

    except WebSocketDisconnect:
        # Логирование отключения
        print("Client disconnected normally")
```

> [!warning] Актуализация синтаксиса
> В 2026 году настоятельно рекомендуется выполнять аутентификацию (проверку JWT) **до** вызова `await websocket.accept()`. Если вызвать `accept()` для неавторизованного пользователя, вы потратите ресурсы сервера на установку сокета, который всё равно придется закрыть.

#### Глоссарий терминов

- **[WebSocket Protocol (RFC 6455)](https://fastapi.tiangolo.com/advanced/websockets/)** — стандарт полнодуплексного протокола связи поверх TCP, использующий минимальные заголовки после хэндшейка.
- **[HTTP Upgrade Handshake](https://fastapi.tiangolo.com/tutorial/security/first-steps/)** — механизм переключения протокола с HTTP на WebSocket через заголовки `Upgrade`.
- **[`WebSocket.accept()`](https://fastapi.tiangolo.com/advanced/websockets/)** — метод FastAPI, завершающий процесс рукопожатия и открывающий поток данных.
- **[`WebSocketDisconnect`](https://fastapi.tiangolo.com/advanced/websockets/)** — исключение, сигнализирующее о разрыве соединения клиентом.
- **[Bidirectional Streaming](https://fastapi.tiangolo.com/advanced/stream-data/)** — возможность одновременной передачи и приема данных без ожидания завершения транзакции.
- **Frame-based Communication** — способ передачи данных в WebSocket мелкими фрагментами (кадрами), в отличие от потока байтов в голом TCP.

#### Практический кейс: Разработка эхо-сервиса с валидацией Pydantic

**Сценарий**: Необходимо создать шлюз, который принимает сообщения только от доверенных IoT-устройств. Устройства отправляют телеметрию в формате JSON.

**Реализация**:

1. **Пре-ацепт проверка**: При поступлении запроса на `/ws?device_key=...`, FastAPI извлекает `device_key` через `Query`. Если ключ не найден в БД (или Redis), сервер вызывает `websocket.close(code=4003)`.
2. **Устойчивость к ошибкам**: Внутри цикла `while True` блок `try...except ValidationError` гарантирует, что если устройство пришлет "битый" JSON или строку вместо числа в поле `temperature`, сервер отправит диагностическое сообщение `send_json()`, но не закроет сокет.
3. **Результат**: Снижение нагрузки на БД за счет того, что проверка прав происходит один раз при подключении, а не для каждого сообщения телеметрии.

#### Вопросы и задания для самопроверки

1. **Вопрос**: Почему вызов `websocket.send_text()` до `await websocket.accept()` вызовет ошибку `RuntimeError`?
    - _Ответ: Потому что протокол WebSocket требует завершения HTTP-хэндшейка (Upgrade) перед началом обмена кадрами данных. Без `accept()` соединение остается на уровне HTTP._
2. **Задача**: Реализуйте в цикле `while True` проверку времени последнего сообщения. Если клиент не присылал данных более 60 секунд, сервер должен закрыть сокет с кодом `1001` (Going Away).
3. **Практическое задание**: Напишите функцию-зависимость, которая извлекает JWT из заголовка `Sec-WebSocket-Protocol` (часто используется, когда браузерные API не позволяют выставлять `Authorization` заголовок для WS) и возвращает объект `User`.
