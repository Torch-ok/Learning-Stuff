#### Теоретический фундамент и архитектура

В современной веб-разработке 2026 года для передачи данных в реальном времени, не требующих двунаправленного взаимодействия, протокол **Server-Sent Events (SSE / W3C EventSource)** является более эффективным и простым в реализации решением, чем WebSockets. SSE представляет собой стандарт потоковой передачи текстовых данных от сервера к клиенту поверх классического протокола HTTP в формате `text/event-stream`.

**Преимущества SSE перед WebSockets для дашбордов и LLM:**

- **Нативная поддержка браузерами**: Используется стандартный `EventSource API`, который автоматически обрабатывает переподключение при разрыве связи.
- **Однонаправленность**: Идеально подходит для сценариев типа генеративного ИИ (LLM Streaming), где сервер постепенно «выталкивает» токены текста, или для живых лент уведомлений и котировок.
- **HTTP-совместимость**: SSE работает через обычные порты 80/443 и легче проходит через прокси-серверы и корпоративные брандмауэры.

В FastAPI поддержка SSE реализована через `response_class=EventSourceResponse`. Фреймворк автоматически реализует лучшие практики: отправляет «keep-alive» комментарии каждые 15 секунд для поддержания соединения, устанавливает заголовок `Cache-Control: no-cache` и отключает буферизацию через заголовок `X-Accel-Buffering: no` (критично для Nginx).

Для передачи бинарных данных, таких как видео или аудио, используется **`fastapi.responses.StreamingResponse`**. Эта механика основана на использовании асинхронных генераторов (`async generator`), которые возвращают данные побайтовыми частями (чанками), что позволяет обрабатывать файлы любого размера без переполнения оперативной памяти (RAM). Кроме того, `StreamingResponse` поддерживает **HTTP Range Requests (206 Partial Content)**, что необходимо для корректной работы перемотки в видеоплеерах.

#### Практическая реализация и синтаксис

**Реализация SSE-эндпоинта с именованными событиями:**

```python
import asyncio
from datetime import datetime
from typing import AsyncIterable
from fastapi import APIRouter
from fastapi.sse import EventSourceResponse, ServerSentEvent

router = APIRouter()

@router.get("/stream-metrics")
async def sse_metrics() -> AsyncIterable[ServerSentEvent]:
    async def event_generator():
        while True:
            # Генерация данных метрики
            yield ServerSentEvent(
                data={"timestamp": str(datetime.now()), "cpu_load": 42},
                event="metric_update", # Имя события для клиента
                id="event_123" # ID для возобновления через Last-Event-ID
            )
            await asyncio.sleep(1)

    return EventSourceResponse(event_generator())
```

[Stream SSE with FastAPI](https://fastapi.tiangolo.com/tutorial/server-sent-events/#stream-sse-with-fastapi), [ServerSentEvent Fields](https://fastapi.tiangolo.com/tutorial/server-sent-events/#serversentevent)

**StreamingResponse для генерации крупного CSV-отчета:**

```python
from fastapi.responses import StreamingResponse

@router.get("/export-csv")
async def export_large_csv():
    async def csv_generator():
        yield "id,name,value\n"
        for i in range(1000000):
            # Постепенная отдача строк без загрузки всего списка в RAM
            yield f"{i},User_{i},{i*10}\n"

    return StreamingResponse(csv_generator(), media_type="text/csv")
```

[Stream JSON Lines](https://fastapi.tiangolo.com/tutorial/stream-json-lines/), [Return a Response Directly](https://fastapi.tiangolo.com/advanced/response-directly/)

**Потоковая отдача видео чанками:**

```python
import aiofiles
from fastapi.responses import StreamingResponse

@router.get("/video/play")
async def stream_video():
    async def file_iterator(file_path: str, chunk_size: int = 1024 * 1024):
        async with aiofiles.open(file_path, mode="rb") as f:
            while chunk := await f.read(chunk_size):
                yield chunk # Отправка по 1 МБ за раз

    return StreamingResponse(file_iterator("movie.mp4"), media_type="video/mp4")
```

[Stream binary data](https://fastapi.tiangolo.com/tutorial/stream-json-lines/#use-cases), [Async IO](https://fastapi.tiangolo.com/async/)

#### Глоссарий терминов

- **[Server-Sent Events (SSE)](https://fastapi.tiangolo.com/tutorial/server-sent-events/)** — стандарт однонаправленной передачи текстовых событий от сервера к клиенту через постоянное HTTP-соединение.
- **[`EventSourceResponse`](https://fastapi.tiangolo.com/tutorial/server-sent-events/#stream-sse-with-fastapi)** — класс ответа FastAPI для автоматической инкапсуляции данных в формат SSE.
- **[`StreamingResponse`](https://fastapi.tiangolo.com/advanced/custom-response/#streamingresponse)** — механизм для передачи потоковых данных (бинарных или текстовых) с использованием итераторов или генераторов.
- **Async Generators in HTTP Response** — функции с `async def` и `yield`, позволяющие асинхронно производить данные для потокового ответа.
- **HTTP Range Requests (`206 Partial Content`)** — механизм запроса части ресурса, позволяющий скачивать файлы по частям или перематывать видео.
- **Content-Type: `text/event-stream`** — обязательный заголовок для SSE, указывающий браузеру на начало потоковой передачи событий.

#### Практический кейс: Потоковый вывод генерации текста (LLM)

**Сценарий**: Реализация API для AI-чата. Когда пользователь задает вопрос, нейросеть начинает генерировать ответ. Чтобы пользователь не ждал 10-20 секунд полного формирования текста, приложение должно стримить каждый новый токен (слово) мгновенно.

**Реализация**:

1. **SSE для текста**: Эндпоинт `/ai/chat` использует `EventSourceResponse`. Каждый раз, когда модель выдает новый кусок текста, он упаковывается в `ServerSentEvent(data=token)` и уходит клиенту.
2. **Экономия ресурсов**: Благодаря тому, что FastAPI выполняет сериализацию на стороне Rust-ядра (Pydantic v2), нагрузка на CPU при массовом стриминге минимальна.
3. **RAM Management**: При традиционной отдаче файла (например, видео-инструкции к ответу ИИ) целиком, серверу потребовалось бы загрузить весь файл в память. Использование `StreamingResponse` с чанками по 1 МБ снижает потребление RAM в сотни раз для каждого активного соединения.

#### Вопросы и задания для самопроверки

1. **Вопрос**: Почему браузерный клиент SSE автоматически восстанавливает соединение при сбое (HTTP 5xx или потеря сети), а для WebSockets это нужно реализовывать вручную на JavaScript?
    - _Ответ: Это часть спецификации W3C EventSource. Браузер отслеживает состояние HTTP-канала и, используя поле `retry` из последнего события или стандартные интервалы, инициирует новый запрос с заголовком `Last-Event-ID`._
2. **Задача**: В генераторе `StreamingResponse` используется `with open(...)` вместо `aiofiles.open(...)`. Как это повлияет на работу FastAPI при 100 одновременных подключениях?
    - _Ответ: Стандартный `open` является блокирующей операцией ввода-вывода. Хотя FastAPI запустит такой генератор в тред-пуле, это менее эффективно, чем нативная асинхронность, и может привести к исчерпанию пула потоков [593, 8.1 draft]._
3. **Практическое задание**: Напишите SSE-эндпоинт, который раз в секунду отправляет объект Pydantic-модели `SystemStatus`. Убедитесь, что вы объявили возвращаемый тип как `AsyncIterable[SystemStatus]` для автоматической сериализации и валидации.
