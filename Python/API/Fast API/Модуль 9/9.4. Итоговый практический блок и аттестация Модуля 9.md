#### Сквозной практический кейс: Горизонтально масштабируемый чат-сервер на WebSockets с Redis Pub/Sub

**Постановка задачи:** Спроектировать и разработать чат-сервер, способный работать в кластере (несколько нод FastAPI). Система должна обеспечивать изоляцию сообщений по комнатам (`room_id`), проверять JWT-токены перед подключением и использовать Redis для синхронизации сообщений между серверами [9.4 prompt].

**Пошаговый алгоритм выполнения:**

1. **Создание `ConnectionManager`**: Реализуйте класс для учета локальных подключений каждой ноды. Используйте структуру `dict[str, list[WebSocket]]`, где ключом является `room_id` [9.2 draft]. Это позволит менеджеру знать, каким именно сокетам, подключенным к _текущему_ процессу, нужно доставить сообщение.
    
2. **Интеграция с Redis Pub/Sub**: Используйте библиотеку `redis.asyncio` для создания глобальной шины сообщений. При старте приложения нода должна подписываться на каналы Redis, соответствующие активным комнатам [8.3 draft].
    
3. **WebSocket-эндпоинт с аутентификацией**: Создайте эндпоинт `@app.websocket("/ws/rooms/{room_id}")`. Валидация токена должна происходить **до** вызова `await websocket.accept()`, чтобы не тратить ресурсы на неавторизованные сессии [9.1 draft]. После ацепта добавьте сокет в `ConnectionManager`.
    
4. **Цикл обмена сообщениями**:
    
    - **Прием**: При получении JSON от клиента нода вызывает `redis.publish(room_id, data)`, транслируя сообщение в брокер.
    - **Трансляция**: Асинхронная фоновая задача каждой ноды слушает Redis. При появлении сообщения в канале `room_id` нода вызывает локальный метод `manager.broadcast_to_room(room_id, message)`, доставляя его всем своим клиентам [9.2 draft].
5. **Graceful Disconnect**: Оберните цикл в `try...except WebSocketDisconnect`. При разрыве связи удалите сокет из менеджера. Если в комнате на данной ноде не осталось участников, отпишитесь от канала Redis для экономии трафика [9.1 draft, 9.2 draft].
    

#### Комплексный контрольный тест для самопроверки

1. **Вопрос**: Какой метод следует вызвать, чтобы закрыть соединение WebSocket с кодом `4003` (Forbidden)?
    - _Ответ: `await websocket.close(code=4003)`. Это необходимо делать до вызова `accept()`, если пользователь не прошел проверку безопасности [9.1 draft]._
2. **Задача на дублирование**: Вы заметили, что пользователи получают свои собственные сообщения дважды. Как изменить логику `ConnectionManager`, чтобы при рассылке `broadcast` сообщение не отправлялось автору (sender)?
    - _Решение: Добавить в метод `broadcast` необязательный параметр `exclude: WebSocket` и пропускать его при итерации по списку подключений [9.2 draft]._
3. **Практическое задание**: Напишите асинхронный тест для WebSocket-эндпоинта, используя `httpx.AsyncClient` и контекстный менеджер `async with client.websocket_connect("/ws") as websocket`. Проверьте, что сервер возвращает корректный JSON-ответ [602, 604, 7.4 draft].
4. **Задача на Nginx**: При деплое SSE-эндпоинта выяснилось, что события приходят клиенту пачками (с задержкой), а не мгновенно. Какой заголовок нужно добавить в конфигурацию Nginx `location`?
    - _Решение: `proxy_set_header X-Accel-Buffering no;`, чтобы отключить буферизацию ответов прокси-сервером [731, 9.3 draft]._
5. **Вопрос на эффективность**: Почему для мобильного мессенджера с плохим 4G-соединением SSE может быть предпочтительнее WebSockets для получения уведомлений?
    - _Ответ: SSE нативно поддерживает автоматическое переподключение (reconnection) силами браузера/ОС и использует стандартный HTTP-стек, что делает его более устойчивым к разрывам связи по сравнению с WS, который требует ручной реализации Heartbeat и логики Reconnect [726, 9.3 draft]._
