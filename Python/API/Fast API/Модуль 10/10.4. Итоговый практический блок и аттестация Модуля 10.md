#### Сквозной практический кейс: Разработка и покрытие интеграционными асинхронными тестами CRUD-сервиса с документацией

**Постановка задачи:** Спроектировать и разработать модуль управления каталогом товаров (Products CRUD). Сервис должен обладать детальной документацией для фронтенд-разработки и быть полностью покрыт асинхронными тестами с использованием реальной базы данных PostgreSQL [253, 444, 10.2 draft].

**Пошаговый алгоритм выполнения:**

1. **Проектирование схем и документации:** Опишите модели `ProductCreate` и `ProductResponse` с использованием Pydantic v2. Добавьте в `ProductCreate` параметр `model_config` с `json_schema_extra`, чтобы в Swagger отображались реалистичные примеры цен и описаний товаров. Для эндпоинтов укажите `response_model` и заполните словарь `responses` для кодов 404 и 422, чтобы документация была исчерпывающей.
    
2. **Настройка тестовой инфраструктуры:** В файле `conftest.py` реализуйте фикстуру `postgres_container` с `scope="session"`, которая поднимает PostgreSQL через `PostgresContainer` [345, 10.2 draft]. Настройте асинхронный движок SQLAlchemy (`create_async_engine`) и фикстуру `db_session`, выполняющую `session.rollback()` после каждого теста для обеспечения изоляции данных [715, 10.2 draft].
    
3. **Реализация и тестирование CRUD:** Создайте тесты для всех операций каталога, используя `httpx.AsyncClient` с `ASGITransport(app=app)` [509, 10.2 draft].
    
    - **POST**: Проверьте создание товара и корректность возвращаемого JSON.
    - **GET**: Протестируйте получение списка товаров с фильтрацией и обработку 404 ошибки при запросе несуществующего ID.
    - **PATCH**: Убедитесь, что частичное обновление корректно обрабатывает `exclude_unset=True` в моделях Pydantic.
4. **Мокирование внешних систем:** Если сервис отправляет уведомления о добавлении товаров во внешнюю аналитическую систему, подмените этот сервис в тестах на `AsyncMock` через `app.dependency_overrides` [527, 576, 10.3 draft]. Проверьте, что метод отправки логов был вызван ровно один раз при успешном создании товара [310, 10.3 draft].
    
5. **Аттестация качества кода:** Запустите проверку типов командой `mypy . --strict` для верификации корректности использования `Annotated` и `AsyncSession` [82, 10.3 draft]. Проведите финальный прогон тестов с генерацией отчета о покрытии `pytest --cov=app` [80, 82, 7.4 draft]. Целевой показатель — отсутствие ошибок типов и покрытие бизнес-логики выше 90%.
    

#### Комплексный контрольный тест для самопроверки

1. **Вопрос:** Почему `mypy` может выдавать ошибку `Argument 1 has incompatible type "Depends"; expected "AsyncSession"` в коде эндпоинта, хотя FastAPI успешно выполняет инъекцию?
    
    - _Ответ: `mypy` не знает о механизмах рантайма FastAPI [10.3 draft]. Необходимо использовать синтаксис `Annotated[AsyncSession, Depends(get_db)]`, чтобы анализатор видел реальный тип переменной, возвращаемый зависимостью._
2. **Задача на кастомизацию:** Как через переопределение `app.openapi()` добавить в схему две независимые системы авторизации (например, заголовок `X-API-Key` и `Bearer JWT`)?
    
    - _Решение: Нужно извлечь `app.openapi_schema`, если она уже создана, или сгенерировать новую, затем вручную обновить словарь `components["securitySchemes"]` новыми объектами и добавить их в глобальный список `security` схемы [415, 10.1 draft]._
3. **Практическое задание:** Напишите асинхронную pytest-фикстуру `time_tracker`, которая замеряет время выполнения теста и вызывает `pytest.fail()`, если интеграционный запрос к базе данных длится дольше 500 мс.
    
4. **Задача на отладку:** Ваш тест падает с ошибкой `sqlalchemy.exc.ProgrammingError: Table 'users' already exists`. Фикстура создания таблиц имеет `scope="function"`. Как это исправить?
    
    - _Решение: Измените область видимости фикстуры создания таблиц на `scope="session"`, чтобы таблицы создавались один раз, а для очистки данных между тестами используйте откат транзакций (Rollback Strategy) в фикстуре `db_session` [10.2 draft]._
5. **Вопрос на сравнение:** В чем преимущество использования `Testcontainers` (PostgreSQL) перед мокированием репозиториев (`Mock DB`) при написании тестов для финансовых транзакций?
    
    - _Ответ: Моки могут скрывать ошибки в SQL-запросах, неправильное использование уровней изоляции транзакций или несовместимость типов данных, в то время как `Testcontainers` позволяет протестировать код в условиях, максимально приближенных к производственным [345, 10.2 draft]._
