#### Теоретический фундамент и архитектура

Стратегия интеграционного тестирования в FastAPI 2026 года направлена на проверку полной цепочки прохождения запроса: от приема HTTP-пакета до записи данных в постоянное хранилище через асинхронную ORM SQLAlchemy 2.0. В отличие от модульных тестов, здесь проверяется корректность транзакций, работа миграций и специфичные для конкретной СУБД (например, PostgreSQL) типы данных.

**Преимущества асинхронного клиента:** Использование `httpx.AsyncClient` вместо стандартного `TestClient` (базирующегося на `requests`) является обязательным для современных приложений. `AsyncClient` позволяет корректно обрабатывать конкурентные запросы внутри тестов, тестировать `WebSockets` и проверять завершение `BackgroundTasks` без блокировки цикла событий (Event Loop). Для взаимодействия с кодом приложения без поднятия реального сетевого сокета используется `ASGITransport`.

**Оркестрация тестового окружения:** Для обеспечения детерминированности и изоляции тестов применяется паттерн **Testcontainers** (`testcontainers-python`), который автоматически запускает полноценный контейнер PostgreSQL в Docker на время выполнения тестовой сессии. Это устраняет проблему «загрязнения» базы данных и расхождений между SQLite и продакшн-окружением.

**Стратегии очистки и область видимости:** Плагин `pytest-asyncio` управляет жизненным циклом асинхронных ресурсов. Оптимальная архитектура сюиты предполагает:

1. **Session Scope**: запуск контейнера и выполнение миграций Alembic один раз за сессию.
2. **Function Scope**: использование транзакционного отката (`session.rollback()`) после каждого теста для мгновенного возврата БД в исходное состояние без пересоздания таблиц.

#### Практическая реализация и синтаксис

**Настройка `conftest.py` с PostgresContainer и асинхронной сессией:**

```python
import pytest
import asyncio
from httpx import AsyncClient, ASGITransport
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker
from testcontainers.postgres import PostgresContainer
from app.main import app
from app.database import get_db

@pytest.fixture(scope="session")
def postgres_container():
    # Запуск реального Postgres в Docker для тестов
    with PostgresContainer("postgres:16-alpine") as postgres:
        yield postgres

@pytest.fixture(scope="session")
async def async_engine(postgres_container):
    # Создание асинхронного движка для контейнера
    engine = create_async_engine(postgres_container.get_connection_url().replace("postgresql", "postgresql+asyncpg"))
    yield engine
    await engine.dispose()

@pytest.fixture
async def async_client() -> AsyncClient:
    # Фикстура клиента с использованием ASGITransport
    async with AsyncClient(transport=ASGITransport(app=app), base_url="http://test") as ac:
        yield ac
```

**Примеры интеграционных тестов:**

```python
@pytest.mark.asyncio
async def test_create_user_integration(async_client: AsyncClient):
    # Тест создания ресурса (POST)
    payload = {"username": "test_user", "email": "test@example.com"}
    response = await async_client.post("/api/v1/users/", json=payload)

    assert response.status_code == 201
    assert response.json()["username"] == "test_user"

@pytest.mark.asyncio
async def test_get_user_not_found(async_client: AsyncClient):
    # Тест получения несуществующего ресурса (GET 404)
    response = await async_client.get("/api/v1/users/9999")
    assert response.status_code == 404

@pytest.mark.asyncio
async def test_validation_error(async_client: AsyncClient):
    # Проверка срабатывания Pydantic валидации (422)
    response = await async_client.post("/api/v1/users/", json={"invalid": "data"})
    assert response.status_code == 422
```

> [!warning] Актуализация синтаксиса 
> В 2026 году при использовании `pytest-asyncio` необходимо явно указывать `loop_scope` для асинхронных фикстур, чтобы избежать ошибок несоответствия области видимости `Event Loop` и самой фикстуры.

#### Глоссарий терминов

- **[`httpx.AsyncClient` & `ASGITransport`](https://fastapi.tiangolo.com/advanced/async-tests/)** — инструмент для выполнения запросов к ASGI-приложению внутри тестов без использования сетевого стека.
- **[`pytest-asyncio`](https://fastapi.tiangolo.com/tutorial/testing/)** — расширение `pytest` для поддержки корутин и асинхронного управления ресурсами.
- **[Testcontainers Pattern](https://github.com/testcontainers/testcontainers-python)** — методология использования контейнеризированных зависимостей (БД, Redis) для создания идентичных продакшну условий тестирования.
- **Session Scope vs Function Scope** — уровни видимости фикстур, определяющие частоту их инициализации (один раз на весь запуск или для каждой функции).
- **Database Migration Rollback** — стратегия поддержания чистоты БД, при которой изменения отменяются через транзакционный `rollback`, а не через пересоздание схем.
- **[Integration Test Suite](https://fastapi.tiangolo.com/tutorial/testing/)** — набор тестов, проверяющих совместную работу нескольких программных модулей и системных компонентов.

#### Практический кейс: Построение изоляционного тестового стенда в CI/CD

**Сценарий:** Настройка GitHub Actions для автоматической проверки API. Сервис использует PostgreSQL и требует 100% совместимости SQL-запросов (например, использование `JSONB` или `Window Functions`).

**Реализация:**

1. **Отказ от SQLite:** Хотя `sqlite+aiosqlite` работает быстрее, он не поддерживает специфичные для Postgres ограничения.
2. **Асинхронный запуск:** В пайплайне используется `PostgresContainer`. Благодаря асинхронности Python 3.12+, тесты I/O-операций с базой выполняются параллельно, что нивелирует задержку на запуск Docker-контейнера.
3. **Изоляция:** Каждый прогон CI создает абсолютно новый инстанс БД, исключая влияние предыдущих сборок на текущий результат.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему при тестировании через `ASGITransport` не работают тайм-ауты сетевого уровня, доступные в реальном `Uvicorn`?
    - _Ответ: `ASGITransport` вызывает приложение напрямую как функцию, минуя реальный сетевой стек и обработку сокетов на уровне ОС._
2. **Задача:** Исправьте ошибку «RuntimeError: Task attached to a different loop» при использовании асинхронной фикстуры `session` внутри теста с декоратором `@pytest.mark.asyncio`.
    - _Решение: Убедитесь, что фикстура `session` и сам тест используют один и тот же `Event Loop`, установив корректный `loop_scope`._
3. **Практическое задание:** Напишите фикстуру `seed_data`, которая зависит от `async_session` и добавляет 5 тестовых товаров в таблицу `products` перед выполнением каждого теста категории «Магазин».
