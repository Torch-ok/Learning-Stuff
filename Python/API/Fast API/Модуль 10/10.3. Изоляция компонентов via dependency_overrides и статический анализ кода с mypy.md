#### Теоретический фундамент и архитектура

В высоконагруженных системах 2026 года принцип инверсии зависимостей (**Dependency Inversion**) является критически важным для обеспечения детерминированности тестов. FastAPI предоставляет элегантный механизм `app.dependency_overrides`, который позволяет глобально подменять функции-зависимости, объявленные через `Depends`, на их имитации (Mock) или заглушки (Stub) в тестовом окружении. Это позволяет изолировать бизнес-логику от внешних I/O-систем, таких как сторонние платежные шлюзы, сервисы отправки почты или S3-хранилища, делая тесты независимыми от сетевых задержек и состояния внешних API.

Паттерн мокирования в асинхронной среде Python требует использования `unittest.mock.AsyncMock`, так как стандартные объекты `MagicMock` не являются `awaitable` и вызывают ошибки при попытке их вызова в асинхронном контексте [542, 7.2 draft]. Для простых сценариев предпочтительнее использовать **Stubs** — фейковые классы, реализующие тот же интерфейс, что и реальные сервисы, но возвращающие заранее определенные данные. Обязательным требованием безопасности является вызов метода `app.dependency_overrides.clear()` после каждого теста, чтобы предотвратить "протекание" состояния (**State Leakage**) между независимыми тестовыми сценариями [545, 7.2 draft].

Статический анализ с использованием `mypy` в 2026 году дополняет систему валидации Pydantic, проверяя корректность типов на этапе написания кода. Для работы с FastAPI необходимо подключать специализированные плагины: `pydantic.mypy` для верификации моделей и `sqlalchemy.ext.mypy.plugin` для корректной типизации полей `Mapped[...]` в SQLAlchemy 2.0.

#### Практическая реализация и синтаксис

**Пример подмены внешнего платежного сервиса в `pytest`-тесте:**

```python
from unittest.mock import AsyncMock
import pytest
from app.main import app
from app.dependencies import get_payment_service

@pytest.fixture
def mock_payment_api():
    # Создание асинхронного мока для эмуляции внешнего API
    mock = AsyncMock()
    # Настройка 500 ошибки для проверки отказоустойчивости
    mock.charge.side_effect = Exception("External Bank Error")

    # Глобальная подмена зависимости в приложении
    app.dependency_overrides[get_payment_service] = lambda: mock
    yield mock
    # Очистка контекста после выполнения теста
    app.dependency_overrides.clear()
```

**Конфигурация `pyproject.toml` для строгого анализа `mypy`:**

```toml
[tool.mypy]
python_version = "3.12"
strict = true
plugins = [
    "pydantic.mypy",
    "sqlalchemy.ext.mypy.plugin"
]

[tool.pydantic-mypy]
init_forbid_extra = true
init_typed = true
warn_required_dynamic_aliases = true [623, 7.3 draft]
```

#### Глоссарий терминов

- **[`app.dependency_overrides`](https://fastapi.tiangolo.com/advanced/testing-dependencies/)** — встроенный в FastAPI словарь для замены реальных компонентов на тестовые дублеры.
- **`AsyncMock` & Stubs** — инструменты имитации поведения объектов: моки для проверки вызовов и стабы для возврата данных в тестах.
- **State Leakage in Tests** — анти-паттерн, при котором настройки или данные из одного теста влияют на результаты другого из-за отсутствия очистки среды.
- **Static Type Checking (`mypy`)** — процесс автоматической верификации соответствия типов переменных и функций без запуска кода.
- **[`pydantic.mypy` Plugin](https://pydantic.dev/docs/validation/latest/concepts/typing/#mypy-plugin)** — расширение `mypy`, обучающее анализатор понимать специфику моделей Pydantic v2.
- **Strict Type Safety** — режим работы анализатора, запрещающий использование типа `Any` и требующий полной аннотации всех компонентов.

#### Практический кейс: Подготовка репозитория к автоматическому контролю качества в CI Pipeline

**Сценарий:** Настройка GitHub Actions пайплайна для крупного финтех-проекта на FastAPI.

**Реализация:**

1. **Статический анализ**: На шаге `lint` запускается `mypy . --strict`. Это позволяет на этапе CI отловить ошибки несоответствия типов в SQLAlchemy-моделях (например, когда поле `Mapped[int]` пытается принять `None`).
2. **Изоляция I/O**: Все тесты, работающие с отправкой SMS и Email, принудительно используют `dependency_overrides` для подмены реальных провайдеров на `AsyncMock`. Это гарантирует, что тесты не будут падать из-за исчерпания лимитов на тестовых аккаунтах внешних сервисов.
3. **Разбор ошибок**: При работе с `Annotated[AsyncSession, Depends(get_db)]` типичные ошибки `mypy` решаются путем явного указания типа в аннотации, что обеспечивает корректное автодополнение в IDE и прохождение проверок в CI.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему использование стандартного декоратора `@patch` для мокирования функций внутри эндпоинтов считается менее надежным в FastAPI, чем `app.dependency_overrides`?
    - _Ответ: `dependency_overrides` работает на уровне ядра FastAPI DI, гарантируя, что подмена произойдет даже в глубоко вложенных под-зависимостях, тогда как `@patch` может не сработать из-за особенностей импорта модулей в асинхронном рантайме._
2. **Задача:** Анализатор `mypy` выдает ошибку `Incompatible types in assignment` для поля `user.id: Mapped[int]`, когда вы присваиваете ему значение из Pydantic модели. Как правильно типизировать это взаимодействие?
3. **Практическое задание:** Напишите асинхронный контекстный менеджер `temp_override(dependency, replacement)`, который временно добавляет переопределение в `app.dependency_overrides` и гарантированно удаляет его в блоке `finally`.
