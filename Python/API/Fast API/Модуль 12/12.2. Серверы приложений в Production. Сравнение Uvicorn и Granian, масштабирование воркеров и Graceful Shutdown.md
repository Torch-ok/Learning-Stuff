#### Теоретический фундамент и архитектура

Переход от разработки к промышленной эксплуатации требует выбора производительного и стабильного ASGI-сервера. FastAPI, являясь асинхронным фреймворком на базе Starlette, требует сервер, способный эффективно управлять жизненным циклом приложения и конкурентными соединениями.

**Выбор сервера (Uvicorn vs. Granian):**

- **Uvicorn** — это стандарт де-факто в экосистеме Python. Он построен на базе `uvloop` (быстрой реализации `asyncio` на Cython) и `httptools`. В режиме `fastapi run` сервер автоматически оптимизируется под высокую производительность, отключая функции отладки и автоматическую перезагрузку.
- **Granian** (актуально для 2026 года) — сверхвысокопроизводительный сервер на базе Rust. Он обеспечивает минимальную задержку (**Latency**) и более эффективное использование ресурсов CPU по сравнению с чисто Python-решениями, поддерживая как ASGI, так и нативный интерфейс RSGI.

**Масштабирование через воркеры:** Для утилизации всех ядер процессора используется мультипроцессинговая модель. В то время как один процесс Python ограничен одним ядром из-за GIL (даже в асинхронном режиме), запуск нескольких **Workers** позволяет распределять нагрузку. Рекомендуемая формула для I/O-интенсивных приложений составляет $2 \times \text{количество ядер CPU} + 1$, что позволяет минимизировать простои во время ожидания ответов от БД или внешних API.

**Обработка сигналов и PID 1:** В контейнеризированных средах (Docker) критически важно, чтобы приложение корректно получало сигналы `SIGTERM` и `SIGINT`. Если Python-процесс запускается как **PID 1** (первый процесс в контейнере), он может игнорировать сигналы остановки, что приводит к принудительному завершению через 10 секунд (Timeout). Использование `lifespan` в FastAPI позволяет перехватывать эти сигналы и выполнять **Graceful Shutdown**: корректно закрывать соединения с базой данных (SQLAlchemy) и Redis, завершать активные фоновые задачи.

#### Практическая реализация и синтаксис

**Запуск Uvicorn в продакшн-режиме:** Для стабильной работы в Docker рекомендуется отключать `reload` и явно указывать количество воркеров.

```bash
# Запуск через FastAPI CLI (рекомендуется для 2026)
uv run fastapi run app/main.py --host 0.0.0.0 --port 8000 --workers 4

# Запуск напрямую через Uvicorn без логов доступа для снижения нагрузки
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4 --no-access-log
```

**Запуск Granian (Rust-core):**

```bash
# Интерфейс asgi, высокая плотность запросов
granian --interface asgi app.main:app --host 0.0.0.0 --port 8000 --workers 4 --backlog 2048
```

**Dockerfile с использованием `tini` для корректной передачи сигналов:** Использование легковесного инициализатора гарантирует, что `SIGTERM` дойдет до FastAPI для плавного закрытия ресурсов.

```yml
FROM python:3.12-slim
# Установка tini
RUN apt-get update && apt-get install -y tini && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY . .
# ... сборка зависимостей через uv ...
ENTRYPOINT ["/usr/bin/tini", "--"]
CMD ["fastapi", "run", "app/main.py", "--host", "0.0.0.0", "--port", "8000"]
```


> [!warning] Актуализация синтаксиса 
> Использование флага `--reload` в продакшне запрещено, так как это потребляет лишние ресурсы и может привести к непредсказуемому поведению при случайном изменении временных файлов.

#### Глоссарий терминов

- **[ASGI Application Server](https://fastapi.tiangolo.com/deployment/server-workers/)** — программный слой (Uvicorn/Granian), обеспечивающий асинхронное взаимодействие между веб-сервером и FastAPI-приложением.
- **Rust-based HTTP Server (Granian)** — высокопроизводительный сервер, написанный на Rust для минимизации накладных расходов при обработке HTTP/ASGI запросов.
- **[Multi-process Worker Model](https://fastapi.tiangolo.com/deployment/server-workers/#gunicorn-with-uvicorn-workers)** — архитектура, запускающая несколько независимых копий приложения для параллельной обработки трафика на многоядерных системах.
- **`SIGTERM` / `SIGINT` Handling** — процесс перехвата сигналов операционной системы для инициации процедуры плановой остановки сервера [8.3 draft].
- **PID 1 Problem** — особенность работы Unix-подобных систем в Docker, требующая специального обработчика (типа `tini`) для трансляции системных сигналов дочерним процессам.
- **[Graceful Shutdown Timeout](https://fastapi.tiangolo.com/advanced/events/)** — период времени, в течение которого сервер ожидает завершения обработки текущих запросов перед полным выключением.

#### Практический кейс: Настройка высоконагруженного узелка под 8-ядерный сервер

**Сценарий:** Настройка API-шлюза для обработки 10 000 RPS. Сервер имеет 8 физических ядер и 16 ГБ RAM.

**Реализация:**

1. **Выбор сервера**: Granian на Rust для снижения Memory footprint при экстремальных нагрузках.
2. **Масштабирование**: Установка `--workers 17` ($8 \times 2 + 1$).
3. **Оптимизация I/O**: Отключение `access-log`. Логирование ошибок и критических событий переведено в JSON через `structlog` (stdout), что исключает блокировку процесса на записи в файлы.
4. **Graceful Shutdown**: В `lifespan` прописано закрытие пула `AsyncSession` (SQLAlchemy). При редеплое в Kubernetes время задержки (`terminationGracePeriodSeconds`) установлено в 30 секунд, чтобы все активные WebSocket-соединения успели закрыться без ошибок на стороне клиента.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему использование `--reload` в продакшне может привести к утечке дескрипторов и падению сервера?
    - _Ответ: Механизм `reload` постоянно отслеживает файловую систему, что создает лишнюю нагрузку. Кроме того, он не гарантирует корректную остановку предыдущих воркеров при перезапуске, что может привести к зависшим соединениям с БД._
2. **Задача:** Как настроить таймаут для завершения запросов при использовании Uvicorn, чтобы сервер не закрывался мгновенно при `docker stop`?
    - _Решение: Используйте параметр `--timeout-keep-alive` или настройте параметры `lifespan` для дожидания завершения всех `BackgroundTasks` ._
3. **Практическое задание:** Составьте команду запуска Granian, которая ограничивает количество воркеров до 2, использует 4 потока Rust (threads) на каждого воркера и отключает вывод логов в консоль.
