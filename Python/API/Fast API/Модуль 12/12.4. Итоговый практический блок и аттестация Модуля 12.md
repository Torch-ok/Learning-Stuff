#### Сквозной практический кейс: Развертывание Production-Ready контура в Docker Compose

**Постановка задачи:** Спроектировать и реализовать отказоустойчивый локальный стенд на базе `docker-compose.yml`, обеспечивающий изоляцию данных, мониторинг метрик и защищенную доставку трафика [45, 96, 12.4 prompt].

**Пошаговый алгоритм выполнения:**

1. **Создание артефакта приложения:** Напишите `Dockerfile` с использованием `Multi-Stage build`. На первой стадии (`builder`) соберите зависимости с помощью `uv` или `pip`. На второй (`runtime`) используйте `python:3.12-slim`, создайте пользователя `appuser` (UID 10001) и скопируйте только необходимые файлы. Запуск приложения настройте через `ENTRYPOINT ["tini", "--"]` для корректной трансляции сигналов [61, 688, 12.1 draft, 12.2 draft].
    
2. **Настройка Reverse Proxy:** Подготовьте `nginx.conf`. Настройте `upstream` блок для связи с FastAPI через TCP или Unix-сокет. Реализуйте SSL-терминацию (TLS 1.3) и настройте `proxy_buffers` (например, `8 32k`) для обработки крупных JSON-ответов. Установите проброс WebSocket-заголовков `Upgrade` и `Connection` [12.3 draft].
    
3. **Оркестрация в Docker Compose:** Составьте `docker-compose.yml`. Выделите две сети: `frontend` (для Nginx и FastAPI) и `backend` (для FastAPI, Postgres и Redis). Добавьте секцию `healthcheck` для PostgreSQL (команда `pg_isready`) и настройте `depends_on` в FastAPI с условием `service_healthy`. Обеспечьте персистентность через `volumes` для баз данных [65, 130, 614, 12.2 draft].
    
4. **Мониторинг и Observability:** Добавьте сервис Prometheus. Настройте его на сбор данных с эндпоинта `/metrics` вашего приложения. В Nginx ограничьте доступ к `/metrics`, разрешив его только внутренним IP-адресам сети мониторинга [11.2 draft, 11.4 draft].
    
5. **Тестирование устойчивости:** Запустите контур командой `docker compose up -d`. Симулируйте аварийную остановку базы данных и убедитесь, что FastAPI корректно обрабатывает потерю соединения и восстанавливает его при перезапуске контейнера благодаря политике `restart: unless-stopped` [315, 12.2 draft].
    

#### Комплексный контрольный тест для самопроверки

1. **Вопрос:** В чем заключается основная опасность использования `depends_on` без сопутствующего `healthcheck` при запуске FastAPI-приложения с PostgreSQL?
    
    - _Ответ: `depends_on` гарантирует только запуск процесса в контейнере БД, но база может потратить несколько секунд на инициализацию файловой системы. Без Healthcheck приложение упадет с ошибкой подключения при старте [614, 12.2 draft]._
2. **Задача на отладку:** Nginx возвращает `502 Bad Gateway` при попытке подключения к Unix-сокету Uvicorn в Volume. Права на файл сокета внутри контейнера FastAPI — `600`, владелец — `appuser`. Как обеспечить доступ Nginx?
    
    - _Решение: Нужно либо запустить Nginx под тем же UID, что и FastAPI, либо настроить маску прав (umask) при создании сокета на `000`, чтобы внешние процессы могли читать и писать в него [12.3 draft]._
3. **Практическое задание:** Напишите фрагмент `docker-compose.yml` для сервиса `app`, реализующий проверку здоровья по пути `/healthz` каждые 15 секунд с таймаутом 5 секунд.
    
4. **Задача на логирование:** Сконфигурируйте в Compose-файле драйвер логирования для предотвращения переполнения диска: установите максимальный размер файла в 20 МБ и хранение не более 5 ротируемых копий.
    
5. **Вопрос на архитектуру:** Какие ключевые возможности Kubernetes (K8s) делают его более предпочтительным, чем Docker Compose, для эксплуатации высоконагруженного FastAPI-кластера с 100 000+ RPS?
    
    - _Ответ: Kubernetes предоставляет механизмы автоскейлинга (HPA), нативный Service Discovery, управление секретами и конфигурациями без перезапуска подов, а также стратегии развертывания Blue-Green и Canary._
