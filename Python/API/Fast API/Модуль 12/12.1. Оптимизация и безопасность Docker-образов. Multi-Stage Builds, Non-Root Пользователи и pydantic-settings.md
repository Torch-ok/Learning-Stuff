#### Теоретический фундамент и архитектура

В 2026 году промышленная эксплуатация FastAPI требует не только корректного кода, но и создания защищенных, минималистичных контейнеров. Безопасность начинается с выбора базового образа: использование `python:3.12-slim` обеспечивает баланс между размером и совместимостью, в то время как образы типа `alpine` могут вызывать сложности из-за использования библиотеки `musl` вместо стандартной `glibc`, что замедляет или ломает установку Python-пакетов с C-расширениями.

**Паттерн Multi-Stage Builds:** Данная архитектура позволяет разделить процесс на два этапа:

1. **Builder stage**: Установка компиляторов, сборка зависимостей через `uv` или `pip` и подготовка `wheels`.
2. **Runtime stage**: Использование максимально чистого образа, в который из первой стадии копируются только установленные пакеты и код приложения. Это исключает наличие инструментов сборки (gcc, git) в финальном образе, уменьшая его размер и вектор атак.

**Концепция Least Privilege (Минимальные привилегии):** Запуск приложения под пользователем `root` внутри контейнера является критической уязвимостью, так как любой взлом приложения может дать злоумышленнику доступ к хост-системе. Правильная практика — создание выделенного системного пользователя и группы, а также явная настройка прав доступа (`CHOWN`) к рабочей директории.

**Конфигурирование через `pydantic-settings`:** Библиотека `pydantic-settings` (класс `BaseSettings`) является современным стандартом для управления конфигурацией. Она централизует настройки, автоматически валидирует типы данных из переменных окружения и `.env` файлов, а также использует тип `SecretStr` для предотвращения утечки паролей в логи.

**Стратегия кэширования слоев:** Для ускорения сборки в CI/CD конвейерах инструкции `COPY` должны располагаться от самых редко изменяемых к самым частым: сначала копируются файлы зависимостей (`pyproject.toml`, `requirements.txt`), выполняется их установка, и только затем копируется исходный код.

#### Практическая реализация и синтаксис

**Оптимизированный Dockerfile (Multi-Stage):**

```yml
# Stage 1: Build dependencies
FROM python:3.12-slim AS builder
WORKDIR /app
COPY requirements.txt .
# Установка зависимостей в локальную директорию
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt

# Stage 2: Final runtime image
FROM python:3.12-slim
WORKDIR /app
# Создание non-root пользователя для безопасности
RUN groupadd -r appgroup && useradd -r -g appgroup appuser
# Копирование только установленных пакетов из стадии builder
COPY --from=builder /install /usr/local
COPY . .
# Настройка прав собственности
RUN chown -R appuser:appgroup /app
USER appuser
# Запуск сервера без --reload для продакшна
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Настройка `pydantic-settings` (`config.py`):**

```python
from pydantic import SecretStr, PostgresDsn, RedisDsn
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    # Автоматическая валидация URL баз данных
    DATABASE_URL: PostgresDsn
    REDIS_URL: RedisDsn
    SECRET_KEY: SecretStr # Маскирование в логах
    ENVIRONMENT: str = "production"
    DEBUG: bool = False

    model_config = SettingsConfigDict(
        env_file=".env", # Загрузка из файла
        env_file_encoding="utf-16"
    )

settings = Settings() # Экземпляр настроек
```

**Файл `.dockerignore`:**

```

node_modules
*.log
```

#### Глоссарий терминов

- **[Multi-Stage Docker Build](https://docs.docker.com/build/building/multi-stage/)** — метод сборки образа, разделяющий окружение для компиляции и финального исполнения для оптимизации ресурсов.
- **Minimal Runtime Base Images** — использование облегченных дистрибутивов (`slim`), содержащих только необходимые библиотеки для работы Python.
- **[Principle of Least Privilege](https://fastapi.tiangolo.com/deployment/docker/#non-root-user)** — стандарт безопасности, требующий запуска процессов с минимально необходимым уровнем прав (non-root).
- **Layer Caching Strategy** — оптимизация порядка команд в Dockerfile для переиспользования ранее собранных слоев и ускорения CI/CD.
- **[`pydantic-settings` (`BaseSettings`)](https://docs.pydantic.dev/latest/usage/settings/)** — инструмент для типизированного управления конфигурацией приложения через переменные окружения.
- **Docker Attack Surface Reduction** — практика удаления лишних бинарных файлов и утилит из образа для снижения вероятности успешной атаки.

#### Практический кейс: Проектирование production-ready Dockerfile

**Сценарий:** Крупный банковский сервис на FastAPI поставлялся в виде образа размером 1.4 GB, содержащего `gcc`, `make` и работающего под `root`. Необходимо провести аудит и оптимизацию.

**Реализация:**

1. **Сжатие**: Применение `Multi-Stage build` позволило оставить компиляторы `asyncpg` на первой стадии сборки. Вес образа снизился до 128 MB.
2. **Безопасность**: Добавлен пользователь `appuser` с UID 10001. При попытке записи логов напрямую в `/app/` приложение упало с `PermissionError`, что выявило отсутствие настройки томов (Volumes) для персистентности данных.
3. **Конфигурация**: Переход на `BaseSettings` позволил автоматически отклонять запуск контейнера, если в Docker Secrets не был проброшен `DB_PASSWORD` (Fail-Fast принцип).

#### Вопросы и задания для самопроверки

1. **Вопрос:** Почему наличие C-компиляторов и менеджеров пакетов в финальном образе считается угрозой безопасности?
    - _Ответ: Если злоумышленник получит доступ к выполнению кода (RCE), наличие компиляторов позволит ему на месте собрать вредоносное ПО, эксплойты для повышения привилегий или криптомайнеры._
2. **Задача:** При запуске контейнера под non-root пользователем FastAPI выдает ошибку `[Errno 13] Permission denied: '/app/logs/api.log'`. Как это исправить в Dockerfile?
    - _Решение: Необходимо до переключения на пользователя (`USER appuser`) выполнить команду `RUN mkdir -p /app/logs && chown -R appuser:appgroup /app/logs`._
3. **Практическое задание:** Реализуйте в классе `Settings` логику считывания настроек, где приоритет системных переменных окружения выше, чем значений из `.env` файла.
    - _Ответ: Это поведение в `pydantic-settings` настроено по умолчанию. Системные переменные (`export DB_URL=...`) всегда имеют приоритет над файлом `.env`._
