#### Теоретический фундамент и архитектура

В основе архитектуры FastAPI лежит паттерн **Dependency Injection** (инъекция зависимостей), который является частным случаем принципа **Inversion of Control** (IoC),. В контексте веб-фреймворка этот подход означает, что эндпоинт не занимается созданием необходимых ему объектов (например, сессии базы данных или сервиса авторизации) самостоятельно, а декларирует потребность в них через аргументы функции,. FastAPI берет на себя управление жизненным циклом этих объектов: их создание, передачу в функцию и последующую очистку ресурсов,.

Механизм `fastapi.Depends` анализирует сигнатуру функции-обработчика и строит **Dependency Graph** (граф зависимостей),. Перед вызовом эндпоинта фреймворк разрешает все узлы этого графа, начиная с самых низкоуровневых. Современным стандартом разработки в 2026 году является использование синтаксиса `typing.Annotated`, который позволяет создавать переиспользуемые псевдонимы (aliases) для зависимостей, отделяя бизнес-логику от технических деталей реализации,,.

Зависимости в FastAPI могут быть древовидными и содержать **Sub-dependencies** (вложенные зависимости). Например, зависимость для получения текущего пользователя может, в свою очередь, зависеть от схемы OAuth2 и сессии базы данных,. Важной особенностью является механизм кэширования: по умолчанию параметр `use_cache=True` гарантирует, что если одна и та же зависимость встречается несколько раз в рамках одного графа для одного HTTP-запроса, она будет выполнена только один раз, а её результат будет переиспользован,. Это критически важно для производительности, чтобы избежать дублирующих запросов к БД или повторной валидации токенов,.

#### Практическая реализация и синтаксис

Современный подход предполагает создание цепочек зависимостей, обеспечивающих строгую типизацию и безопасность.

**Пример многоуровневого графа зависимостей:**

```python
from typing import Annotated
from fastapi import Depends, HTTPException, status
from sqlalchemy.ext.asyncio import AsyncSession
# Импорт локальных компонентов
from .database import get_db
from .models import User

# 1. Базовая зависимость сессии БД
DatabaseDep = Annotated[AsyncSession, Depends(get_db)]

# 2. Зависимость для получения текущего пользователя (Sub-dependency)
async def get_current_user(db: DatabaseDep, token: str = Depends(oauth2_scheme)) -> User:
    user = await db.get(User, parse_token(token))
    if not user:
        raise HTTPException(status_code=401, detail="Invalid token")
    return user

CurrentUser = Annotated[User, Depends(get_current_user)]

# 3. Зависимость для проверки прав администратора
async def get_active_admin(current_user: CurrentUser) -> User:
    if not current_user.is_admin or not current_user.is_active:
        raise HTTPException(status_code=403, detail="Admin privileges required")
    return current_user

AdminUser = Annotated[User, Depends(get_active_admin)]

@app.get("/admin/stats")
async def read_stats(admin: AdminUser):
    return {"status": "success", "user": admin.username}
```

[Get Current User](https://fastapi.tiangolo.com/tutorial/security/get-current-user/), [SQL Databases](https://fastapi.tiangolo.com/tutorial/sql-databases/)

Использование `use_cache=False` необходимо в специфических сценариях. Например, если зависимость `get_request_id` генерирует новый UUID, и вам нужно гарантировать уникальность идентификатора даже если эта зависимость вызывается в разных частях одного запроса.

> [!warning] Актуализация синтаксиса 
> До версии FastAPI 0.95.0 зависимости объявлялись как значения по умолчанию: `db: Session = Depends(get_db)`. В актуальных стандартах 2026 года следует использовать `Annotated`, чтобы сохранить чистоту типов Python и корректную поддержку IDE,.

#### Глоссарий терминов

- **[Dependency Injection (DI)](https://fastapi.tiangolo.com/tutorial/dependencies/)** — паттерн проектирования, при котором зависимости передаются объекту извне, а не создаются им внутри.
- **Inversion of Control (IoC)** — принцип архитектуры, при котором управление потоком выполнения передается фреймворку,.
- **[`fastapi.Depends`](https://fastapi.tiangolo.com/tutorial/dependencies/)** — встроенный инструмент FastAPI для объявления и разрешения зависимостей.
- **Dependency Graph (Граф зависимостей)** — иерархическая структура связей между функциями-зависимостями, которую FastAPI выстраивает для их выполнения,.
- **`use_cache` Parameter** — настройка `Depends`, позволяющая отключить сохранение результата выполнения зависимости для текущего запроса.
- **[Sub-dependency (Вложенная зависимость)](https://fastapi.tiangolo.com/tutorial/dependencies/sub-dependencies/)** — функция зависимости, которая сама запрашивает другие зависимости через `Depends`.

#### Практический кейс: Построение многоуровневого графа авторизации и прав доступа

**Сценарий:** Разработка системы доступа к финансовым документам. Доступ разрешен только активным пользователям с ролью `Accountant` или `Owner`, при этом информация о пользователе должна подгружаться из PostgreSQL один раз за запрос,.

**Реализация:**

1. **Парсинг:** Зависимость `oauth2_scheme` извлекает Bearer-токен из заголовка `Authorization`.
2. **Валидация JWT:** Вложенная зависимость `get_current_user` декодирует токен и проверяет его срок действия.
3. **Поиск в БД:** Тот же `get_current_user` использует `DatabaseDep` для выполнения `SELECT` запроса к таблице `users`. Благодаря `use_cache=True` (по умолчанию), если эндпоинт запрашивает пользователя, а следом его запрашивает middleware или другая зависимость, запрос к БД выполнится лишь единожды,.
4. **Проверка ролей:** Зависимость `check_accountant_role` принимает результат `get_current_user` и выбрасывает **403 Forbidden**, если роль не соответствует требованиям.

**Результат:** Чистая и масштабируемая система прав доступа, где каждый эндпоинт защищен одной строкой `user: AccountantDep`, а вся сложная логика инкапсулирована в графе зависимостей,.

#### Вопросы и задания для самопроверки

1. **Вопрос:** Если в эндпоинте объявлены две зависимости, которые обе зависят от `get_db`, сколько раз будет вызвана функция `get_db` при обработке одного запроса, если `use_cache=True`?
    - _Ответ: Один раз. FastAPI закэширует результат первого вызова и передаст его во все последующие узлы графа в рамках этого запроса._
2. **Задача:** Определите порядок выполнения: `A -> [B, C]`, где `B -> D`. В какой последовательности FastAPI запустит функции-зависимости?
3. **Практическое задание:** Проведите рефакторинг API. Создайте `Annotated`-тип `SessionDep`, который включает в себя `AsyncSession` и зависимость `get_db`, и замените им прямые вызовы `Depends` во всех эндпоинтах вашего сервиса.
