#### Сводный академический глоссарий Модуля 4

- **Dependency Injection (DI)** — паттерн проектирования, при котором вызываемый код (эндпоинт) получает необходимые ему объекты (зависимости) извне, что обеспечивает гибкость и упрощает тестирование,,.
- **Inversion of Control (IoC)** — архитектурный принцип, передающий управление жизненным циклом объектов (создание, очистка) фреймворку FastAPI вместо ручного инстанцирования в бизнес-логике,.
- **fastapi.Depends** — встроенный инструмент для декларативного объявления зависимостей, позволяющий FastAPI автоматически разрешать их перед выполнением функции,,.
- **use_cache** — параметр `Depends`, который по умолчанию (`True`) гарантирует выполнение зависимости только один раз в рамках одного HTTP-запроса, переиспользуя результат в под-зависимостях,.
- **typing.Annotated** — стандартный механизм Python для добавления метаданных (включая `Depends`) к типам данных, ставший эталоном для объявления зависимостей в FastAPI,,.
- **Class-based Dependencies** — использование классов или их экземпляров в роли зависимостей, что позволяет группировать параметры запроса и реализовывать сложную логику через метод `__call__`,.
- **Dependency Factories** — паттерн создания динамически настраиваемых зависимостей через функции или параметризованные классы,.
- **Async Generator Dependencies (yield)** — зависимости, использующие `async def` с оператором `yield` для разделения фазы подготовки ресурса и фазы его обязательной очистки,,,.
- **Resource Management & try...finally** — использование защитных блоков внутри зависимостей с `yield` для предотвращения утечек памяти и соединений с базой данных,,.

#### Сквозной практический кейс: Модульная система авторизации и доступа к БД через DI

**Постановка задачи:** Спроектировать слой `Dependency Injection` для сервиса документов. Необходимо реализовать цепочку: создание асинхронной сессии БД -> валидация JWT-токена -> извлечение профиля пользователя -> проверка прав на редактирование конкретного документа,.

**Пошаговый алгоритм выполнения:**

1. **Генератор асинхронной сессии:** Реализуйте функцию-генератор, которая предоставляет `AsyncSession`,. Для обеспечения надежности оберните `yield` в блок `try...finally`, чтобы гарантировать закрытие сессии даже при возникновении `HTTPException` в ээндпоинте,,.
    
    ```python
    async def get_db() -> AsyncGenerator[AsyncSession, None]:
        async with async_session_local() as session:
            try:
                yield session
            finally:
                await session.close()
    ```
    
2. **Класс-фабрика RBAC:** Создайте параметризованный класс `AccessChecker(roles: list[str])`, реализующий метод `__call__`. Он будет выступать зависимостью, которая проверяет наличие необходимых ролей у пользователя.
    
3. **Annotated-алиасы типов:** Оформите технические типы для повышения читаемости,.
    
    ```python
    SessionDep = Annotated[AsyncSession, Depends(get_db)]
    CurrentUser = Annotated[User, Depends(get_current_user)]
    ```
    
4. **Сборка эндпоинта:** Используйте созданные алиасы в `APIRouter`. Благодаря `use_cache=True`, сессия БД и профиль пользователя будут извлечены только один раз, даже если они требуются в нескольких под-зависимостях одного маршрута,,.
    
    ```python
    @router.patch("/{doc_id}")
    async def edit_document(
        doc_id: int,
        db: SessionDep,
        user: CurrentUser,
        can_edit: Annotated[bool, Depends(AccessChecker(roles=["editor", "admin"]))]
    ):
        # Бизнес-логика редактирования
        pass
    ```
    
5. **Тестирование через Overrides:** Для изолированного тестирования используйте атрибут `app.dependency_overrides`,. Подмените `get_db` на функцию, возвращающую мок-сессию или тестовую базу в `Pytеst` фикстуре,.
    

#### Комплексный контрольный тест для самопроверки

1. **Вопрос:** В какой ситуации результат выполнения функции с `Depends` будет пересчитан повторно в рамках одного и того же HTTP-запроса?
    - _Ответ: Если при объявлении зависимости был явно указан параметр `use_cache=False`._
2. **Задача:** Исправьте архитектурную проблему: зависимость `get_file` открывает файловый дескриптор, но при ошибке в эндпоинте (например, 404) дескриптор остается открытым. Как обеспечить его закрытие?
    - _Решение: Переписать зависимость на использование `yield` внутри блока `try...finally`._
3. **Практическое задание:** Напишите класс `PaginationParams`, который принимает `skip` и `limit` как `Query`-параметры. Объявите его в эндпоинте с использованием `Annotated` так, чтобы FastAPI автоматически инстанцировал объект класса,.
4. **Задача на тестирование:** Напишите код для `conftest.py`, который подменяет глобальную зависимость `get_settings` на объект `TestSettings` для всего приложения `app` через `dependency_overrides`,.
5. **Вопрос:** В каком порядке FastAPI выполняет зависимости, если они объявлены одновременно: в `FastAPI(dependencies=...)`, в `APIRouter(dependencies=...)` и в декораторе `@router.get(dependencies=...)`?
    - _Ответ: Зависимости выполняются в иерархическом порядке: сначала глобальные (уровня приложения), затем уровня роутера, и в конце — уровня конкретного эндпоинта._
