#### Теоретический фундамент и архитектура

Система внедрения зависимостей (Dependency Injection) в FastAPI не ограничивается использованием только функций. Любой вызываемый объект (**Callable**) в Python может выступать в роли зависимости. Это включает в себя не только стандартные функции, объявленные через `def` или `async def`, но и классы, а также экземпляры классов, реализующие магический метод `__call__`.

**Использование классов как зависимостей:** Когда вы передаете класс в `Depends(ClassName)`, FastAPI автоматически создает экземпляр этого класса, анализируя параметры его конструктора (`__init__`) как параметры запроса. Это позволяет эффективно группировать связанные параметры (например, пагинацию или фильтрацию) в единую структуру, обеспечивая лучшую поддержку IDE и автодополнение кода.

**Сокращенный синтаксис Depends():** В современных стандартах 2026 года для улучшения читаемости используется синтаксис `typing.Annotated`. Если тип зависимости уже указан в аннотации, в вызове `Depends()` можно не дублировать имя класса — FastAPI разрешит его автоматически на основе типа данных.

**Фабрики зависимостей (Dependency Factories):** Иногда логика зависимости должна меняться в зависимости от внешних параметров (например, проверка разных уровней доступа для разных эндпоинтов). Для этого применяются функции высшего порядка или параметризуемые классы, которые возвращают готовый к использованию **Callable** объект.

**Состояние и Синглтоны:** Использование классов-зависимостей является основным способом управления состоянием приложения и внедрения тяжелых объектов, таких как клиенты сторонних API или настройки конфигурации (`pydantic-settings`). Внедряя один и тот же экземпляр класса через зависимости, вы реализуете паттерн «Синглтон», обеспечивая централизованное управление ресурсами и исключая их избыточное создание.

#### Практическая реализация и синтаксис

**Класс-зависимость для параметров каталога:** Этот подход агрегирует несколько параметров запроса в один объект.

```python
from typing import Annotated
from fastapi import Depends, Query

class CommonQueryParams:
    def __init__(
        self,
        page: Annotated[int, Query(ge=1)] = 1,
        limit: Annotated[int, Query(le=100)] = 10,
        search: Annotated[str | None, Query()] = None
    ):
        self.page = page
        self.limit = limit
        self.search = search

# Использование в эндпоинте через сокращенный синтаксис
@app.get("/items/")
async def read_items(params: Annotated[CommonQueryParams, Depends()]):
    return {"page": params.page, "search_term": params.search}
```

**Фабрика зависимостей для проверки ролей (RBAC):** Создание динамической проверки прав доступа.

```python
from fastapi import HTTPException, status

class RoleChecker:
    def __init__(self, allowed_roles: list[str]):
        self.allowed_roles = allowed_roles

    def __call__(self, current_user: CurrentUser):
        if current_user.role not in self.allowed_roles:
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail="Operation not permitted"
            )
        return True

# Применение фабрики к разным ресурсам
allow_admin = RoleChecker(allowed_roles=["admin"])
allow_manager = RoleChecker(allowed_roles=["admin", "manager"])

@app.delete("/system-reset", dependencies=[Depends(allow_admin)])
async def reset_system():
    return {"status": "reset_complete"}
```

**Инъекция глобальных настроек (Singleton Pattern):** Использование `pydantic-settings` для внедрения конфигурации.

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    api_key: str
    redis_url: str

    model_config = ConfigDict(env_file=".env")

# Создаем синглтон вне зависимостей
settings = Settings()

def get_settings():
    return settings

SettingsDep = Annotated[Settings, Depends(get_settings)]
```

#### Глоссарий терминов

- **[Callable Dependency](https://fastapi.tiangolo.com/tutorial/dependencies/)** — любая сущность (функция или класс), которую FastAPI может вызвать для разрешения зависимости.
- **[Dependency Factory (Фабрика зависимостей)](https://fastapi.tiangolo.com/tutorial/query-param-models/)** — механизм создания параметризованных зависимостей для реализации динамической логики.
- **[Class-based Dependency](https://fastapi.tiangolo.com/tutorial/dependencies/classes-as-dependencies/)** — использование класса в качестве зависимости для автоматической инициализации параметров запроса в объект.
- **Parameterized Dependency** — зависимость, поведение которой настраивается в момент объявления в эндпоинте.
- **Singleton Pattern в DI** — стратегия внедрения, при которой во все части приложения передается один и тот же заранее созданный экземпляр сервиса или настроек.

#### Практический кейс: Проектирование гибкой системы фильтрации каталога и RBAC

**Сценарий:** Необходимо создать защищенный API каталога товаров. Администраторы могут видеть все товары (включая скрытые), а менеджеры — только активные. При этом оба типа пользователей используют одинаковую сложную систему фильтрации (по цене, бренду и дате).

**Реализация:**

1. **Агрегация фильтров:** Создается класс `ProductFilter`, который через `Annotated` описывает 10+ параметров `Query`. Это избавляет от необходимости прописывать их в каждом эндпоинте, предотвращая дублирование кода.
2. **Защита через фабрику:** Используется `RoleChecker` для ограничения доступа. Фабрика внедряется на уровне `APIRouter` для группы административных эндпоинтов.
3. **Результат:** Сложные эндпоинты сокращаются до нескольких строк, так как вся техническая работа по валидации параметров и проверке прав вынесена в вызываемые объекты и классы-зависимости.

#### Вопросы и задания для самопроверки

1. **Вопрос:** В чем разница в поведении FastAPI при использовании `Depends(MyClass)` и `Depends(MyClass())`?
    - _Ответ: В первом случае FastAPI создает новый экземпляр класса для каждого запроса (если не включено кэширование). Во втором случае используется уже существующий экземпляр, что полезно для внедрения синглтонов._
2. **Задача:** Напишите фабрику зависимостей `RateLimiter(requests_per_minute: int)`, которая проверяет количество запросов пользователя и выбрасывает ошибку 429 при превышении лимита.
3. **Практическое задание:** Создайте класс-сервис `AnalyticsService`, который принимает `db: SessionDep` и `current_user: CurrentUser`, и объедините в нем методы для записи логов действий пользователя во всех эндпоинтах модуля отчетности.
