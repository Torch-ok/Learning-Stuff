#### Теоретический фундамент и архитектура

Передача данных в FastAPI осуществляется через тело запроса (`Request Body`), которое автоматически сопоставляется со схемами Pydantic для валидации и типизации. Когда эндпоинт принимает несколько Pydantic-моделей одновременно, FastAPI ожидает JSON-объект, где именами ключей верхнего уровня выступают названия параметров функции. В случаях, когда необходимо обернуть даже одиночную модель в именованный ключ JSON, используется параметр `Body(embed=True)`, что делает структуру запроса более предсказуемой для фронтенд-разработки.

Для обработки данных в форматах `application/x-www-form-urlencoded` и `multipart/form-data` FastAPI требует установки внешней библиотеки `python-multipart`. Важно учитывать, что согласно протоколу HTTP, в одном запросе нельзя одновременно использовать `application/json` и кодировку форм; попытка объявить `Body` (JSON) и `Form` в одном эндпоинте приведет к ошибке.

Загрузка файлов в FastAPI реализована двумя способами:

- **Передача через `bytes`:** Содержимое файла полностью считывается в оперативную память сервера. Это допустимо только для очень маленьких файлов, так как при больших объемах возникает критический риск переполнения памяти (OOM).
- **Использование `UploadFile`:** Этот класс использует «прокручиваемый» временный файл (`SpooledTemporaryFile`), который хранится в памяти до определенного лимита, а затем автоматически сбрасывается на диск. `UploadFile` предоставляет метаданные, такие как `filename` и `content_type`, а также асинхронный интерфейс для неблокирующего чтения и записи.

#### Практическая реализация и синтаксис

Современный стандарт разработки требует использования `Annotated` для всех типов входных данных.

**Пример сложного эндпоинта с множественными параметрами:**

```python
from typing import Annotated
from fastapi import APIRouter, Body, Path, Query
from pydantic import BaseModel

router = APIRouter()

class Item(BaseModel):
    name: str
    price: float

@router.put("/items/{item_id}")
async def update_item(
    item_id: Annotated[int, Path(title="ID товара", ge=1)],
    item: Item, # Автоматически извлекается из Body
    user: Annotated[str, Body(embed=True)], # Ожидает JSON {"user": "name"}
    q: Annotated[str | None, Query()] = None
):
    return {"item_id": item_id, "item": item, "user": user, "q": q}
```

**Пример обработки формы логина:**

```python
from fastapi import Form

@router.post("/login/")
async def login(
    username: Annotated[str, Form()],
    password: Annotated[str, Form()]
):
    return {"username": username}
```

**Асинхронная загрузка файла с сохранением по чанкам:**

```python
import shutil
from fastapi import File, UploadFile, HTTPException

@router.post("/upload-avatar/")
async def upload_avatar(file: Annotated[UploadFile, File()]):
    # Валидация MIME-типа
    if not file.content_type.startswith("image/"):
        raise HTTPException(status_code=400, detail="Only images allowed")

    file_path = f"media/{file.filename}"
    with open(file_path, "wb") as buffer:
        # Чтение по чанкам для экономии RAM
        while content := await file.read(1024 * 1024): # 1MB chunk
            buffer.write(content)

    return {"filename": file.filename, "path": file_path}
```

#### Глоссарий терминов

- **Request Body (`Body`)** — данные, передаваемые клиентом в теле HTTP-запроса, обычно в формате JSON.
- **Embedded Body (`Body(embed=True)`)** — инструкция FastAPI ожидать JSON-ключ с именем параметра даже для одиночной модели.
- **Multipart Form Data** — тип кодировки тела запроса, позволяющий передавать файлы и поля форм одновременно.
- **UploadFile** — высокоуровневый класс FastAPI для работы с загруженными файлами через асинхронный интерфейс.
- **SpooledTemporaryFile** — механизм Python для хранения временных данных в памяти с автоматическим переключением на диск при превышении лимита размера.
- **Chunked File Reading** — метод обработки файлов частями (чанками) для предотвращения чрезмерного потребления оперативной памяти.

#### Практический кейс: Разработка высоконагруженного сервиса загрузки медиаконтента

**Сценарий:** Необходимо создать микросервис для приема пользовательских документов. Система должна быть защищена от загрузки вредоносных скриптов вместо документов и от переполнения дискового пространства.

**Реализация:**

1. **Валидация:** Используется атрибут `file.content_type` для проверки соответствия формата (например, `application/pdf`).
2. **Ограничение размера:** Хотя `UploadFile` экономит RAM, размер файла проверяется перед сохранением через метод `file.seek(0, 2)` для получения позиции курсора в конце файла (размера).
3. **Потоковая запись:** Файл сохраняется на диск с помощью `await file.read(CHUNK_SIZE)`. Это гарантирует, что даже при загрузке 2 ГБ видео, сервер будет использовать лишь несколько мегабайт RAM.
4. **Очистка ресурсов:** В блоке `finally` обязательно вызывается `await file.close()`, чтобы удалить временные файлы `SpooledTemporaryFile` и освободить системные дескрипторы.

#### Вопросы и задания для самопроверки

1. **Вопрос:** В каком случае загрузка файла через `bytes` может привести к аварийной остановке сервера?
    - _Ответ: При загрузке файлов, чей размер превышает доступную свободную оперативную память сервера, так как `bytes` читает весь файл в RAM целиком._
2. **Задача:** Исправьте ошибку в коде эндпоинта.
    
    ```python
    @app.post("/register")
    async def register(user: UserSchema, avatar: Annotated[UploadFile, File()]):
        pass
    ```
    
    _Подсказка: Вы не можете смешивать `UserSchema` (JSON) и `File` (Multipart) в одном запросе. Используйте `Form` для полей пользователя или отправляйте метаданные JSON отдельным запросом._
3. **Практическое задание:** Напишите эндпоинт `POST /multiple-uploads/`, принимающий список файлов `list[UploadFile]`. Реализуйте цикл, который суммирует размеры всех файлов и возвращает ошибку 413, если общий объем превышает 50 МБ.
