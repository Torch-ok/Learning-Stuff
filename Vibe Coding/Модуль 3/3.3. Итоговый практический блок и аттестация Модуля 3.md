#### Сквозной практический кейс: Проектирование памяти ИИ-архитектора для поиска зависимостей в монорепозитории

**Постановка задачи:** Создание `RAG`-пайплайна для монорепозитория на `TypeScript` (50 000 строк кода), предназначенного для автоматической генерации интеграционных тестов. Система должна понимать связи между компонентами, чтобы генерировать тесты, покрывающие реальные цепочки вызовов [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

**Пошаговый алгоритм решения:**

1. **Выбор стратегии чанкинга:** Вместо простого деления по количеству символов используется `Semantic Chunking`. Применяется логика извлечения функций и классов целиком, опираясь на синтаксическое дерево. Это необходимо, чтобы каждый чанк содержал законченную логическую единицу кода, а `Overlap` в 10-15% гарантирует сохранение контекста импортов и внешних вызовов [Vector embeddings | OpenAI API](https://developers.openai.com/api/docs/guides/embeddings), [RAG Best Practices](https://www.youtube.com/watch?v=...).
2. **Настройка векторного хранилища:** Используется `Supabase` с расширением `pgvector` [Build a User Management App with Next.js | Supabase Docs](https://supabase.com/docs/guides/getting-started/tutorials/with-nextjs). Для каждого фрагмента кода генерируется эмбеддинг размерностью 1536 (модель `text-embedding-3-small`) [Vector embeddings | OpenAI API](https://developers.openai.com/api/docs/guides/embeddings). В метаданные сохраняются путь к файлу (`file_path`) и список зависимостей, определенных агентом на этапе индексации [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
3. **Проектирование алгоритма поиска:** При запросе "Напиши тест для API оплаты" система переводит запрос в вектор. Выполняется поиск `Top-K` (K=5) наиболее похожих фрагментов кода через `Cosine Similarity`. Алгоритм дополнительно фильтрует результаты по метаданным, исключая устаревшие ветки (`branches`) [Qdrant Overview](https://qdrant.tech/documentation/overview/), [Vector embeddings | OpenAI API](https://developers.openai.com/api/docs/guides/embeddings).
4. **Формирование финального промпта:** Найденные фрагменты кода внедряются в `System Prompt` как `Static Context`. Промпт требует от модели выполнить роль `QA Engineer` и написать тесты, используя только предоставленные примеры существующих `API`. Для повышения безопасности используется схема `Generator-Verifier`, где вторая модель проверяет сгенерированные тесты на наличие галлюцинированных зависимостей [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering), [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

Обоснуйте ответ, исходя из затрат на переобучение и необходимости актуальности данных [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering), [RAG Best Practices](https://www.youtube.com/watch?v=...).
