
#### Теоретический фундамент и архитектура

- **Назначение и экономика `RAG`:**
    
    - Технология `Retrieval-Augmented Generation (RAG)` предназначена для расширения возможностей `LLM` путем предоставления ей доступа к частным данным, таким как проприетарная документация или закрытая кодовая база проекта, без необходимости проведения дорогостоящего процесса дообучения (`Fine-Tuning`). `RAG` позволяет модели выдавать более точные и контекстуальные ответы, опираясь на актуальное состояние репозитория.
    - **Сравнение эффективности:** Использование гигантских `Context Window` (до 1М токенов) эффективно, но ведет к резкому росту стоимости из-за высокой цены токенов и деградации внимания при заполнении окна. `Fine-Tuning` требует колоссальных вычислительных ресурсов и подготовки качественных датасетов. `RAG` является золотой серединой: он дешевле в эксплуатации, так как в промпт подмешиваются только релевантные куски данных, и позволяет работать с базами знаний, которые физически не помещаются в оперативную память модели.
- **4-этапный пайплайн работы `RAG` в вайбкодинге:**
    
    1. **Chunking:** Файлы проекта разбиваются на малые смысловые фрагменты (`Chunks`). Для кода эффективна стратегия экстракции функций или классов, чтобы сохранить логическую целостность. Использование перекрытия (`Overlap`) позволяет сохранить контекст между соседними фрагментами.
    2. **Embeddings Generation:** Каждый фрагмент пропускается через модель эмбеддингов (например, `text-embedding-3-small`), превращаясь в `Dense Vector` — массив чисел, кодирующий семантический смысл кода или текста.
    3. **Vector Stores:** Полученные векторы сохраняются в специализированные базы данных, такие как `Qdrant` или расширение `pgvector` для `PostgreSQL` (используемое в `Supabase`). Здесь векторы индексируются для быстрого поиска.
    4. **Retrieval & Context Injection:** При запросе пользователя ("Как работает авторизация?") система превращает запрос в вектор, находит в базе `Top-K` наиболее близких фрагментов по `Cosine Similarity` и динамически вставляет их в системный промпт (`System Prompt`).

#### Практическая реализация и синтаксис

**Пример Python-кода для чанкинга с использованием `tiktoken`:**

```python
import tiktoken

def semantic_chunking(text, chunk_size=500, overlap=50):
    encoding = tiktoken.get_encoding("cl100k_base")
    tokens = encoding.encode(text)

    chunks = []
    for i in range(0, len(tokens), chunk_size - overlap):
        chunk_tokens = tokens[i : i + chunk_size]
        chunks.append(encoding.decode(chunk_tokens))
    return chunks

# Пример для файла документации
docs_chunks = semantic_chunking("Full project documentation text...", chunk_size=300, overlap=30)
```

.

**Пример SQL-запроса для поиска векторов в `PostgreSQL` (`pgvector`):**

```sql
-- Поиск 5 самых похожих фрагментов кода по косинусному сходству
SELECT content, metadata, 1 - (embedding <=> '[0.123, -0.567, ...]') AS similarity
FROM project_chunks
WHERE 1 - (embedding <=> '[0.123, -0.567, ...]') > 0.8
ORDER BY embedding <=> '[0.123, -0.567, ...]'
LIMIT 5;
```

#### Глоссарий терминов

- **Retrieval-Augmented Generation (`RAG`)** — методика улучшения ответов ИИ за счет предварительного поиска релевантной информации во внешней базе знаний.
- **Text Chunking & Overlap Strategy** — процесс деления длинного текста на части с частичным накладыванием их друг на друга для предотвращения потери смысла на границах.
- **Vector Database (`pgvector` / `Qdrant`)** — хранилище, оптимизированное для поиска данных на основе математической близости их векторных представлений.
- **Dynamic Context Injection** — автоматическая вставка найденных поисковой системой фрагментов данных в тело запроса к `LLM` для генерации обоснованного ответа.

#### Практический кейс: Подключение базы знаний к ИИ-ассистенту

**Задача:** Создать `RAG`-ассистента для проекта на `TypeScript`, который сможет объяснять архитектуру и указывать точные файлы.

**Реализация:**

1. **Extraction:** Скрипт обходит папку `/src` и извлекает все функции и `Interface` определения как отдельные чанки.
2. **Indexing:** Через `OpenAI API` создаются эмбеддинги для каждого метода. В метаданные вектора записывается относительный путь к файлу (например, `src/auth/service.ts`).
3. **Storage:** Векторы загружаются в `Supabase` с включенным `pgvector`.
4. **Query:** Когда разработчик спрашивает "Где логика валидации JWT?", ассистент делает векторный поиск, находит фрагмент кода из `service.ts` и отвечает: "Логика валидации находится в файле `src/auth/service.ts` в методе `validateToken`", цитируя код из найденного чанка.
