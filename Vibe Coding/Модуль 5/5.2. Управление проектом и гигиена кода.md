#### Теоретический фундамент и архитектура

- **Стандартная структура директорий modern-приложения:**
    
    - Для обеспечения `AI-Friendly` среды вайбкодер должен придерживаться строгих конвенций файловой структуры. В `Next.js` основными являются папки `/app` (для маршрутизации `App Router`), `/public` (для статичных ассет) и `/src` (опциональная папка для отделения кода приложения от конфигурационных файлов проекта) [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure).
    - Использование логического разделения, такого как `Private Folders` (папки с префиксом `_`), позволяет колоцировать (`Colocation`) вспомогательные файлы (компоненты, библиотеки логики) прямо внутри сегментов маршрута, не делая их публично доступными через `URL` [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure).
    - Логичная иерархия критически важна для управления `Context Window`: когда файлы разложены по назначению (например, `/lib` для утилит и `/components` для `UI`), ИИ-агенту проще индексировать проект и извлекать только релевантные модули, избегая шума и эффекта `Lost in the Middle` [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/), [Вайбкодинг 101: полный гайд для новичков в 2026 году](https://vibecoding.ru/vibecoding).
- **Управление переменными окружения (`Environment Variables`):**
    
    - Для хранения конфигураций используются файлы `.env` (общие настройки) и `.env.local` (локальные секреты, такие как `API` ключи). Последний **никогда** не должен попадать в систему контроля версий [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure), [Supabase CLI config | Supabase Docs](https://supabase.com/docs/guides/local-development/cli/config).
    - Файл `.env.example` служит шаблоном: он содержит только названия ключей без реальных значений, чтобы другие разработчики (или ИИ-агенты) знали, какие переменные необходимо создать для работы приложения [Use Supabase with Next.js | Supabase Docs](https://supabase.com/docs/guides/getting-started/quickstarts/nextjs).
    - Безопасность — это «не-переговорное» правило: утечка `SERVICE_ROLE_KEY` или `OPENAI_API_KEY` может привести к катастрофическим последствиям, поэтому их подстановка в конфиги должна идти через переменные окружения, а не зашиваться в код [Supabase CLI config | Supabase Docs](https://supabase.com/docs/guides/local-development/cli/config), [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
- **Контроль версий как инструмент безопасности (`Git & GitHub`):**
    
    - В вайбкодинге `Git` выполняет роль «страховочной сети» (`Safety Net`) или системы сохранений в видеоигре. Вайбкодер должен совершать `Checkpoint Commit` каждый раз, когда ИИ внес работающее изменение [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
    - Частые коммиты (каждые несколько минут) создают «лестницу безопасности», по которой можно спуститься назад, если ИИ «галлюцинирует» и ломает проект [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

#### Практическая реализация и синтаксис

**Эталонная структура директорий Fullstack-проекта (`Next.js`):**

```
/my-vibe-app
├── /.git               # История версий и контрольные точки
├── /app                # Маршруты и страницы (App Router)
│   ├── /layout.tsx     # Общий скелет UI
│   ├── /page.tsx       # Главная страница
│   └── /api            # Серверные Route Handlers
├── /components         # Повторно используемые UI-компоненты
├── /lib                # Общие утилиты и конфиг Supabase client
├── /public             # Статичные файлы (логотипы, шрифты)
├── .env.local          # СЕКРЕТЫ (НЕ для Git)
├── .env.example        # Шаблон переменных окружения
├── .gitignore          # Правила исключения файлов из Git
└── package.json        # Зависимости и скрипты
```

[Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure), [Вайбкодинг 101: полный гайд для новичков в 2026 году](https://vibecoding.ru/vibecoding).

**Сценарий безопасного внедрения фичи:**

```bash
# 1. Проверить текущее состояние перед вызовом ИИ
git status

# 2. Создать ветку для новой задачи (изоляция)
git checkout -b feature/ai-auth-logic

# 3. После генерации кода ИИ - проверить изменения
git diff

# 4. Если код сломал сборку, мгновенно откатиться к последней версии
git restore .

# 5. Если всё работает, зафиксировать успех
git add .
git commit -m "feat: valid auth logic by AI"
```

[Pro Git](https://progit.pdf/), [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

#### Глоссарий терминов

- **Project Directory Hierarchy** — система организации файлов проекта, обеспечивающая предсказуемый поиск модулей для человека и ИИ [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure).
- **Environment Variables (.env / .env.local)** — механизм хранения конфигурационных параметров вне исходного кода для обеспечения безопасности и гибкости сред [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure).
- **Secret Leak Protection (.gitignore)** — практика использования файла конфигурации `Git` для предотвращения попадания чувствительных данных (ключей, токенов) в публичные репозитории [Supabase CLI config | Supabase Docs](https://supabase.com/docs/guides/local-development/cli/config).
- **Git Safe Workflow (Commit / Reset Safety Net)** — методология разработки, при которой регулярная фиксация состояний позволяет минимизировать ущерб от ошибок ИИ-генерации [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

#### Практический кейс: Ликвидация последствий массовой галлюцинации ИИ

**Ситуация:** Разработчик попросил ИИ отрефакторить один файл, но агент в порыве «очистки» случайно удалил 10 критически важных компонентов в папке `/components` и изменил структуру импортов, что привело к полной неработоспособности приложения [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

**Алгоритм восстановления:**

1. **Stop & Interrogate:** Вайбкодер немедленно останавливает агента командой `ESC` и запрашивает: «Why did you delete components folders?» [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
2. **Diagnostics:** Команда `git status` показывает масштаб разрушений (удаленные и измененные файлы) [Pro Git](https://progit.pdf/).
3. **Nuclear Option:** Если изменений слишком много, используется `git reset --hard HEAD`, чтобы вернуть проект в состояние последнего стабильного коммита. Все галлюцинации стираются мгновенно [Pro Git](https://progit.pdf/), [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
4. **Surgical Restore:** Если нужно вернуть только удаленные файлы, не теряя полезную часть нового кода, используется `git restore components/` [Pro Git](https://progit.pdf/).
5. **New Attempt:** Разработчик очищает контекст (`Context Reset`), декомпозирует задачу на более мелкие и повторяет запрос в новом чате [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

> [!warning] Ограничения ИИ и смещение фокуса разработчика 
> ИИ может вести себя как «Godzilla в Токио», бесшумно удаляя тесты или файлы при рефакторинге. Ваша ответственность — не верить отчету «Mission Accomplished», а лично проверять каждый `diff` и использовать `Git` как единственный источник истины [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

#### Вопросы и задания для самопроверки

1. **Безопасность**: Какие три элемента (файлы/папки) обязательно должны быть добавлены в `.gitignore`, чтобы избежать утечки ключей и избыточности в `GitHub`? [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure).
2. **Git-логика**: ИИ сгенерировал 500 строк неработающего кода. Вы еще не делали `git add`. Какую команду нужно выполнить, чтобы очистить рабочую директорию и попробовать снова? [Pro Git](https://progit.pdf/).
3. **Практика**: Составьте структуру файла `.env.example` для проекта, требующего `NEXT_PUBLIC_SUPABASE_URL` и `OPENAI_API_KEY`. Объясните ИИ-агенту через комментарии в этом файле, какой из ключей можно безопасно показывать в браузере, а какой — нет [Supabase CLI config | Supabase Docs](https://supabase.com/docs/guides/local-development/cli/config), [Use Supabase with Next.js | Supabase Docs](https://supabase.com/docs/guides/getting-started/quickstarts/nextjs).
