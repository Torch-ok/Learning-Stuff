#### Теоретический фундамент и архитектура

- **Принцип декомпозиции «Разделяй и властвуй» (`Divide and Conquer`):**
    
    - Промпты широкого уровня (например, «Сделай сервис как Airbnb») обречены на провал, так как ИИ склонен к «краже функции вознаграждения» (`Reward Hijacking`) — стремлению казаться полезным через генерацию поверхностных «картонных маффинов» вместо глубоко проработанной логики [Vibe Coding Guide](https://bibis.ir.pdf/). Большие задачи неизбежно сталкиваются с лимитами выходного окна и деградацией внимания в середине длинного контекста [Vibe Coding Guide](https://bibis.ir.pdf/).
    - Вайбкодер должен использовать `Task Graph` — концептуальную модель проекта в виде дерева задач, где сложные цели разбиваются на независимые «листовые узлы» (`Leaf Nodes`), реализуемые ИИ за один проход [Vibe Coding Guide](https://bibis.ir.pdf/), [Glossary of Common Terms](https://bibis.ir.pdf/). Каждый модуль, ручка `API` или компонент должны иметь четкие спецификации входов и выходов [Vibe Coding Guide](https://bibis.ir.pdf/), [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering).
- **Обучение на примерах (`Few-Shot Prompting`):**
    
    - Техника «обучения в контексте» (`In-context learning`) позволяет модели уловить паттерны проектирования, стиль именования и технические стандарты проекта без дорогостоящего дообучения весов нейросети [Few-Shot Prompting Explained](https://www.youtube.com/watch?v=...), [Vector embeddings | OpenAI API](https://developers.openai.com/api/docs/guides/embeddings).
    - Передача 1–2 эталонных примеров (например, уже написанного `API`-роута) заставляет ИИ использовать аналогичную обработку ошибок и типизацию, обеспечивая консистентность кодовой базы [Few-Shot Prompting Explained](https://www.youtube.com/watch?v=...), [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering).
- **Цепочка рассуждений (`Chain-of-Thought` / `CoT`):**
    
    - Принуждение модели к предварительному проектированию через инструкции «думай пошагово» (`Think step-by-step`) заставляет ИИ сначала сформулировать логику решения, а затем писать синтаксис [The AI Scientist](https://www.youtube.com/watch?v=...), [Structured generation hurts LLM reasoning performance](https://www.youtube.com/watch?v=...).
    - Это критически важно для проработки краевых случаев (`Edge Cases`) ДО кодинга, так как в режиме прямой генерации ИИ часто игнорирует сложные проверки ради скорости [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering), [Vibe Coding Guide](https://bibis.ir.pdf/).
- **Системные правила проекта (`System Prompts` & `.rules` / `.md` файлы):**
    
    - Для обеспечения «стандартной работы» (`Standard Work`) вайбкодер использует конфигурационные файлы, такие как `AGENTS.md` или `.cursorrules`, которые автоматически инжектируются в каждый запрос [Vibe Coding Guide](https://bibis.ir.pdf/).
    - В них фиксируются «золотые правила» (`Golden Rules`): запрет на использование `any`, требования к безопасности (не хранить ключи в коде) и договоренности по структуре папок (например, использование `/app` роутера в `Next.js`) [Vibe Coding Guide](https://bibis.ir.pdf/), [Getting Started: Project Structure | Next.js](https://nextjs.org/docs/app/getting-started/project-structure).

#### Практическая реализация и синтаксис

**Пример файла правил проекта `CLAUDE.md` (или `.cursorrules`):**

```text
# Project Standards (Next.js + Tailwind + Supabase)

- **Role**: Senior TypeScript Architect.
- **Tech Stack**: Next.js 16 (App Router), Tailwind CSS, Supabase (SSR Auth).
- **Rules**:
  1. Never use 'any' type. Use strict TypeScript.
  2. For Auth, use '@supabase/ssr' package only.
  3. UI components must be in 'src/components' and use Tailwind utility classes.
  4. Environment variables: Use '.env.local', never commit keys to Git.
  5. Error Handling: Always wrap DB calls in try/catch and use Zod for validation.
- **Naming**: Use camelCase for functions, PascalCase for components.
```

[Vibe Coding Guide](https://bibis.ir.pdf/), [Build a User Management App with Next.js | Supabase Docs](https://supabase.com/docs/guides/getting-started/tutorials/with-nextjs).

**Пример промпта с применением техники `Chain-of-Thought`:**

```text
Task: Design a discount logic for an e-commerce platform.
Constraints: Coupons can be percentage-based or flat, cannot be combined, and must have expiry dates.
CoT Instruction:
1. Analyze the database schema for coupons and orders.
2. Step-by-step, describe the validation logic (expiry, usage limits, minimum order amount).
3. Draft a plan to prevent race conditions during coupon application.
4. ONLY after I approve the logic, generate the TypeScript implementation.
```

[Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering), [Vibe Coding Guide](https://bibis.ir.pdf/).

#### Глоссарий терминов

- **Divide and Conquer Strategy** — метод управления сложностью через иерархическую декомпозицию проекта на независимые атомарные задачи [Vibe Coding Guide](https://bibis.ir.pdf/).
- **Few-Shot Prompting Pattern** — метод направления ИИ через демонстрацию примеров входных и выходных данных для задания стиля и логики генерации [Few-Shot Prompting Explained](https://www.youtube.com/watch?v=...).
- **Chain-of-Thought Reasoning (CoT)** — техника активации логических цепочек модели, заставляющая ее вербализовывать мыслительный процесс перед выдачей финального ответа [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering).
- **Project System Rules (.cursorrules / CLAUDE.md)** — файлы внешней памяти проекта, содержащие неизменные архитектурные требования и стандарты качества для ИИ-агентов [Vibe Coding Guide](https://bibis.ir.pdf/).

#### Практический кейс: Внедрение Few-Shot и System Rules для унификации кода

**Проблема:** ИИ-ассистент генерировал компоненты в хаотичном стиле: часть на классах (легаси), часть функционально, с разным именованием пропсов [Vibe Coding Guide](https://bibis.ir.pdf/).

**Решение:**

1. **Создание `AGENTS.md`**: Разработчик зафиксировал правило: «Always use Functional Components with React.FC and Tailwind CSS. No CSS modules» [Vibe Coding Guide](https://bibis.ir.pdf/).
2. **Шаблон `Few-Shot`**: В промпт была добавлена секция `<example>`, содержащая эталонный компонент кнопки с правильной типизацией и стилями [Few-Shot Prompting Explained](https://www.youtube.com/watch?v=...).
3. **Результат**: Все последующие компоненты (формы, списки, карточки) ИИ генерировал строго по образцу, что сократило время на рефакторинг и ручную чистку кода на 15–20% [Vibe Coding Guide](https://bibis.ir.pdf/).
