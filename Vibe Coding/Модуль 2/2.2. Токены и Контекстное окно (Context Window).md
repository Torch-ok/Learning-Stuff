#### Теоретический фундамент и архитектура

- **Понятие токена (`Token`) и процессы токенизации (`Tokenization`):**
    
    - `Token` — это минимальная атомарная единица обработки данных для `LLM`. В отличие от человеческого восприятия, модель видит не слова, а числовые идентификаторы (`ID`), присвоенные фрагментам текста [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/). Один токен может представлять собой целое слово (для коротких и частых слов типа "cat"), часть слова, знак препинания или даже пробел [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/), [Vector embeddings | OpenAI API](https://developers.openai.com/api/docs/guides/embeddings).
    - **Соотношение объемов:** Из-за сложной морфологии русский язык значительно менее "эффективен" в токенах: 1000 токенов ≈ 700–750 слов на английском, но лишь 350–400 слов на русском [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/). Любые технические термины, длинные названия и специфическое форматирование увеличивают этот расход [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).
    - **Особенности токенизации кода:** В разработке каждый символ имеет значение. Отступы, фигурные скобки, переносы строк и даже лишние знаки препинания учитываются как отдельные токены [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/). Если код содержит таблицы или сложные структуры, итоговое количество токенов может в несколько раз превышать визуальный объем текста [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).
- **Анатомия контекстного окна (`Context Window`):**
    
    - `Context Window` — это предел оперативной памяти модели, ограничивающий суммарный объем входящего запроса (`Prompt`) и генерируемого ответа (`Completion`) [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/), [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering). Модели 2025–2026 годов являются бездисковыми и "беспамятными" (`Stateless`): при каждом новом сообщении в чате вы физически пересылаете всю историю переписки заново, что ведет к квадратичному росту стоимости [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
    - **Размеры:** Современные фронтирные модели (например, `GPT-4.1` или `Llama 4`) поддерживают от `128k` до `1M` и даже `10M` токенов [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/), [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering). Однако важно помнить про лимит выходного окна (`Output Context Window`), который значительно меньше и обычно составляет `4,000–8,000` токенов [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
- **Эффект «Lost in the Middle» и провал внимания:**
    
    - Увеличение `Context Window` не гарантирует идеального "вспоминания". Существует феномен `Context Saturation` (насыщение контекста): при заполнении окна более чем на 50%, модель начинает игнорировать инструкции, даже если они написаны заглавными буквами [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/). Исследования показывают деградацию логики уже после `3,000` токенов у многих моделей [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
    - Механизм внимания (`Attention Mechanism`) лучше всего фокусируется на данных в самом начале и в самом конце промпта. Информация, расположенная в середине длинного текста, часто "вымывается" и игнорируется [Basic Prompt Examples for LLMs](https://www.youtube.com/watch?v=...). Чем больше в запросе "шума" (нерелевантного кода), тем выше вероятность галлюцинаций и ошибок [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).

> [!warning] Ограничения ИИ и смещение фокуса разработчика 
> Огромное контекстное окно — это ловушка. Чем больше данных на "клипборде" у ИИ, тем менее точными становятся его рассуждения. Вайбкодер должен не "пихать всё в чат", а заниматься кураторством контекста, вовремя очищая историю и выделяя только необходимые модули [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

#### Практическая реализация и синтаксис

**Пример скрипта на Python для расчета токенов (библиотека `tiktoken`):**

```python
import tiktoken

def count_code_tokens(file_path: str, model="gpt-4o"):
    # Используем кодировку cl100k_base для актуальных моделей
    encoding = tiktoken.encoding_for_model(model)

    with open(file_path, 'r', encoding='utf-8') as f:
        code_content = f.read()

    tokens = encoding.encode(code_content)
    print(f"File: {file_path}")
    print(f"Total tokens: {len(tokens)}")

# Пример вызова для TypeScript файла
count_code_tokens("src/controllers/userController.ts")
```

[Vector embeddings | OpenAI API](https://developers.openai.com/api/docs/guides/embeddings), [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).

**Влияние форматирования на токенизацию TypeScript:**

Один и тот же логический блок может занимать разное количество токенов:

1. **Сжатый стиль:** `if(a){return b}` — меньше токенов (пробелы отсутствуют).
2. **Развернутый стиль (Prettier):**
    
    ```python
    if (a) {
      return b;
    }
    ```
    
    — больше токенов за счет символов табуляции (`\t` или 2–4 пробела), переносов строк (`\n`) и точек с запятой [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).

#### Глоссарий терминов

- **Token & Subword Unit** — базовый фрагмент данных (слово или его часть), который `LLM` использует для предсказания и генерации текста [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).
- **Code Tokenization Impact** — влияние синтаксических знаков и форматирования кода на итоговый расход токенов и стоимость запроса [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).
- **Context Window Limit** — жесткое ограничение на суммарный объем данных, который модель способна "удержать в уме" за один проход [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
- **Lost in the Middle Phenomenon** — снижение способности ИИ извлекать и использовать информацию, находящуюся в середине длинного входного текста [Как устроены AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/), [Basic Prompt Examples for LLMs](https://www.youtube.com/watch?v=...).

#### Практический кейс: Оптимизация длинного файла с бизнес-логикой

**Проблема:** При передаче контроллера на 2000 строк кода ИИ успешно отрефакторил функции в начале и конце файла, но полностью пропустил критическое правило валидации в середине (эффект `Lost in the Middle`) [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).

**Алгоритм решения (Техника Curation):**

1. **Decomposition:** Вместо отправки всего файла, выделите проблемную функцию и её непосредственные зависимости (интерфейсы `DTO`) [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
2. **Focused Context:** Сформируйте новый чат, подав только: 1) Сигнатуру функции; 2) Описание бага; 3) Схему базы данных [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
3. **CliffsNotes:** Если важен общий контекст приложения, используйте "краткое содержание" архитектуры вместо полных исходников [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
4. **Save Game:** Используйте чекпоинты в `IDE` (`Cursor` / `Windsurf`), чтобы откатиться к чистому контексту, если сессия стала слишком длинной и модель начала "тупить" [Vibe Coding - Building Production-Grade Software](https://bibis.ir.pdf/).
