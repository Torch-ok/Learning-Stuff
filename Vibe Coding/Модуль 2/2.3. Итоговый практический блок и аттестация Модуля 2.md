#### Сквозной практический кейс: Стратегия управления контекстом и параметрами генерации при поиске плавающего бага

**Постановка задачи:** В веб-приложении на `Next.js` обнаружена плавающая ошибка сессии. После 2 часов диалога с ИИ, в ходе которого было перепробовано 10 вариантов фикса, модель начала предлагать код, противоречащий установленным ранее правилам безопасности, и использовать несуществующие методы `Supabase Auth` [Vibe Coding Guide](https://bibis.ir.pdf/).

**Пошаговый алгоритм решения:**

1. **Оценка контекста:** Разработчик замечает, что ИИ игнорирует системное правило «не использовать `localStorage` для токенов», заданное в начале. Это явный признак эффекта `Lost in the Middle` и насыщения контекста (`Context Saturation`), когда модель при заполнении окна более чем на 50% начинает «тупеть» [Vibe Coding Guide](https://bibis.ir.pdf/), [AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).
2. **Сброс сессии:** Вместо продолжения «отравленного» диалога, создается новый чат. Параметр `Temperature` устанавливается в значение `0.1` (или `0.2`), чтобы минимизировать случайность и заставить ИИ строго следовать синтаксису `TypeScript` [LLM Settings](https://www.youtube.com/watch?v=...), [Vibe Coding Guide](https://bibis.ir.pdf/).
3. **Формирование чистого промпта:** В новый чат подаются только:
    - Актуальная схема базы данных и типы `Auth`.
    - Минимальный фрагмент `Middleware`, где происходит ошибка.
    - Свежий стектрейс из консоли браузера [Vibe Coding Guide](https://bibis.ir.pdf/), [Prompt engineering | OpenAI API](https://developers.openai.com/api/docs/guides/prompt-engineering).
4. **Валидация решения:** Получив ответ, вайбкодер проводит «White-box audit»: проверяет предложенный импорт `auth-utils`. Если ИИ настаивает на его использовании, разработчик запрашивает: «Explain the internal logic of this function», чтобы выявить галлюцинацию на этапе аргументации [Vibe Coding Guide](https://bibis.ir.pdf/), [Clean Code.pdf](https://Clean Code.pdf).

#### Комплексный контрольный тест для самопроверки

1. **Сравните поведение модели**: Почему при `Temperature = 0.9` модель может выдать 5 разных вариантов одной и той же функции при повторе запроса, а при `Temperature = 0.1` результат будет почти всегда идентичен? Как это влияет на отладку? [LLM Settings](https://www.youtube.com/watch?v=...).
2. **Физика токенизации**: Объясните, почему замена 4 пробелов на 1 символ табуляции в коде на 2000 строк может сэкономить значительную часть `Context Window` и снизить стоимость запроса. Какие символы ИИ считает за отдельные токены? [AI токены / Хабр](https://habr.com/ru/companies/gptunnel/articles/986526/).
3. **Детекция галлюцинаций**: ИИ сгенерировал импорт `import { validateSuperAuth } from 'auth-magic-utils'`. Вместо запуска `npm install`, какой уточняющий вопрос следует задать модели, чтобы она сама признала ошибку, исходя из принципа «Interrogation»? [Vibe Coding Guide](https://bibis.ir.pdf/).
4. **Архитектурный выбор**: Ваш файл контроллера занимает 10 000 токенов, что в 2 раза больше комфортного порога внимания модели. Опишите стратегию `Decomposition`: на какие логические части вы разделите файл перед отправкой в ИИ, чтобы избежать потери контекста? [Vibe Coding Guide](https://bibis.ir.pdf/), [Clean Architecture](https://Clean Architecture A Craftsman Guide to Software Structure and Design.pdf).
5. **Гигиена контекста**: Составьте список из 3 правил для файла `.rules` или `AGENTS.md`, которые помогут ИИ-агенту самостоятельно «очищать» свою память или предупреждать вас о достижении лимитов контекстного окна [Vibe Coding Guide](https://bibis.ir.pdf/).
