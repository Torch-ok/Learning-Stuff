Для инженера уровня Middle DevOps это основной инструмент борьбы с «раздуванием» образов и обеспечения безопасности за счет минимизации состава итогового артефакта [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### Проблема SDK-балласта и «налога на сборку»

Классический подход к написанию `Dockerfile` с одной инструкцией `FROM` порождает фундаментальную техническую проблему: в итоговый образ, который отправится на продакшен-сервер, попадает всё содержимое сборочного окружения [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

Рассмотрим наш сквозной пример. Для корректной работы **Flask** с базой данных **PostgreSQL** часто требуется библиотека `psycopg2`. На дистрибутивах вроде Alpine Linux её компиляция требует наличия «тяжелого» инструментария: `gcc`, `musl-dev`, `postgresql-dev` и других заголовочных файлов [Using a non-root user - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4/using-a-non-root-user), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Если оставить эти инструменты в финальном образе:

1. **Размер образа** вырастет на сотни мегабайт, что замедлит работу CI/CD-пайплайнов и деплой [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
2. **Площадь атаки (Attack Surface)** значительно расширится: наличие компиляторов и утилит вроде `git` или `curl` внутри контейнера облегчает злоумышленнику задачу по сборке вредоносного ПО в случае взлома приложения [Securing_Docker], [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
3. **Утечка секретов:** Исходный код и приватные ключи, нужные только для скачивания зависимостей, могут остаться в промежуточных слоях [Docker-in-Practice], [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### Концепция Multi-stage: Фильтрация артефактов

Технология **Multi-stage builds** позволяет использовать несколько инструкций `FROM` в одном `Dockerfile` [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). Каждый этап (stage) — это фактически временный контейнер, который Docker создает в процессе сборки [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Магия заключается в том, что вы можете выборочно копировать файлы из одного этапа в другой, выбрасывая всё ненужное [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Optimizing the image size - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4/optimizing-the-image-size).

#### Эталонный Dockerfile для Flask + PostgreSQL

Ниже представлен профессиональный пример разделения на стадию сборки (`builder`) и стадию исполнения (`runner`) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

```yml
# ЭТАП 1: Сборочное окружение (builder)
FROM python:3.11-alpine AS builder

WORKDIR /build

# Установка системных зависимостей для компиляции psycopg2
RUN apk add --no-cache gcc musl-dev postgresql-dev

# Копирование манифеста и установка библиотек в локальную папку
COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install -r requirements.txt


# ЭТАП 2: Рантаим (runner) - этот образ пойдет в продакшен
FROM python:3.11-alpine AS runner

WORKDIR /app

# Установка ТОЛЬКО рантаим-зависимости (libpq необходима для работы psycopg2)
RUN apk add --no-cache libpq

# ГЛАВНАЯ МАГИЯ: Копируем только скомпилированные пакеты из стадии builder
# Мы забираем результат работы, оставляя GCC и исходники в прошлом
COPY --from=builder /install /usr/local

# Копируем код приложения
COPY . .

# Переход на непривилегированного пользователя для безопасности
RUN adduser -D appuser
USER appuser

CMD ["python", "app.py"]
```

В данном примере итоговый образ `runner` будет весить в 3–5 раз меньше, чем если бы мы объединили всё в одну стадию [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Инструкция `COPY --from=builder` позволяет переносить только скомпилированные артефакты, игнорируя гигабайты мусора, оставшегося после работы компилятора [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

> [!warning] Актуализация синтаксиса 
> В старых источниках можно встретить обращение к стадиям по индексам (например, `COPY --from=0`) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). По стандартам 2026 года настоятельно рекомендуется использовать именованные стадии через ключевое слово `AS`, так как это делает код `Dockerfile` читаемым и устойчивым к изменениям порядка шагов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
