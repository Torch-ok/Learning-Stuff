Ниже представлены ключевые понятия, определяющие методологию взаимодействия с Docker CLI и управление рантаймом контейнеров по стандартам 2026 года.

- **Management Commands** — иерархическая структура команд Docker (например, `docker container <action>`), введенная для логической группировки операций над объектами и устранения двусмысленности legacy-синтаксиса [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).
- **Detached mode** — режим запуска контейнера в фоновом процессе (флаг `-d`), при котором управление немедленно возвращается в терминал хоста, а стандартные потоки вывода перехватываются драйвером логирования [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).
- **Interactive mode** — режим (флаги `-it`), обеспечивающий двустороннюю связь между терминалом пользователя и процессом внутри контейнера через выделение псевдо-TTY и удержание открытым потока STDIN [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).
- **Graceful Shutdown** — процесс «мягкой» остановки приложения, при котором Docker дает процессу время на корректное завершение транзакций и очистку ресурсов перед окончательным уничтожением [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).
- **SIGTERM** — стандартный сигнал завершения (Signal 15), отправляемый командой `stop`, который приложение может перехватить для выполнения Graceful Shutdown [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
- **SIGKILL** — жесткий сигнал уничтожения (Signal 9), который нельзя перехватить или проигнорировать; приводит к моментальной остановке процесса ядром Linux [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).
- **Exit Code** — целочисленный код возврата процесса; код `0` означает успех, коды выше `128` обычно указывают на завершение по системному сигналу (например, `137` — это SIGKILL) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker-in-Practice](https://manning.com/books/docker-in-practice).

## Практическое упражнение (Интерактивный CLI-тренажер Модуля 4)

**Инженерный кейс: «Развертывание на коленке»**

Представьте, что вам нужно быстро проверить работоспособность базы данных и возможность подключения к ней из бэкенда, не создавая `compose.yaml`. Ваша задача — выполнить последовательность действий строго через Docker CLI.

### Шаг 1: Запуск PostgreSQL в фоновом режиме

Мы запускаем базу данных нашего интернет-магазина. Нам важно, чтобы она сама поднималась при сбоях, но не мешала нам работать в терминале.

```bash
docker container run -d \
  --name shop-db \
  --restart unless-stopped \
  -e POSTGRES_PASSWORD=secret \
  postgres:16-alpine
```

**Разбор:**

- `-d` запускает контейнер как демона (detached) [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).
- `--restart unless-stopped` гарантирует, что база поднимется после перезагрузки сервера, если вы не остановили ее вручную [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
- `-e` передает переменную окружения с паролем [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

### Шаг 2: Интерактивная проверка из Python

Запустим временный контейнер с Python, чтобы «простучать» базу. Нам нужно попасть внутрь оболочки, а после выхода контейнер должен самоуничтожиться, чтобы не занимать место.

```bash
docker container run -it --rm \
  --name db-checker \
  python:3.11-slim \
  bash
```

**Разбор:**

- `-it` открывает интерактивный доступ к bash внутри Python-образа [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).
- `--rm` автоматически удалит контейнер после команды `exit` [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

### Шаг 3: Мониторинг и фильтрация

Предположим, какой-то из ваших экспериментов упал. Найдем только те контейнеры, которые завершились с ошибкой.

```bash
docker container ls -a --filter "status=exited" --filter "exited=1"
```

**Разбор:** Флаг `--filter` позволяет отсеять мусор и сфокусироваться на проблемных сервисах [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).

### Шаг 4: Graceful Shutdown

Корректно остановим нашу базу данных, чтобы PostgreSQL успел сбросить кэш на диск.

```bash
docker container stop shop-db
```

**Разбор:** Команда посылает SIGTERM. Если база не успеет закрыться за 10 секунд, Docker применит SIGKILL [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
