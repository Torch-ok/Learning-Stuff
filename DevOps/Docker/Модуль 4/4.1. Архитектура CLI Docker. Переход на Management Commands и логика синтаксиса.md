По мере развития Docker и превращения его из небольшого проекта в мощную платформу, интерфейс командной строки (CLI) столкнулся с проблемой «засорения». В ранних версиях команды добавлялись бессистемно, что привело к появлению десятков разнородных команд верхнего уровня, таких как `docker run`, `docker ps`, `docker rmi` или `docker build` [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/). К 2026 году индустриальным стандартом стал переход на так называемые **Management Commands** — строго структурированную иерархию, которая упорядочивает взаимодействие с объектами Docker [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### Эволюция синтаксиса: От хаоса к иерархии
Главная проблема старого (legacy) синтаксиса заключалась в его двусмысленности. Например, команда `docker rm` использовалась для удаления контейнеров, а `docker rmi` — для удаления образов [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/). С появлением новых типов объектов (сетей, томов, секретов) такая плоская структура стала бы нечитаемой [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).

В современном CLI Docker логика построена по принципу **«Объект — Действие»**:
`docker <object> <action> [options]`

Где `<object>` — это тип системного ресурса, которым вы управляете [Definitions and basic concepts - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts):
*   `container` — всё, что касается запущенных процессов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
*   `image` — управление шаблонами и слоями [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).
*   `network` — конфигурация виртуальных сетей [Docker networking - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/docker-networking).
*   `volume` — управление постоянными хранилищами данных [Volumes in action - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/volumes-in-action).
*   `system` — общие настройки движка и очистка ресурсов [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).

Такой подход позволяет инженеру сразу понимать, на какой уровень абстракции направлено действие. Если вы работаете с нашим сквозным стеком (**Flask + PostgreSQL**), вы четко разделяете: `docker image build` для подготовки «чертежа» приложения и `docker container run` для его запуска в производство [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).

#### Таблица соответствия: Legacy vs Management Commands

Для эффективной работы в 2026 году крайне рекомендуется использовать полную форму команд. Хотя старые сокращения еще поддерживаются для обратной совместимости, они считаются признаком «плохого тона» в профессиональной среде [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

| Legacy команда | Management Command | Объект управления                                                                                                                                                                                  |
| :-------------- | :--------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docker ps` | `docker container ls` | Контейнеры [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf) |
| `docker run` | `docker container run` | Контейнеры [MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts)                                                            |
| `docker rm` | `docker container rm` | Контейнеры [Хабр](https://habr.com/ru/companies/ruvds/articles/440660/)                                                                                                                            |
| `docker images` | `docker image ls` | Образы [Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/)                                                                                                                               |
| `docker rmi` | `docker image rm` | Образы [Хабр](https://habr.com/ru/companies/ruvds/articles/440660/)                                                                                                                                |
| `docker build` | `docker image build` | Образы [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf)     |
| `docker pull` | `docker image pull` | Образы [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf)     |
| `docker cp` | `docker container cp` | Файлы внутри контейнера [Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/)                                                                                                              |

Использование Management Commands делает ваши скрипты автоматизации более читаемыми и предсказуемыми. Теперь флаги, специфичные для контейнеров (например, `--restart`), никогда не будут перепутаны с флагами для образов или сетей [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).

### Тест для самопроверки (Синтаксис CLI)

<details>
<summary>1. Какая команда является современным стандартом для просмотра списка всех (включая остановленные) контейнеров?</summary>
<blockquote>
<b>Ответ:</b> <code>docker container ls -a</code>. Использование Management Command <code>container ls</code> с флагом <code>-a</code> (all) позволяет увидеть полную картину ресурсов </blockquote>
</details>[Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).


<details>
<summary>2. В чем преимущество синтаксиса "docker &lt;object&gt; &lt;action&gt;" перед старым плоским списком команд?</summary>
<blockquote>
<b>Ответ:</b> Это обеспечивает логическую группировку и устраняет двусмысленность (например, четкое разделение между удалением контейнера <code>container rm</code> и удалением образа <code>image rm</code>), а также делает CLI расширяемым для новых типов объектов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
</blockquote>
</details>

<details>
<summary>3. Какую команду вы выберете для удаления неиспользуемого образа PostgreSQL, если контейнеров на его основе больше нет?</summary>
<blockquote>
<b>Ответ:</b> <code>docker image rm postgres</code>. Это современная замена устаревшей команде <code>docker rmi</code> [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).
</blockquote>
</details>

<details>
<summary>4. Какая Management Command отвечает за глобальную очистку системы от "мусора" (остановленных контейнеров, пустых сетей и кэша)?</summary>
<blockquote>
<b>Ответ:</b> <code>docker system prune</code>. Объект <code>system</code> объединяет действия, влияющие на весь Docker Engine целиком [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
</blockquote>
</details>

<details>
<summary>5. Если вы введете <code>docker pull alpine</code>, к какому объекту и действию Docker неявно приведет эту команду?</summary>
<blockquote>
<b>Ответ:</b> К команде <code>docker image pull alpine</code>. Движок автоматически сопоставляет legacy-команды с их современными аналогами в иерархии объектов [Docker Deep Dive](https://z-lib.org/).
</blockquote>
</details>
