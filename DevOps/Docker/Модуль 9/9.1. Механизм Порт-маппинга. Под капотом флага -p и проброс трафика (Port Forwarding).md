В 2026 году сетевая изоляция остается одним из столпов безопасности контейнеризации [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). По умолчанию каждый контейнер Docker является сетевой «песочницей»: он обладает собственным сетевым стеком, IP-адресом и таблицей маршрутизации, полностью изолированными от хост-машины и внешней среды [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/), [Docker QnA vijay](https://github.com/vijay/docker-qna). Это означает, что если наше приложение **Flask** слушает порт `5000` внутри контейнера, этот порт будет абсолютно недоступен для браузера на вашем ноутбуке без явной настройки проброса трафика [Docker QnA vijay](https://github.com/vijay/docker-qna), [Docker для новичков — #1 Что такое контейнер, image, DockerHub? / Хабр](https://habr.com/ru/articles/804323/).

#### Концепция сетевой изоляции

Когда Docker запускает процесс (например, **PostgreSQL** на порту `5432`), ядро Linux создает для него отдельное **Network Namespace** [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Docker-in-Practice](https://manning.com/books/docker-in-practice). Внутри этого пространства контейнер видит только свой интерфейс `eth0` с приватным IP-адресом (обычно из диапазона `172.17.0.0/16`) [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Снаружи, со стороны хост-системы, этот процесс не слушает порты на реальных сетевых интерфейсах сервера. Порт `5000` открыт только внутри виртуальной сети Docker [Docker QnA vijay](https://github.com/vijay/docker-qna).

#### Синтаксис и механика флага -p (--publish)

Для того чтобы сделать сервис доступным извне, используется механизм **Port Forwarding** (перенаправление портов), реализуемый через флаг `-p` или его полную форму `--publish` в команде `docker container run` [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).

**Стандартный формат:** `-p [host_port]:[container_port]`

**Пример для Flask:** `docker container run -d -p 8080:5000 flask-app` [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Здесь порт `8080` на вашем компьютере (хосте) связывается с портом `5000` внутри контейнера. Весь трафик, приходящий на `localhost:8080`, Docker перенаправит внутрь контейнера на порт `5000` [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

> [!important] Различие с EXPOSE 
> Инструкция `EXPOSE` в Dockerfile — это лишь документация, которая не открывает порты фактически [Docker Deep Dive](https://z-lib.org/), [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/). Только флаг `-p` (или `-P` для публикации всех экспонированных портов на случайные порты хоста) создает реальную сетевую связку [Docker QnA vijay](https://github.com/vijay/docker-qna), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

#### Под капотом Linux: iptables и NAT

Когда вы указываете флаг `-p`, Docker Daemon выполняет сложную низкоуровневую работу в ОС Linux [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/):

1. **Манипуляция iptables:** Docker добавляет правила в цепочку `DOCKER` системного брандмауэра `iptables` [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/). Эти правила используют механизм **DNAT** (Destination Network Address Translation), переписывая адрес назначения входящих пакетов с IP хоста на внутренний IP контейнера [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
2. **Процесс docker-proxy:** Для каждого опубликованного порта Docker запускает на хосте отдельный легковесный процесс `docker-proxy` [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/). Он слушает порт на хосте и физически перебрасывает данные между сокетом хоста и сокетом контейнера [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
3. **Маршрутизация через bridge:** Пакет проходит через виртуальный мост `docker0`, который выступает шлюзом для контейнера, и попадает на виртуальный интерфейс `veth` внутри контейнера [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

#### Привязка к интерфейсам и безопасность

По умолчанию запись `-p 8080:80` равносильна `-p 0.0.0.0:8080:80` [Docker QnA vijay](https://github.com/vijay/docker-qna), [Interacting with the container via volumes and ports - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/interacting-with-the-container-via-volumes-and-ports). Это означает, что Docker будет слушать порт на **всех** доступных сетевых интерфейсах сервера (Ethernet, Wi-Fi, VPN) [Docker QnA vijay](https://github.com/vijay/docker-qna). Если ваш сервер имеет публичный IP, ваше приложение станет доступно всему интернету [Interacting with the container via volumes and ports - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/interacting-with-the-container-via-volumes-and-ports).

**Безопасный подход (Local-only binding):** Для базы данных **PostgreSQL**, к которой должен обращаться только локальный бэкенд, или для отладки Flask, используйте явную привязку к петлевому интерфейсу (loopback) [Docker QnA vijay](https://github.com/vijay/docker-qna), [Interacting with the container via volumes and ports - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/interacting-with-the-container-via-volumes-and-ports): `docker container run -p 127.0.0.1:5432:5432 postgres`

В этом случае порт будет открыт только для запросов с самой хост-машины, закрывая «дверь» для внешних атак [Interacting with the container via volumes and ports - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/interacting-with-the-container-via-volumes-and-ports).

#### Ловушка для инженера: Перепутанный порядок

Классическая ошибка новичков — путаница в порядке портов. **Запомните правило:** мы читаем слева направо, как предложение: «Хост передает Трафик в Контейнер» [Docker-in-Practice](https://manning.com/books/docker-in-practice).

- **Правильно:** `-p 80:5000` (Браузер на 80 -> Flask на 5000).
- **Ошибка:** `-p 5000:80` (Хост будет ждать трафик на 5000 и пытаться отправить его на порт 80 внутри контейнера, где Flask его не ждет). Приложение будет работать, контейнер будет в статусе `Up`, но при попытке открыть сайт вы получите `Connection Refused` [Docker QnA vijay](https://github.com/vijay/docker-qna).

Если вы получили ошибку `port is already allocated`, это значит, что другой процесс или контейнер на хосте уже занял указанный вами `host_port` [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ), [Extending_Docker](https://www.packtpub.com/product/extending-docker/9781783984367). Вам необходимо либо остановить старый процесс, либо выбрать другой свободный порт на хосте [Docker QnA vijay](https://github.com/vijay/docker-qna), [Extending_Docker](https://www.packtpub.com/product/extending-docker/9781783984367).
