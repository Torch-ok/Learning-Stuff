В современной архитектуре Docker сетевое взаимодействие не является монолитным. Благодаря реализации спецификации **Container Network Model (CNM)** и библиотеке `libnetwork`, движок Docker поддерживает подключаемую (pluggable) архитектуру драйверов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker networking - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/docker-networking). Каждый сетевой драйвер определяет свою топологию и правила маршрутизации трафика, позволяя инженеру гибко настраивать баланс между изоляцией, производительностью и сложностью конфигурации [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker QnA vijay](https://github.com/vijay/docker-qna).

#### Драйвер bridge: Виртуальный коммутатор внутри хоста

Драйвер `bridge` (мост) — это самый распространенный тип сети, используемый по умолчанию в Linux-системах [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Технически это программная реализация стандарта **802.1d bridge**, которая ведет себя как виртуальный сетевой коммутатор (switch) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).

**Анатомия взаимодействия:** Когда вы запускаете контейнер в такой сети, Docker создает пару виртуальных интерфейсов (`veth pair`) [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker-in-Practice](https://manning.com/books/docker-in-practice). Один конец «трубы» (`eth0`) помещается внутрь **Network Namespace** контейнера, а второй прикрепляется к мосту на хосте [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

1. **Дефолтная сеть `bridge`:**
    
    - Создается автоматически при установке Docker и мапится на интерфейс `docker0` в ядре Linux [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).
    - **Критическое ограничение:** Контейнеры в этой сети могут общаться друг с другом только по IP-адресам [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Встроенный DNS-сервер здесь не работает для разрешения имен, что делает разработку сложных систем (например, Flask + PostgreSQL) крайне неудобной из-за динамической природы IP [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
2. **Пользовательские сети (User-defined bridge networks):**
    
    - Создаются командой `docker network create --driver bridge my-net` [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker QnA vijay](https://github.com/vijay/docker-qna).
    - **Service Discovery через DNS:** Это «киллер-фича» пользовательских сетей [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). В каждой такой сети Docker запускает встроенный DNS-резолвер [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/), [Docker-in-Practice](https://manning.com/books/docker-in-practice). Если контейнер с базой данных назван `db`, то Flask-приложение в этой же сети может просто обращаться к хосту `db` вместо `172.18.0.5` [Docker networking - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/docker-networking), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

#### Драйвер host: Максимальная скорость без барьеров

Драйвер `host` полностью убирает сетевую изоляцию между контейнером и хост-машиной [Docker QnA vijay](https://github.com/vijay/docker-qna), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Контейнер не получает собственного IP-адреса и использует сетевой стек хоста напрямую [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Docker_eBook](https://zzzprojects.com/docker-ebook).

- **Плюсы:** Идеальная производительность. Трафик не проходит через цепочки `iptables` и правила NAT, что критично для высоконагруженных систем [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
- **Минусы:** Риск коллизии портов [Docker-in-Practice](https://manning.com/books/docker-in-practice). Если на хосте уже запущен **Nginx** на порту 80, вы не сможете запустить контейнер в режиме `--network host`, слушающий этот же порт [Docker-in-Practice](https://manning.com/books/docker-in-practice). Кроме того, контейнер получает доступ ко всем сетевым интерфейсам сервера, что снижает безопасность [Docker_eBook](https://zzzprojects.com/docker-ebook).

#### Драйвер none: Абсолютный вакуум

Использование драйвера `none` помещает контейнер в полностью изолированный сетевой стек [Docker QnA vijay](https://github.com/vijay/docker-qna), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Внутри доступен только интерфейс петлевого адреса (`loopback / 127.0.0.1`) [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/), [Docker_eBook](https://zzzprojects.com/docker-ebook).

**Юзкейсы:**

- Выполнение пакетных задач, не требующих доступа к сети (например, генерация PDF или обработка видео) [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).
- Криптографические операции, где риск утечки ключей по сети должен быть исключен на уровне ядра [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

#### Мультихост-решения: overlay и macvlan

Когда инфраструктура разрастается до нескольких серверов, в дело вступают продвинутые драйверы [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

- **overlay:** Позволяет объединить контейнеры на разных физических хостах в одну виртуальную сеть уровня L2 [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Это стандарт для **Docker Swarm** [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Под капотом используется технология **VXLAN**, которая инкапсулирует пакеты контейнеров в UDP-пакеты физической сети хостов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).
- **macvlan:** Самый низкоуровневый драйвер, который назначает каждому контейнеру уникальный MAC-адрес, делая его полноценным участником физической сети хоста [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker QnA vijay](https://github.com/vijay/docker-qna). Контейнеры выглядят для сетевого оборудования (роутеров) как отдельные физические серверы [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

> [!warning] Особенность macvlan 
> Для работы `macvlan` сетевая карта хоста должна поддерживать «разборчивый режим» (**promiscuous mode**) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf). Большинство публичных облачных провайдеров (AWS, Azure) запрещают этот режим из соображений безопасности, поэтому там этот драйвер использовать невозможно [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
