Для того чтобы превратить исходный код нашего приложения (**Flask**, **Nginx** или **PostgreSQL**) в переносимый артефакт, необходимо описать процесс его «выпекания» в специальном текстовом документе — `Dockerfile`,,. `Dockerfile` — это декларативный манифест, содержащий последовательный набор инструкций, которые движок Docker выполняет сверху вниз для автоматизированной сборки образа,,,. Каждая команда в этом файле, добавляющая контент, формирует новый неизменяемый слой, что позволяет использовать преимущества кэширования и переиспользования данных,,,.

#### Инструкция FROM: Фундамент образа

Любой валидный `Dockerfile` (за редким исключением) должен начинаться с инструкции `FROM`,,,. Она определяет родительский образ (**Base Image**), который станет основой для всех последующих изменений,,,.

**Синтаксис и лучшие практики:**

- **Синтаксис:** `FROM <image>[:<tag>]`,,.
- **Фиксация тегов:** Использование плавающего тега `:latest` в инструкции `FROM` (например, `FROM python`) является критической ошибкой для стабильности сборки,,. Если мейнтейнер обновит версию Python в реестре, ваш образ может внезапно перестать собираться или работать из-за несовместимости,,.
- **Рекомендация 2026:** Всегда фиксируйте конкретную версию и дистрибутив, например `FROM python:3.11-slim` или `FROM node:22-alpine`,,,. Это гарантирует детерминированность: образ будет собираться одинаково сегодня и через год,,.

#### Инструкция WORKDIR: Управление контекстом путей

Инструкция `WORKDIR` устанавливает рабочую директорию для всех последующих инструкций, таких как `RUN`, `COPY`, `ADD`, `CMD` и `ENTRYPOINT`,,,.

- **Замена cd:** Профессиональные инженеры избегают использования команд перехода `RUN cd /app && ...`, так как они действуют только в рамках одного слоя,,. `WORKDIR` же меняет контекст для всего процесса сборки и рантайма,,.
- **Автоматизация:** Если указанная директория не существует, Docker создаст её автоматически, включая все промежуточные папки,,,.
- **Пример:** Для нашего бэкенда на Flask хорошим тоном будет использование `WORKDIR /app`,.

#### Переменные: ARG против ENV

Docker предоставляет два механизма работы с переменными, которые часто путают, но они имеют принципиально разное время жизни,,.

1. **ARG (Build-time variables):**
    
    - Используются исключительно в процессе сборки образа,,.
    - Значения можно передавать через флаг `--build-arg` команды `docker image build`,,.
    - **Runtime:** В запущенном контейнере эти переменные недоступны,.
    - _Предупреждение:_ Не используйте `ARG` для передачи секретов (паролей к БД Postgres), так как они сохраняются в истории слоев образа и могут быть извлечены.
2. **ENV (Environment variables):**
    
    - Устанавливают переменные окружения, которые будут доступны как во время сборки, так и в рантайме внутри контейнера,,,.
    - Именно через `ENV` наше Flask-приложение узнает настройки порта или адрес подключения к базе данных,,.
    - Переменные `ENV` наследуются дочерними образами.

#### Дистрибуция файлов: COPY против ADD

Обе инструкции предназначены для копирования файлов из контекста сборки (вашего компьютера) в файловую систему образа, но имеют разную степень сложности,,.

- **COPY:** Рекомендуется для 99% задач,,. Она просто берет файл или папку и перемещает их в образ по указанному пути,,. Она прозрачна и предсказуема.
- **ADD:** Обладает «магическими» свойствами, которые следует использовать с осторожностью,.
    
    1. **Распаковка:** Если источником является локальный архив (tar, gzip), `ADD` автоматически распакует его «на лету» в целевую директорию,,,,.
    2. **Remote URL:** Позволяет скачивать файлы по прямой ссылке,,,,.
    
    - _Почему это плохо:_ Использование `ADD` для скачивания файлов из интернета — антипаттерн. Такая операция создает «тяжелый» слой, который нельзя очистить в рамках одной инструкции, в отличие от `RUN curl ... && rm ...`,.

**Пример эффективного копирования зависимостей Flask:**

```yml
# Сначала копируем только файл зависимостей для эффективного кэширования
COPY requirements.txt .
RUN pip install -r requirements.txt
# И только потом копируем весь код проекта
COPY . .
```
