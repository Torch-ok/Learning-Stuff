В процессе написания `Dockerfile` начинающие инженеры часто сталкиваются с путаницей между инструкциями, которые выполняют команды [Изучаем Docker, часть 3: файлы Dockerfile / Хабр](https://habr.com/ru/companies/ruvds/articles/439980/). Понимание того, **когда** выполняется команда и **как** она запускается ядром Linux, является критическим для обеспечения безопасности и стабильности работы нашего сквозного стека (**Nginx + Flask + PostgreSQL**) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### Разграничение зон ответственности: Сборка vs Рантаим

Главное различие кроется во времени жизни инструкции [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/):

1. **RUN** — выполняется исключительно **во время сборки** образа (`build-time`) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf). Каждая такая инструкция создает новый неизменяемый слой файловой системы, фиксируя результат выполнения команды (например, установку пакета `python3-pip`) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/). Если вы написали `RUN apt-get update`, это изменение будет «запечено» в образ навсегда [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
2. **CMD и ENTRYPOINT** — задают команду, которая выполнится **только при запуске** контейнера (`runtime`) [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/). Они не создают слоев файловой системы, а записываются в метаданные (JSON-конфигурацию) образа как инструкции для движка Docker [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### Битва форм записи: Shell vs Exec

Docker позволяет записывать эти инструкции двумя способами, которые имеют принципиально разные последствия для управления процессами [Defining start conditions for the container - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/defining-start-conditions-for-the-container).

##### 1. Shell-форма (Антипаттерн для PID 1)

Синтаксис: `CMD python app.py` [Docker-in-Practice](https://manning.com/books/docker-in-practice). В этом случае Docker запускает оболочку `/bin/sh -c`, которая уже в свою очередь запускает ваше приложение [Defining start conditions for the container - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/defining-start-conditions-for-the-container), [Docker-in-Practice](https://manning.com/books/docker-in-practice).

- **Проблема:** Внутри контейнера оболочка `sh` получает `PID 1` [Docker-in-Practice](https://manning.com/books/docker-in-practice). Она не умеет перенаправлять системные сигналы своим дочерним процессам [Docker-in-Practice](https://manning.com/books/docker-in-practice).
- **Последствия:** Когда вы вводите `docker container stop`, Docker посылает сигнал `SIGTERM` оболочке `sh` [Docker-in-Practice](https://manning.com/books/docker-in-practice). Оболочка игнорирует его, и наше **Flask**-приложение никогда не узнает о необходимости закрыть соединения. По истечении 10 секунд Docker просто «казнит» контейнер через `SIGKILL`, что может привести к повреждению данных в **PostgreSQL** [Docker-in-Practice](https://manning.com/books/docker-in-practice).

##### 2. Exec-форма (Стандарт индустрии)

Синтаксис: `CMD ["python", "app.py"]` [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/). Здесь команда записывается в виде JSON-массива. Движок Docker запускает процесс напрямую, минуя оболочку [Defining start conditions for the container - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/defining-start-conditions-for-the-container), [Docker-in-Practice](https://manning.com/books/docker-in-practice).

- **Профит:** Ваше приложение само становится процессом с `PID 1` [Docker-in-Practice](https://manning.com/books/docker-in-practice). Оно напрямую получает `SIGTERM` и может выполнить корректное завершение (**Graceful Shutdown**) [Docker-in-Practice](https://manning.com/books/docker-in-practice).

#### Совместное использование ENTRYPOINT и CMD

В 2026 году классическим паттерном является использование `ENTRYPOINT` как основы команды, а `CMD` — как набора аргументов по умолчанию [Defining start conditions for the container - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/defining-start-conditions-for-the-container), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

**Пример для нашего Flask-приложения:**

```yml
ENTRYPOINT ["python"]
CMD ["app.py"]
```

[Defining start conditions for the container - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/defining-start-conditions-for-the-container), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

Такая гибкость позволяет пользователю запустить контейнер в обычном режиме, а при необходимости — переопределить только аргументы через CLI: `docker container run flask-image --version` (контейнер выполнит `python --version` вместо `python app.py`) [Defining start conditions for the container - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/defining-start-conditions-for-the-container).

#### Вспомогательные инструкции: Метаданные и окружение

- **EXPOSE** — чисто информационная инструкция, которая документирует, на каком порту работает сервис (например, `EXPOSE 80` для Nginx) [Изучаем Docker, часть 3: файлы Dockerfile / Хабр](https://habr.com/ru/companies/ruvds/articles/439980/). Она **не открывает** порт наружу — это делает только флаг `-p` при запуске [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).
- **VOLUME** — декларирует область для хранения постоянных данных [Изучаем Docker, часть 3: файлы Dockerfile / Хабр](https://habr.com/ru/companies/ruvds/articles/439980/). Все, что попадает в эту папку внутри контейнера, будет вынесено за пределы слоистой системы CoW [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/).
- **USER** — переключает контекст исполнения [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). По умолчанию Docker работает от `root`, что небезопасно [Using a non-root user - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4/using-a-non-root-user). Хорошей практикой является создание пользователя `appuser` и переключение на него перед `CMD` [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Using a non-root user - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4/using-a-non-root-user).
- **LABEL** — позволяет вешать на образ «бирки» с информацией (версия, автор, описание) [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).
