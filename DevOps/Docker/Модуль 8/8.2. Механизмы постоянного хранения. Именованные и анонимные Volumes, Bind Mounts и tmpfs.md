Для обеспечения персистентности (постоянства) данных в 2026 году Docker предлагает три основных механизма монтирования, каждый из которых имеет свою специализацию в жизненном цикле нашего сквозного стека (**Nginx + Flask + PostgreSQL**) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf). Выбор между ними — это не вопрос вкуса, а вопрос архитектурной надежности и производительности [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

#### Глубокий анализ Volumes: Индустриальный стандарт

**Volumes** (тома) — это «первоклассные граждане» в мире Docker [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf). В отличие от других методов, тома полностью управляются движком Docker Engine и изолированы от прямого вмешательства процессов хост-системы [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

- **Механика под капотом:** В Linux-системах Docker выделяет специальную область в `/var/lib/docker/volumes/`, где хранит содержимое томов [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
- **Именованные тома (Named Volumes):** Имеют четкое имя (например, `pg_data`). Это лучший выбор для базы данных **PostgreSQL** в нашем проекте. Они легко переиспользуются, их удобно бэкапить, и они не привязаны к конкретному контейнеру [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/), [Volumes in action - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/volumes-in-action).
- **Анонимные тома (Anonymous Volumes):** При создании получают от Docker длинный случайный хэш вместо имени. Обычно они используются для временных данных, которые должны пережить перезапуск, но их сложно найти вручную на диске хоста [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

**Почему Volumes идеальны для PostgreSQL?**

1. **Безопасность прав:** Docker сам следит за тем, чтобы права доступа (permissions) внутри тома соответствовали нуждам процесса базы данных, избавляя инженера от «ада прав доступа» на хосте [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
2. **Драйверы:** Тома могут храниться не только локально, но и в облачных хранилищах (S3, Azure) через систему плагинов, что критично для масштабирования [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

#### Bind Mounts: Инструмент разработчика

**Bind Mounts** — это прямое проброс моста между любой точкой на диске вашего ноутбука и папкой внутри контейнера [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Interacting with the container via volumes and ports - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/interacting-with-the-container-via-volumes-and-ports).

**Главный юзкейс: Hot Reload для Flask** Представьте: вы правите код `app.py` в VS Code. Благодаря Bind Mount папка с исходниками на хосте синхронизирована с `/app` внутри контейнера. Flask-сервер (в режиме debug) видит изменение файла и мгновенно перезагружает приложение [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ). Вам не нужно пересобирать образ (`docker image build`) на каждую правку запятой — это экономит часы времени ежедневно [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

> [!danger] Риски безопасности Bind Mounts 
> Используя Bind Mount, вы даете контейнеру доступ к файловой системе хоста. Если запустить вредоносный контейнер от имени `root` и примонтировать `/etc` хоста в контейнер, он сможет изменить файл паролей `/etc/shadow` вашего реального сервера [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

#### tmpfs mounts: Скорость света в RAM

**tmpfs mounts** позволяют монтировать данные не на диск, а в оперативную память (RAM) хоста [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

- **Зачем это нужно:** Если нашему приложению нужно обрабатывать тысячи мелких временных сессий или кэшировать запросы, запись на диск станет «бутылочным горлышком». tmpfs обеспечивает максимально возможную скорость I/O [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).
- **Безопасность секретов:** Если в контейнере нужно хранить временный ключ расшифровки, tmpfs гарантирует, что после остановки контейнера данные физически исчезнут из памяти и никогда не останутся на диске в виде следов [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
