В методологии DevOps 2026 года управление данными выделено в отдельный инженерный домен [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/). Тома (Volumes) официально признаны «гражданами первого класса» (first-class citizens) в экосистеме Docker Engine, что означает наличие у них собственного жизненного цикла, независимого от контейнеров, и выделенного набора Management Commands для администрирования [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker_Up_and_Running].

#### Группа команд docker volume: Управление артефактами хранения

Для работы с постоянными хранилищами используется иерархическая команда `docker volume` [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker-Cookbook]. Рассмотрим основные операции на примере СУБД **PostgreSQL** из нашего проекта [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

1. **`docker volume create`** — создание именованного тома [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
    
    ```bash
    docker volume create pg_data_prod
    ```
    
    По умолчанию Docker использует драйвер `local`, который создает подкаталог для данных в `/var/lib/docker/volumes/` на Linux-хосте [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker_Up_and_Running].
    
1. **`docker volume ls`** — аудит всех существующих томов в системе [Docker_Up_and_Running], [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/). Позволяет быстро увидеть, какие драйверы используются и как называются хранилища [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker-Cookbook].
    
2. **`docker volume inspect`** — получение детальной JSON-конфигурации тома [Docker_Up_and_Running], [Docker_eBook].
    
    ```bash
    docker volume inspect pg_data_prod
    ```
    
    В выводе критически важно поле `Mountpoint` — оно указывает точный путь в файловой системе хоста, где физически лежат таблицы вашей базы данных [Docker_Up_and_Running], [Docker_eBook]. Это знание необходимо для настройки систем резервного копирования (backups) внешними средствами [Docker-in-Practice], [Volumes in action - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/volumes-in-action).
    
1. **`docker volume rm`** — ручное удаление конкретного тома [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker_eBook]. _Важно:_ Docker запретит удаление, если том в данный момент примонтирован хотя бы к одному (даже остановленному) контейнеру [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker_eBook].
    
2. **`docker volume prune`** — глобальная очистка «мусорных» томов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Изучаем Docker, часть 5: команды / Хабр](https://habr.com/ru/companies/ruvds/articles/440660/).
    
> [!warning] Опасная зона 
> Команда `prune` безвозвратно удаляет **ВСЕ** тома, которые не подключены ни к одному существующему контейнеру [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker_Up_and_Running]. Если вы временно удалили контейнер с **PostgreSQL**, планируя пересоздать его, выполнение `prune` в этот промежуток приведет к полной потере данных базы [Docker_Up_and_Running], [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).
    

#### Битва синтаксисов: -v vs --mount

При запуске контейнера через `docker container run` у инженера есть два пути монтирования данных [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

##### Старый стиль (Legacy): -v / --volume

Синтаксис объединяет все параметры в одну строку через двоеточие: `[хост]:[контейнер]:[опции]` [Docker-in-Practice], [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

```bash
docker container run -v pg_data:/var/lib/postgresql/data:ro postgres
```

**Проблема:** Если вы ошиблись в пути на хосте при использовании `bind mount`, флаг `-v` молча создаст пустую директорию от имени `root`, что часто приводит к трудноуловимым ошибкам прав доступа [Interacting with the container via volumes and ports - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/interacting-with-the-container-via-volumes-and-ports), [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

##### Современный стандарт: --mount

Флаг `--mount` использует явные пары `key=value`, что делает команду длиннее, но гораздо более читаемой и безопасной [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

```bash
docker container run --mount type=volume,source=pg_data,target=/var/lib/postgresql/data,readonly postgres
```

**Преимущества `--mount`:**

- **Строгая типизация:** Вы обязаны указать `type=volume` (управляется Docker) или `type=bind` (конкретный путь на хосте) [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).
- **Предсказуемость:** Если при `type=bind` указанного пути на хосте не существует, Docker выдаст ошибку и не запустит контейнер, предотвращая работу приложения в некорректном окружении [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).
- **Читаемость:** Флаги `readonly` или специфические опции драйверов указываются явно, а не в виде загадочных букв `ro`/`rw` в конце строки [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

#### Безопасность: Режим "Только для чтения"

Для защиты конфигурационных файлов или статики нашего фронтенда **Nginx** от случайного изменения процессом внутри контейнера, всегда используйте монтирование в режиме Read-Only [Docker-in-Practice], [Securing_Docker].

- С флагом `-v`: `:ro` [Docker-Cookbook], [Docker_Up_and_Running].
- С флагом `--mount`: `readonly` [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

Это гарантирует, что даже если злоумышленник взломает **Nginx**, он не сможет подменить `index.html` или файлы сертификатов, так как файловая система на уровне ядра будет запрещать запись в эти точки монтирования [Securing_Docker], [Docker_Up_and_Running].
