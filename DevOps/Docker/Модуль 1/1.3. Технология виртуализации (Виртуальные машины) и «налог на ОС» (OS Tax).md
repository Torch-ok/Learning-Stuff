Чтобы в полной мере оценить революцию, которую совершил Docker, нам необходимо препарировать его главного предшественника — технологию виртуализации. До появления контейнеров единственным надежным способом изолировать приложения друг от друга были **Virtual Machines** (виртуальные машины) [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/). Если представить наш сервер как земельный участок, то виртуальная машина — это строительство на нем полноценного отдельного дома с собственным фундаментом, стенами и коммуникациями [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).

#### Анатомия Виртуальной Машины и роль Hypervisor
Виртуальная машина (VM) — это программная эмуляция физического компьютера. Она «обманывает» программное обеспечение, заставляя его верить, что оно работает на реальном железе [Definitions and basic concepts - MOOC.fi courses](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts). Ключевым компонентом этой архитектуры является **Hypervisor** (гипервизор) — слой программного обеспечения, который берет на себя управление физическими ресурсами (CPU, RAM, диск) и распределяет их между виртуальными машинами [Docker и Docker Compose - Полный Курс Docker Для Начинающих с Нуля | 4 часа / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

В индустрии принято разделять гипервизоры на два фундаментальных типа:
1.  **Type 1 (Bare-metal):** Устанавливается непосредственно на физическое оборудование сервера вместо основной ОС. Примеры: **KVM**, **VMware ESXi**, **Xen**. Это стандарт для профессиональных дата-центров, обеспечивающий максимальную производительность за счет прямого доступа к железу [Docker: Up and Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Extending_Docker](https://www.packtpub.com/product/extending-docker/9781783984800).
2.  **Type 2 (Hosted):** Работает как обычное приложение внутри уже запущенной операционной системы хоста. Примеры: **Oracle VirtualBox**, **VMware Workstation**. Чаще всего используется разработчиками для тестирования разных ОС на своих ноутбуках [Docker: Up and Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

#### Глубокое погружение в «Налог на ОС» (OS Tax / VM Tax)
Главный архитектурный изъян модели VM заключается в том, что каждая машина обязана нести в себе **Guest OS** (Гостевую ОС). Это полноценная копия операционной системы, включающая собственное ядро (**Kernel**), драйверы, системные библиотеки и набор фоновых служб [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker и Docker Compose - Полный Курс Docker Для Начинающих с Нуля | 4 часа / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

Инженеры называют это явление **«налогом на ОС»** (**OS Tax**). Это колоссальный оверхед ресурсов, который мы платим просто за право изолировать одно приложение от другого [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Каждая гостевая ОС «съедает» значительную часть оперативной памяти и процессорного времени на обслуживание самой себя, еще до того, как ваше приложение будет запущено [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker QnA vijay](https://github.com/vijay/docker-qna).

#### Боль инженера: Сквозной проект в среде VM
Давайте посмотрим, как выглядел бы деплой нашего интернет-магазина (**Nginx + Flask + PostgreSQL**) в мире виртуальных машин [Docker и Docker Compose - Полный Курс Docker Для Начинающих с Нуля | 4 часа / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ). Для обеспечения безопасности и изоляции нам пришлось бы создать три независимые VM [YouTube](https://www.youtube.com/watch?v=krZ6LXNtGaU):

*   **VM 1 (Nginx):** Запускаем целую Ubuntu. Ядро грузится 1-2 минуты. Тратится 512 МБ RAM только на работу `systemd`, `syslog` и `cron`. Диск занят на 2-4 ГБ под файлы ОС [YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
*   **VM 2 (Flask):** Снова полноценная ОС. 1 ГБ RAM уходит на поддержание фоновых процессов ядра. Опять долгое ожидание загрузки [YouTube](https://www.youtube.com/watch?v=_uZQtRyF6Eg), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
*   **VM 3 (PostgreSQL):** Самая тяжелая машина. Чтобы база данных работала стабильно, мы выделяем ей 4 ГБ RAM, из которых 1.5 ГБ сразу поглощает Гостевая ОС [YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

В итоге мы имеем три независимых ядра, которые дублируют функции друг друга и воруют ресурсы у бизнеса [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Мы тратим гигабайты памяти на «обогрев атмосферы» фоновыми службами ОС, в то время как наш код Flask все еще ждет, пока ядро гостевой системы соизволит инициализировать сетевой стек [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [YouTube](https://www.youtube.com/watch?v=krZ6LXNtGaU).

> [!tip] Попробуй угадать (Математика утилизации)
> Представьте, что у вас есть мощный сервер на **16 ГБ RAM**. Вы решили использовать тяжелую корпоративную ОС в качестве гостевой, где только ядро и базовые службы (OS Tax) потребляют **2 ГБ RAM**.

<b>Задание</b>: Сколько виртуальных машин вы сможете запустить, если каждому вашему приложению (Flask, Nginx и т.д.) требуется всего по **100 МБ RAM**?</summary>
