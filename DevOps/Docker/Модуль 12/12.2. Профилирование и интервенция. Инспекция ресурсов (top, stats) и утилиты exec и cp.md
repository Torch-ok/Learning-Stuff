В 2026 году для Middle DevOps инженера инструменты мониторинга и отладки рантайма являются «глазами» и «руками», позволяющими проводить диагностику без остановки бизнес-процессов [Docker-Cookbook]. Когда агрегированные логи (из параграфа 12.1) не дают ответа на вопрос, почему наше Flask-приложение стало медленно отвечать, в дело вступают утилиты профилирования и прямого вмешательства [Docker_Up_and_Running].

#### Динамическое профилирование: docker container stats

Команда `docker container stats` предоставляет непрерывный поток данных об использовании ресурсов каждым запущенным контейнером в режиме реального времени [Docker-Cookbook], [Docker_Up_and_Running], [Docker для новичков — #1 Что такое контейнер, image, DockerHub? / Хабр](https://habr.com/ru/articles/804323/).

**Анатомия вывода:**

```bash
docker container stats flask_backend
```

Типовая таблица включает следующие метрики [Docker-Cookbook], [Docker для новичков — #1 Что такое контейнер, image, DockerHub? / Хабр](https://habr.com/ru/articles/804323/):

- **CPU %** — текущая нагрузка на ядра процессора. Аномальные скачки до 100% в нашем проекте могут сигнализировать о бесконечных циклах в коде Flask или «тяжелых» запросах к PostgreSQL [Docker_Up_and_Running], [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
- **MEM USAGE / LIMIT** — физический объем потребляемой оперативной памяти и установленный лимит (cgroups) [Docker-Cookbook]. Если показатель `MEM USAGE` постоянно растет при стабильной нагрузке — вы нашли утечку памяти (**Memory Leak**) в Python-приложении [Docker_Up_and_Running].
- **NET I/O** — объем данных, переданных и полученных по сети [Docker-Cookbook].
- **BLOCK I/O** — интенсивность чтения и записи на диск [Docker-Cookbook].

#### Инспекция процессов: docker container top

Для просмотра списка процессов, запущенных внутри конкретного контейнера, используется команда `docker container top` [Docker_Up_and_Running]. Она позволяет увидеть состояние процессов без входа в само Network/PID Namespace контейнера [Docker_Up_and_Running], [Docker QnA vijay].

**Важный нюанс PID-маппинга:** Контейнер и хост-машина используют **Shared Host Kernel** [Docker Deep Dive]. Это означает, что процесс Flask может иметь `PID 1` внутри контейнера (как основной процесс), но на хост-машине он будет виден под обычным системным `PID` (например, `4525`) [Docker_Up_and_Running], [Docker QnA vijay]. Команда `top` помогает инженеру сопоставить эти идентификаторы для глубокой отладки системными утилитами хоста [Docker_Up_and_Running].

#### Хирургическая интервенция: docker container exec

Команда `docker container exec` позволяет запустить новый процесс (например, Shell) внутри уже работающего контейнера [Docker Deep Dive], [Docker - Полный курс / YouTube], [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).

**Синтаксис для отладки:**

```bash
docker container exec -it shop_db /bin/sh
```

Здесь флаг `-it` (interactive + tty) подключает ваш терминал к оболочке внутри контейнера базы данных [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).

> [!warning] Опасная привычка 
> В DevOps-культуре 2026 года ручная правка конфигурационных файлов или кода через `exec` считается грубейшим нарушением концепции **Immutable Infrastructure** (неизменяемой инфраструктуры) [Docker Deep Dive], [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). Все «ручные» изменения будут безвозвратно удалены при перезапуске или обновлении контейнера [Chapter 3: Building and configuring environments - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3). Используйте `exec` только для диагностики (проверка доступности портов, путей) [Docker Deep Dive].

#### Копирование артефактов: docker container cp

Утилита `docker container cp` является мостом между файловой системой хоста и изолированной средой контейнера [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker-Cookbook].

**Сценарии эксплуатации:**

1. **Извлечение дампов:** Если база данных упала с ошибкой, вы можете вытащить аварийный дамп или лог из `/var/lib/postgresql/data` на хост для внешнего анализа [Docker-Cookbook]. `docker container cp shop_db:/var/log/postgresql/error.log ./error.log`
2. **Доставка отладочных скриптов:** Вы можете пробросить временный диагностический скрипт внутрь Flask-контейнера без пересборки всего образа [Docker-Cookbook]. `docker container cp ./diag_tool.py flask_app:/tmp/diag_tool.py`
