В экосистеме Docker образ — это не просто статичный файл, а перемещаемый артефакт, чей жизненный цикл охватывает этапы от написания первой строчки `Dockerfile` до доставки на боевой сервер [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Чтобы эффективно управлять нашей инфраструктурой (будь то бэкенд на **Flask** или база данных **PostgreSQL**), инженер должен виртуозно владеть командами управления образами и понимать логику их именования [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### Анатомия полного имени образа

В 2026 году стандарт именования образа следует строгому иерархическому пути, который позволяет движку Docker однозначно идентифицировать ресурс в глобальной сети [Chapter 2: Introduction to Containers - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts):

`registry.domain.com/repository-name/image-name:tag`

- **Registry (Host):** Адрес сервера реестра (например, `ghcr.io` или `my-private-reg.com`). Если этот блок опущен, Docker по умолчанию обращается к Docker Hub (`index.docker.io`) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
- **Repository (Namespace):** Пространство имен или организация. В Docker Hub официальные образы живут в пространстве `library` (которое часто сокращается до `_`), а пользовательские — под именами их владельцев [Chapter 2: Introduction to Containers - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
- **Image Name:** Непосредственно название приложения (например, `flask-backend`).
- **Tag:** Метка версии или варианта сборки [Docker для новичков — #1 Что такое контейнер, image, DockerHub? / Хабр](https://habr.com/ru/articles/804323/).

> [!important] Поведение по умолчанию 
> Если при выполнении команд `pull`, `build` или `run` вы не укажете тег явно, Docker автоматически подставит значение `:latest` [Chapter 2: Introduction to Containers - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/). Если в репозитории нет образа с такой меткой, команда завершится с ошибкой [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

#### Основные управляющие команды

1. **`docker image build`** — процесс «выпекания» образа из инструкций `Dockerfile` [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
    
    - Синтаксис: `docker image build -t my-app:1.0 .`
    - Флаг `-t` (tag) задает имя и тег [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).
    - Точка `.` в конце указывает на **Build Context** (контекст сборки) — директорию, файлы из которой будут доступны для копирования в образ [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
2. **`docker image pull`** — скачивание слоев образа из удаленного реестра [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf). Слои скачиваются параллельно для ускорения процесса [Chapter 2: Introduction to Containers - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-2/definitions-and-basic-concepts).
    
3. **`docker image push`** — загрузка вашего локального образа в реестр [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf). Для выполнения требуется предварительная авторизация через `docker login` [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
    
4. **`docker image tag`** — создание «псевдонима» (ссылки) для уже существующего образа [Docker-in-Practice](https://manning.com/books/docker-in-practice). Эта команда не создает копию данных на диске, она лишь создает новую метку, указывающую на тот же самый Image ID [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).
    

#### Коварство тега :latest и стратегия версионирования

Использование `:latest` в реальном продакшене — это критический антипаттерн и «мина замедленного действия» [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

**Почему это опасно?**

- **Недетерминированность:** Тег `:latest` является «плавающим» (floating). Сегодня он указывает на одну версию **PostgreSQL**, а завтра мейнтейнер обновит его до новой мажорной версии, которая несовместима с вашими данными [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
- **Рассинхронизация сред:** При деплое на разные серверы один может скачать «старый» `:latest`, а второй — «новый», что приведет к непредсказуемым ошибкам в кластере [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

**Как делать правильно:**

- **SemVer (Семантическое версионирование):** Использование четких версий, например `flask-app:1.2.4` [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
- **Хэш коммита:** Тегирование образа коротким SHA-хэшем из Git (например, `flask-app:a3f8c1d`), что позволяет мгновенно понять, какой именно код находится внутри контейнера [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
- **Pinned Digests (SHA-256):** Ссылка на уникальный криптографический хэш контента образа (`image@sha256:...`), что гарантирует 100% идентичность образа навсегда [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).

#### Практический кейс: Подготовка Flask-приложения к деплою

Представим, что мы собрали образ нашего бэкенда локально и хотим отправить его в приватный корпоративный реестр компании.

```bash
# 1. Собираем образ с локальным тегом
docker image build -t my-flask-app:v1.0 .

# 2. Создаем алиас (тег), включающий адрес приватного реестра
# Синтаксис: docker image tag <текущее_имя> <новое_полное_имя>
docker image tag my-flask-app:v1.0 registry.corp.com/backend/flask-prod:1.0-a3f8c1d

# 3. Отправляем образ в реестр
docker image push registry.corp.com/backend/flask-prod:1.0-a3f8c1d
```
