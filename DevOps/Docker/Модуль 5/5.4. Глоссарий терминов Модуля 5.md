Ниже приведен перечень ключевых терминов, описывающих структуру и жизненный цикл образов в экосистеме Docker в соответствии со стандартами 2026 года.

- **Immutable Layers** — неизменяемые слои образа, представляющие собой зафиксированные наборы изменений файловой системы; один раз созданный слой никогда не меняется, что позволяет эффективно переиспользовать его в других образах [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf), [Изучаем Docker, часть 2: термины и концепции / Хабр](https://habr.com/ru/companies/ruvds/articles/439978/).
- **Container Layer (Read-Write)** — временный, тонкий записываемый слой, который создается поверх стека Read-Only слоев при запуске контейнера; в нем хранятся все изменения, произведенные во время работы приложения [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).
- **Image Tag** — текстовая метка-идентификатор, указывающая на конкретную версию или вариант образа внутри репозитория (например, `:3.11-slim`) [Docker для новичков — #1 Что такое контейнер, image, DockerHub? / Хабр](https://habr.com/ru/articles/804323/), [Изучаем Docker, часть 2: термины и концепции / Хабр](https://habr.com/ru/companies/ruvds/articles/439978/).
- **Semantic Versioning (SemVer)** — методология версионирования в формате `MAJOR.MINOR.PATCH`, обеспечивающая предсказуемость обновлений и совместимость зависимостей [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
- **Docker Registry** — серверная инфраструктура (публичная или приватная) для хранения, каталогизации и дистрибуции образов Docker [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/), [Изучаем Docker, часть 2: термины и концепции / Хабр](https://habr.com/ru/companies/ruvds/articles/439978/).
- **Image Manifest** — JSON-документ, содержащий описание структуры образа: список слоев, их хэши и конфигурационные метаданные [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491917565/).
- **Layer SHA-хэш (Digest)** — уникальный криптографический идентификатор содержимого слоя или всего образа в целом, гарантирующий детерминированность сборки и защиту от подмены данных [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для начинающих: что это такое и как пользоваться / Хабр](https://habr.com/ru/companies/netologyru/articles/967546/).

## Практическое упражнение (Инженерный аудит образов Модуля 5)

**Сценарий «Наследие старого бэкенда»:** Вы пришли на проект, где предыдущий DevOps-инженер уволился, не оставив ни документации, ни исходных `Dockerfile`. Вам достался только готовый образ в локальном хранилище под именем `legacy-backend:latest`. Ваша задача — провести «рентгеновское исследование» этого артефакта, чтобы понять, как он устроен и можно ли его оптимизировать [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).

**Задание:**

1. Восстановите логику сборки: выясните, сколько слоев в образе и какая инструкция создала самый «тяжелый» слой.
2. Извлеките конфигурацию: определите, какие переменные окружения зашиты в образ, какой порт ожидает приложение и какая команда (бинарный файл) запускается при старте контейнера [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker_up_and_running/9781492036739/).

---

**Пошаговое решение и разбор:**

**Шаг 1: Анализ истории слоев** Для восстановления шагов сборки используем Management Command `history`:

```bash
docker image history legacy-backend:latest
```

**Анализ вывода:** В колонке `SIZE` вы ищете самое большое значение (например, 450 МБ). В колонке `CREATED BY` вы увидите соответствующую команду (например, `RUN apt-get update && apt-get install -y heavy-lib...`). Это позволит понять, на каком этапе образ «раздулся» и где не была произведена очистка кэша [Изучаем Docker, часть 4: уменьшение размеров образов и ускорение их сборки / Хабр](https://habr.com/ru/companies/ruvds/articles/440658/), [Docker Deep Dive Zero to Docker in a single book (Nigel Poulton)](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf/Docker Deep Dive Zero to Docker in a single book (Nigel Poulton) (z-lib.org).pdf).

**Шаг 2: Глубокая инспекция метаданных** Используем команду `inspect` с фильтрацией через Go-шаблоны для вытягивания ключевых параметров:

- **Переменные окружения:** `docker image inspect --format '{{json .Config.Env}}' legacy-backend:latest` [Docker_eBook](https://zzzprojects.com/docker-ebook).
- **Порты и команда запуска:** `docker image inspect --format 'Port: {{.Config.ExposedPorts}} | Entrypoint: {{.Config.Entrypoint}}' legacy-backend:latest` [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker_up_and_running/9781492036739/).

**Результат аудита:** Благодаря этим командам вы получаете полный «паспорт» приложения без необходимости запускать его и рисковать стабильностью системы [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
