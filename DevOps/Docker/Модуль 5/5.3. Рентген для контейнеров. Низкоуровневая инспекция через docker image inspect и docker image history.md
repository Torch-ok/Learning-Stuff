Профессиональная эксплуатация Docker в 2026 году требует от инженера умения проводить глубокий аудит артефактов без их фактического запуска. Прежде чем развернуть наш стек (**Nginx + Flask + PostgreSQL**) на боевом сервере, мы должны убедиться, что образ не содержит лишних данных, порты описаны корректно, а переменные окружения настроены согласно спецификации безопасности [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). Для этих целей движок Docker предоставляет два мощных инструмента низкоуровневого анализа: `inspect` и `history`.

#### Глубокий анализ через docker image inspect

Команда `docker image inspect` возвращает детальный JSON-документ, который является «паспортом» образа. В нем содержится абсолютно вся информация о конфигурации, начиная от архитектуры процессора и заканчивая криптографическими хэшами файловых слоев [Docker_Up_and_Running], [Docker_eBook].

**Структура JSON-ответа (ключевые секции):**

- **`Config.Env`:** Список переменных окружения, которые будут доступны нашему приложению **Flask** или базе **PostgreSQL** при старте [Docker_Up_and_Running].
- **`Config.ExposedPorts`:** Метаданные о портах, которые разработчик пометил как рабочие (например, `80/tcp` для Nginx) [Docker_eBook].
- **`Config.Cmd` и `Config.Entrypoint`:** Команды по умолчанию, которые инициируют запуск изолированного процесса [Docker_Up_and_Running].
- **`RootFS.Layers`:** Массив SHA256-хэшей всех Read-Only слоев, из которых собран образ. Это позволяет сопоставить логическую структуру образа с физическими данными на диске [Docker Deep Dive].
- **`Labels`:** Пользовательские метаданные (версия, мейнтейнер, описание), добавленные через инструкцию `LABEL` в Dockerfile [Docker Fundamentals: теория и базовая эксплуатация / Хабр].

**Мастерство фильтрации через Go-шаблоны:** JSON-вывод может достигать сотен строк. Чтобы не искать нужный параметр вручную, используйте флаг `--format` (или `-f`), поддерживающий синтаксис Go-шаблонов [Docker_eBook].

```bash
# Вытянуть только хэши слоев образа PostgreSQL
docker image inspect --format '{{json .RootFS.Layers}}' postgres:16-alpine

# Узнать, какая команда назначена точкой входа во Flask-приложении
docker image inspect -f '{{.Config.Entrypoint}}' flask-app:latest
```

[Docker_eBook], [Docker-Cookbook].

#### Реконструкция сборки через docker image history

Если `inspect` показывает состояние «здесь и сейчас», то `docker image history` — это «машина времени», позволяющая увидеть, как именно «выпекался» этот слоеный пирог [Docker Deep Dive].

**Зачем это нужно инженеру?**

1. **Поиск «раздутости»:** В колонке `SIZE` вы можете увидеть объем данных, добавленных каждым шагом. Если вы видите, что слой с `RUN apt-get update` весит 200 МБ, значит, инженер забыл очистить кэш пакетного менеджера командой `rm -rf /var/lib/apt/lists/*`, что является грубой ошибкой [Изучаем Docker, часть 4: уменьшение размеров образов и ускорение их сборки / Хабр](https://habr.com/ru/companies/ruvds/articles/440658/).
2. **Аудит инструкций:** Колонка `CREATED BY` содержит текст инструкции Dockerfile (иногда в сокращенном виде), которая породила данный слой [Docker Deep Dive].
3. **Безопасность:** Вы можете отследить, не были ли в образ запечены чувствительные данные (пароли, ключи) на промежуточных этапах сборки, так как они навсегда остаются в истории слоев [Docker-in-Practice].

**Пример вывода для Nginx:**

```text
IMAGE          CREATED BY                                      SIZE      COMMENT
<ID>           /bin/sh -c #(nop)  CMD ["nginx" "-g" "daemon…   0B  
<ID>           /bin/sh -c #(nop)  EXPOSE 80                    0B  
<ID>           /bin/sh -c apt-get update && apt-get install…   55MB  
<ID>           /bin/sh -c #(nop)  ADD file:62400a49cced0d75…   78MB  
```

[Docker_Up_and_Running], [Docker-in-Practice].

Обратите внимание: инструкции, меняющие только метаданные (`EXPOSE`, `CMD`, `ENV`), всегда имеют размер `0B` в выводе истории, так как они не меняют файловую систему, а лишь записываются в конфигурационный JSON [Docker Deep Dive].
