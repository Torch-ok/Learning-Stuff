В архитектуре защищенных систем 2026 года управление секретами (паролями, токенами, SSL-сертификатами) выделено в отдельную критическую дисциплину DevSecOps [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/). Для Middle DevOps инженера использование переменных окружения для передачи чувствительных данных является признаком «технического долга» и серьезной брешью в безопасности [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-in-Practice](https://manning.com/books/docker-in-practice).

#### Уязвимость ENV: Почему переменные окружения небезопасны

Долгое время стандартом было использование инструкций `ENV` в Dockerfile или секции `environment` в Compose [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Однако этот метод имеет фатальные недостатки:

- **Прозрачность для инспекции:** Любой пользователь, имеющий доступ к Docker API, может выполнить `docker container inspect` и увидеть пароли в открытом виде в секции `Config.Env` [Docker QnA vijay](https://github.com/vijay/docker-qna), [passing secret data to a running container - Docker eBook](https://zzzprojects.com/docker-ebook).
- **Утечки в логи:** Переменные окружения часто дублируются в логи дочерних процессов или системные отчеты об ошибках, что приводит к компрометации данных через системы мониторинга [Docker-in-Practice](https://manning.com/books/docker-in-practice), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).
- **Наследование:** Секреты, заданные через `ENV` в базовом образе, сохраняются во всех дочерних слоях и образах, становясь доступными любому, кто скачает ваш образ из реестра [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).

#### Механика Docker Secrets: Секреты в оперативной памяти

Механизм **Docker Secrets**, изначально разработанный для режима Swarm, в 2026 году является нативным и рекомендуемым способом управления данными и в обычном Docker Compose [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).

**Физика процесса под капотом:**

1. Секреты определяются как объекты «первого класса» в API Docker [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).
2. При запуске контейнера Docker создает временную файловую систему в оперативной памяти (**tmpfs**) и монтирует секрет как текстовый файл по пути `/run/secrets/<secret_name>` (на Linux) [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).
3. Данные никогда не записываются на физический диск контейнера и не сохраняются в его RW-слое [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).
4. Как только контейнер останавливается, виртуальная файловая система в RAM уничтожается, не оставляя следов пароля [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).

#### Практика: Настройка compose.yaml с использованием Secrets

Перепишем манифест нашего сквозного проекта (Flask + PostgreSQL) для безопасной работы [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/), [Docker networking - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/docker-networking).

```yml
name: secure-web-app

services:
  database:
    image: postgres:16-alpine
    # Вместо POSTGRES_PASSWORD используем версию для чтения из файла
    environment:
      - POSTGRES_PASSWORD_FILE=/run/secrets/db_password
    secrets:
      - db_password
    networks:
      - backend_net

  backend:
    build: ./app
    secrets:
      - db_password
    environment:
      - DB_PASSWORD_PATH=/run/secrets/db_password
    networks:
      - backend_net
      - frontend_net

# Декларация локальных источников секретов
secrets:
  db_password:
    file: ./configs/db_password.txt

networks:
  frontend_net:
  backend_net:
```

#### Архитектурная рекомендация для приложения

Современные облачные приложения должны следовать паттерну «Config as a File» [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Twelve-Factor App - Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/). Наш Flask-бэкенд должен инициализировать соединение следующим образом:

```python
import os

def get_secret(secret_name):
    # Пытаемся прочитать путь из переменной или используем стандартный путь Docker
    path = os.getenv(f"{secret_name.upper()}_PATH", f"/run/secrets/{secret_name}")
    try:
        with open(path, 'r') as secret_file:
            return secret_file.read().strip()
    except IOError:
        return None

db_password = get_secret("db_password")
```

[Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/). Этот подход гарантирует, что даже если злоумышленник получит доступ к окружению процесса, он увидит лишь путь к файлу, а не сам пароль [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/).
