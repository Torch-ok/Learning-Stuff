В эшелонированной обороне контейнеризированных систем 2026 года блокировка записи в файловую систему контейнера является одним из самых эффективных методов противодействия взлому [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/). Для Middle DevOps инженера концепция **Immutable Infrastructure** (неизменяемой инфраструктуры) должна распространяться не только на образы, но и на состояние контейнера в процессе его выполнения (runtime) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

#### Анатомия атаки: Компрометация изменяемого слоя

Как мы изучили в Модуле 5, каждый контейнер обладает индивидуальным **Read-Write / Container layer** [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). По умолчанию этот слой позволяет процессу изменять любые файлы, унаследованные из образа, и создавать новые [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

**Паттерн типичной атаки на наш сквозной проект:**

1. Злоумышленник находит уязвимость в коде **Flask** (например, через некорректную обработку загрузки файлов или удаленное выполнение кода — RCE) [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/).
2. Используя права процесса (даже если это non-root пользователь), он загружает вредоносный скрипт `.sh` или заменяет системный бинарный файл во внутреннем каталоге `/app` [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
3. После этого атакующий может закрепиться в системе, превратив контейнер в «плацдарм» для сканирования внутренней сети **backend_net** и атаки на **PostgreSQL** [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/).

Метафора инженера: Представьте здание, где стены сделаны из пластилина. Любой посетитель может вылепить в стене потайную дверь. **Read-only rootfs** превращает этот пластилин в монолитный бетон [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

#### Механизм блокировки: флаг --read-only

Для полной изоляции файловой системы в 2026 году используется флаг `--read-only` в CLI или директива `read_only: true` в манифесте [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

При активации этого режима ядро Linux через механизмы **Storage Driver** (например, `overlay2`) полностью блокирует запись в верхний слой контейнера [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/). Любая попытка создать файл или изменить существующий завершится системной ошибкой `Read-only file system` [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781491917565/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/). Это гарантирует, что контейнер останется в точности таким, каким он был собран в образе [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### DevOps-боль: Почему приложения падают?

Проблема в том, что современное ПО не привыкло к абсолютному запрету на запись [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).

- **Nginx** должен писать кэши в `/var/cache/nginx` и создавать PID-файл процесса в `/var/run` [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/).
- **Flask** (особенно в режиме отладки) может пытаться писать временные файлы сессий или Python-байткод в `/tmp` [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
- **PostgreSQL** вообще не запустится без возможности писать в свои системные каталоги [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

Без дополнительных настроек выполнение `docker container run --read-only nginx` приведет к мгновенному падению процесса с ошибкой инициализации [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/).

#### Решение: Комбинация Read-only и tmpfs

Золотой стандарт Middle DevOps инженера — заблокировать всю систему, но точечно «прорезать» отверстия для записи там, где это необходимо, используя оперативную память (**tmpfs**) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

**Эталонная конфигурация в compose.yaml:**

```yml
services:
  gateway:
    image: nginx:latest
    read_only: true # Корневая система заблокирована
    tmpfs:
      - /var/cache/nginx
      - /var/run
      - /var/log/nginx
    ports:
      - "80:80"

  backend:
    image: flask-app:latest
    read_only: true
    tmpfs:
      - /tmp # Временные файлы Flask теперь живут в RAM
      - /app/logs
    environment:
      - APP_ENV=production
```

[Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/), [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).

**Почему это безопасно?**

1. Все изменения, которые Flask или Nginx внесут в `/tmp` или `/var/run`, находятся в оперативной памяти [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/). При остановке контейнера они гарантированно исчезают [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).
2. Злоумышленник не может подменить бинарный файл Flask в `/app`, так как основная файловая система остается Read-Only на уровне ядра [Securing_Docker](https://www.packtpub.com/product/securing-docker/9781785281648/), [Docker_Up_and_Running](https://www.oreilly.com/library/view/docker-up-running/9781491917565/).
