#### Анатомия команд жизненного цикла стека

Управление жизненным циклом через Compose строится на принципе соответствия между файлом `compose.yaml` и реальным состоянием объектов в Docker Engine [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).

1. **`docker compose up` — Приведение к желаемому состоянию** Это самая мощная команда оркестратора. Она не просто «запускает» контейнеры, она анализирует манифест и последовательно создает сети, тома и сервисы [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
    
    - **Флаг `-d` (Detached):** Запускает стек в фоновом режиме, освобождая терминал для дальнейшей работы [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
    - **Smart Recreation (Умное пересоздание):** Compose обладает интеллектом. Если вы изменили конфигурацию только для **Nginx** в YAML-файле, то при повторном вызове `up` оркестратор увидит, что **PostgreSQL** и **Flask** не затронуты изменениями, и оставит их работать, пересоздав только контейнер фронтенда [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
2. **`docker compose down` — Тотальная зачистка** Команда останавливает и полностью удаляет контейнеры и сети, созданные проектом [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
    
    - **Флаг `-v` (Volumes):** По умолчанию `down` не трогает именованные тома, чтобы вы не потеряли данные базы данных [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Использование `docker compose down -v` удаляет абсолютно всё, включая персистентные данные в `volumes` [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ), [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/). Это критически полезно для очистки анонимных томов-мусора, но смертельно опасно для продакшен-баз [Изучаем Docker, часть 6: работа с данными / Хабр](https://habr.com/ru/companies/ruvds/articles/441574/).
3. **`docker compose build` — Контроль над сборкой** Если ваши сервисы (например, Flask-бэкенд) используют директиву `build: .`, то Compose соберет образы автоматически при первом запуске `up` [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Однако, если вы внесли изменения в `Dockerfile` или исходный код, Docker может переиспользовать старый кэш. Команда `docker compose build --no-cache` принудительно заставит оркестратор пересобрать все артефакты с чистого листа [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
    

#### Инструментарий отладки и мониторинга (Observability)

Middle DevOps инженер не заходит в каждый контейнер по отдельности. Он наблюдает за стеком через агрегированные команды [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo).

- **`docker compose logs -f`:** Агрегирует потоки `STDOUT`/`STDERR` от всех контейнеров проекта в один экран [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Каждая строчка лога помечена цветом и именем сервиса (например, `nginx_1 | ...`, `db_1 | ...`), что позволяет мгновенно понять, падает ли Flask из-за того, что Postgres еще не проснулся [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
- **`docker compose ps`:** Показывает статус процессов именно внутри текущего проекта: какие порты маппятся на хост и каково состояние Healthcheck-проверок [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
- **`docker compose top`:** Отображает список работающих процессов внутри каждого контейнера стека, что помогает выявить «зависшие» или зомби-процессы без выхода из контекста Compose [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
- **`docker compose exec [service] [command]`:** Позволяет выполнить команду внутри конкретного сервиса [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo). В отличие от обычного `docker exec`, здесь не нужно знать `Container ID` — достаточно имени сервиса из YAML-файла (например, `docker compose exec db psql -U postgres`) [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).
