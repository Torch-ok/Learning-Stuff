Ниже приведен свод фундаментальных терминов оркестрации, определяющих методологию работы с Docker Compose в стандартах 2026 года.

- **Infrastructure as Code (IaC)** — концепция управления IT-инфраструктурой, при которой описание сетей, томов и сервисов хранится в виде кода (файлов конфигурации), что позволяет версионировать состояние системы в Git и гарантировать её воспроизводимость [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
- **Declarative Approach (Декларативный подход)** — метод настройки, при котором инженер описывает «что» должно быть получено в итоге (конечное состояние), а инструмент (Compose) самостоятельно вычисляет последовательность действий для достижения этой цели [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
- **Compose Project (Проект Compose)** — логическая группа ресурсов (контейнеров, сетей, томов), объединенных общим манифестом и префиксом имени, который по умолчанию совпадает с названием директории проекта [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf).
- **Service Dependency (Зависимость сервисов)** — установленная в манифесте связь между компонентами системы, определяющая порядок их запуска и условия готовности (например, бэкенд не стартует без работающей БД) [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
- **Healthcheck Condition (Условие проверки здоровья)** — расширенный параметр зависимости, позволяющий Compose дожидаться не просто старта контейнера, а успешного выполнения внутреннего теста приложения (статус `healthy`) [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/).
- **Environment Precedence (Приоритет окружения)** — жестко заданная в Docker Engine иерархия источников конфигурации, определяющая, какое значение переменной будет использовано при наличии конфликтов между `.env`, разделом `environment` и переменными хоста [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
- **Recreation Logic (Логика пересоздания)** — интеллектуальный механизм Smart Recreation, при котором `docker compose up` анализирует изменения в коде или конфигах и перезапускает только те сервисы, которые были затронуты, не беспокоя остальную часть стека [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

## Практическое упражнение (Сборка полноценного продакшен-манифеста compose.yaml для трехкомпонентного стека)

**Инженерная задача:** Вам необходимо спроектировать отказоустойчивую среду для интернет-магазина. Архитектура должна соответствовать принципам «сетевой матрешки» (изоляция БД) и гарантировать корректный запуск зависимых сервисов [9.3. Администрирование сетей], [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4).

Ниже представлен эталонный манифест `compose.yaml` (стандарт 2026 г.) с детальным разбором каждой секции [Migrating to Docker Compose - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/migrating-to-docker-compose), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).

```yml
# Имя проекта для изоляции ресурсов в Docker Engine
name: production-shop

services:
  # 1. Слой хранения: PostgreSQL
  database:
    image: postgres:16-alpine
    # Используем env_file для безопасности (пароли не в коде)
    env_file: .env
    networks:
      - backend_net
    volumes:
      - db-data:/var/lib/postgresql/data
    # Критично: проверка готовности БД принимать TCP-соединения
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER:-postgres}"]
      interval: 5s
      timeout: 5s
      retries: 5
      start_period: 10s

  # 2. Слой логики: Flask Backend
  backend:
    build:
      context: ./app
      dockerfile: Dockerfile
    env_file: .env
    # Flask находится в двух сетях: видит БД и виден прокси-серверу
    networks:
      - backend_net
      - frontend_net
    # Интеллектуальная зависимость: ждем статус Healthy от БД
    depends_on:
      database:
        condition: service_healthy

  # 3. Слой входа: Nginx Proxy
  gateway:
    image: nginx:latest
    ports:
      - "80:80" # Единственный порт, торчащий наружу на хост
    networks:
      - frontend_net
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    # Прокси зависит от наличия бэкенда
    depends_on:
      - backend

# Определение изолированных топологий
networks:
  frontend_net:
    driver: bridge
  backend_net:
    # internal: true можно добавить для запрета выхода БД в интернет
    driver: bridge

# Определение персистентного хранилища
volumes:
  db-data:
```
