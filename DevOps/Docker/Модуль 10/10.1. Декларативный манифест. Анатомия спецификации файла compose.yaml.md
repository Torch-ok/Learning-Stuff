В современной практике DevOps 2026 года управление инфраструктурой через разрозненные команды терминала считается устаревшим и подверженным ошибкам подходом [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ). На смену ему пришел декларативный подход, реализованный в инструменте **Docker Compose** [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).

#### От императивного хаоса к декларативному порядку

Для Middle DevOps инженера переход на Docker Compose означает фундаментальную смену парадигмы [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo):

1. **Императивный подход (CLI):** Вы даете Docker конкретные команды «как сделать»: `docker container run`, `docker network create`, `docker volume create` [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Порядок этих команд, порты и связи приходится держать в голове или записывать в сложные bash-скрипты, которые трудно поддерживать [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker-in-Practice](https://manning.com/books/docker-in-practice).
2. **Декларативный подход (Compose):** Вы описываете в текстовом файле «что вы хотите получить» — конечное состояние системы [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdfr%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf). Этот файл является реализацией концепции **Infrastructure as Code (IaC)**: ваша инфраструктура (сети, тома, сервисы) теперь версионируется вместе с программным кодом в Git [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-in-Practice](https://manning.com/books/docker-in-practice).

#### Эволюция спецификации: от docker-compose.yml к compose.yaml

За годы существования Docker Compose прошел путь от внешней утилиты (изначально называвшейся Fig) до части основного движка Docker [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker-Cookbook](https://www.oreilly.com/library/view/docker-cookbook/9781491919712/).

- **Legacy:** Традиционное имя файла `docker-compose.yml` (или `.yaml`) [Chapter 3: Building and configuring environments - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
- **Стандарт 2026:** Согласно актуальной спецификации Compose, предпочтительным именем является лаконичное `compose.yaml` [Migrating to Docker Compose - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/migrating-to-docker-compose), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).

> [!warning] Актуализация синтаксиса 
> В старых источниках поле `version: '3'` на первой строке было обязательным для определения API [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). В современной спецификации (Compose Spec) это поле стало опциональным; Docker Engine 2026 года автоматически определяет версию синтаксиса, отдавая приоритет самым новым стандартам [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).

#### Анатомия корневых разделов манифеста

Файл `compose.yaml` имеет четкую иерархическую структуру, разделенную на функциональные блоки [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/):

1. **`services` (Сервисы):** Описывают контейнеры как логические единицы приложения [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Каждый сервис определяет образ, правила сборки, проброс портов и переменные окружения [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker by federico](https://federico.com/docker-by-federico).
2. **`networks` (Сети):** Позволяют проектировать изолированные сетевые топологии на уровне проекта [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Все контейнеры в рамках одного Compose-проекта по умолчанию попадают в общую сеть и могут находить друг друга по именам сервисов через встроенный DNS [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker networking - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/docker-networking).
3. **`volumes` (Тома):** Раздел для централизованного описания именованных томов [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Это обеспечивает персистентность данных (например, для PostgreSQL), которые переживают удаление контейнеров [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ), [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
4. **`secrets` (Секреты):** Механизм безопасного монтирования чувствительных данных [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). В отличие от переменных окружения, секреты монтируются в контейнер в режиме `readonly` как файлы, что снижает риск их утечки через логи или инспекцию процесса [Docker Deep Dive](obsidian://open?vault=DevOps&file=Sources%2FDocker%2FPdf%2FDocker%20Deep%20Dive%20Zero%20to%20Docker%20in%20a%20single%20book%20(Nigel%20Poulton)%20(z-lib.org).pdf), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).

#### Структура и важность отступов YAML

Формат YAML критически чувствителен к отступам (обычно используется **два пробела** на уровень) [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Нарушение вложенности сделает файл невалидным [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo), [Docker by federico](https://federico.com/docker-by-federico).

**Пример эталонного пустого манифеста:**

```yml
# Имя проекта может задаваться через name (стандарт 2026)
name: my-web-shop

services:
  # Название сервиса — это имя хоста в сети проекта
  flask-app:
    # Описание контейнера
    build: .

  postgres-db:
    image: postgres:16-alpine

networks:
  # Проектирование сетей
  frontend:
  backend:

volumes:
  # Описание томов для БД
  db-data:

secrets:
  # Безопасное хранение пароля
  db-password:
    file: ./db_pass.txt
```
