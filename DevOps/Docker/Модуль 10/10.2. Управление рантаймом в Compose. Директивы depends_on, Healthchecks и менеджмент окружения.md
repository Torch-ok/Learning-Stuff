Запуск многокомпонентной системы (Nginx + Flask + PostgreSQL) требует от инженера не просто умения поднять контейнеры, но и понимания их взаимозависимостей на уровне прикладных протоколов [Docker - Полный курс / YouTube](https://www.youtube.com/watch?v=RLfWakY-Ueo). В этом параграфе мы разберем, как превратить разрозненную группу контейнеров в интеллектуально координируемую систему, способную самостоятельно определять свою готовность к работе [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4).

#### Директива depends_on: Ловушка "старта процесса"

Чаще всего Middle DevOps инженеры сталкиваются с тем, что их Flask-приложение падает сразу после запуска с ошибкой `Connection Refused` при попытке достучаться до базы данных [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4).

**Проблема:** Базовый синтаксис `depends_on` гарантирует только **порядок запуска контейнеров**, но не готовность приложения внутри них [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4), [Docker QnA vijay](https://github.com/vijay/docker-qna).


#### АНТИПАТТЕРН:Flask запустится сразу за Postgres, не дожидаясь инициализации таблиц

```yml
services:
  flask-app:
    depends_on:
      - postgres-db
``` 
[Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4)

Под капотом: Движок Docker видит, что процесс `dockerd` успешно стартовал бинарный файл PostgreSQL. Для Docker контейнер уже в статусе `Up` [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). Однако самой базе требуется еще 5–10 секунд, чтобы инициализировать файловую систему и начать слушать порт 5432 [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4). В этот промежуток Flask совершает попытку подключения и аварийно завершается [Chapter 4: Basics of Container Orchestration - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-4).

#### Связка Healthcheck и depends_on: Условие готовности
Стандарт 2026 года — использование расширенного синтаксиса `depends_on` с условием `condition: service_healthy` [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/). Чтобы это заработало, в сервисе базы данных должен быть описан механизм самодиагностики — `healthcheck` [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/).

**Пример для PostgreSQL и Flask:**
```yaml
services:
  postgres-db:
    image: postgres:16-alpine
    healthcheck:
      # pg_isready — встроенная утилита Postgres для проверки статуса
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s   # Как часто проверять
      timeout: 5s    # Сколько ждать ответа
      retries: 5     # Кол-во попыток до статуса unhealthy
      start_period: 10s # Время на начальную инициализацию

  flask-app:
    build: ./app
    depends_on:
      postgres-db:
        condition: service_healthy # Flask ждет, пока Postgres скажет "Я готов!"
````

[Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker для новичков — #2 Все инструкции Dockerfile / Хабр](https://habr.com/ru/articles/804325/).

В такой конфигурации Docker Compose не начнет запуск Flask, пока контейнер `postgres-db` не пройдет проверку `pg_isready` и не получит статус `healthy` в выводе `docker compose ps` [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/), [Docker и Docker Compose - Полный Курс / YouTube](https://www.youtube.com/watch?v=n9uCgUzfeRQ).

#### Менеджмент окружения: Правила приоритетов

Docker Compose предлагает два основных пути передачи настроек (порты, пароли, ключи) [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/):

1. **Секция `environment`:** Переменные жестко прописаны в `compose.yaml` [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Удобно для общих настроек, но небезопасно для паролей, так как они попадают в Git [Docker Fundamentals: теория и базовая эксплуатация / Хабр](https://habr.com/ru/companies/ruvds/articles/1043544/).
2. **Секция `env_file`:** Загрузка переменных из внешнего файла (обычно `.env`) [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/). Это стандарт для хранения секретов, которые добавляются в `.dockerignore` [Migrating to Docker Compose - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/migrating-to-docker-compose).

**Иерархия приоритетов (сверху вниз):** Если одна и та же переменная определена в нескольких местах, Docker Engine разрешает конфликт по следующей схеме [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/):

- **1 место (Высший приоритет):** Блок `environment` непосредственно в `compose.yaml` [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
- **2 место:** Переменные, загруженные через `env_file` [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
- **3 место:** Переменные окружения самой хост-машины или определенные в `Dockerfile` через `ENV` [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
- **4 место:** Значения по умолчанию из файла `.env`, лежащего в корне проекта (если не указан `env_file`) [Migrating to Docker Compose - MOOC.fi](https://courses.mooc.fi/org/uh-cs/courses/devops-with-docker-spring-2026/chapter-3/migrating-to-docker-compose).

> [!tip]  Совет инженера 
> Всегда используйте `.env` файл для локальной разработки, но в `compose.yaml` оставляйте только названия ключей без значений, если хотите, чтобы Docker брал их из окружения CI/CD-системы [Docker для новичков — #3 Что нужно знать о Docker compose / Хабр](https://habr.com/ru/articles/804331/).
