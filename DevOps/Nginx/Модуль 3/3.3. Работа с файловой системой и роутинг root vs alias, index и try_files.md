Эффективное управление путями к файлам и логика их отдачи — это фундамент производительности Nginx. Для Middle DevOps инженера крайне важно понимать, как сервер трансформирует сетевой URI в физический путь на диске и как реализовать бесшовный роутинг для современных веб-приложений (SPA) и асинхронных бэкендов на FastAPI [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### Принципиальная разница между root и alias

Директивы `root` и `alias` определяют базовый путь на файловой системе, где Nginx будет искать запрашиваемые ресурсы. Однако механизм формирования итогового пути у них кардинально различается [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).

##### Директива root: Конкатенация пути

Директива `root` просто прибавляет URI запроса к указанному пути. **Формула:** `физический_путь = root + URI` [Configuring NGINX as a Web Server](https://docs.nginx.com/nginx/admin-guide/web-server/web-server/).

_Пример:_

```nginx
location /static/ {
    root /var/www/app;
}
```

При запросе `/static/css/style.css` Nginx будет искать файл по адресу `/var/www/app/static/css/style.css` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

##### Директива alias: Замена части URI

Директива `alias` заменяет ту часть URI, которая совпала с `location`, на указанный путь. **Формула:** `физический_путь = alias + (URI - совпавший_префикс_location)` [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).

_Пример:_

```nginx
location /static/ {
    alias /var/www/app/assets/;
}
```

При запросе `/static/css/style.css` Nginx отбросит префикс `/static/` и будет искать файл по адресу `/var/www/app/assets/css/style.css` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

> [!warning]  Критическая ошибка со слэшами
> При использовании `alias` внутри `location`, заданного строкой, крайне важно соблюдать симметрию слэшей. Если `location` заканчивается слэшем, то и путь в `alias` обязан им заканчиваться. Несоблюдение этого правила часто ведет к ошибкам доступа или некорректному формированию путей [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).

Специалисты рекомендуют использовать `root` везде, где это возможно, так как он более предсказуем и производителен [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### Директива index: Порядок поиска файлов

Директива `index` определяет список файлов, которые Nginx будет искать при запросе, заканчивающемся слэшем (то есть при запросе директории) [Руководство для начинающих](https://nginx.org/ru/docs/beginners_guide.html).

- **Алгоритм:** Nginx проверяет файлы в указанном порядке. Если первый файл найден, поиск прекращается и выполняется внутреннее перенаправление на этот файл [Как nginx обрабатывает запросы](https://nginx.org/ru/docs/http/request_processing.html).
- **Синтаксис:** `index index.html index.php;`.
- **Особенность:** Если ни один файл не найден, Nginx может выдать ошибку 403 (если автоиндекс выключен) или сгенерировать список файлов через модуль `autoindex` [Знакомство с Nginx Веб сервер на LInux / YouTube](https://www.youtube.com/watch?v=...).

#### try_files — золотой стандарт роутинга

Директива `try_files` проверяет существование файлов в заданном порядке и использует для обработки запроса первый найденный ресурс [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html). Это основной инструмент для работы с современными фронтенд-фреймворками и балансировки между статикой и динамикой [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Типовой синтаксис:** `try_files $uri $uri/ @backend;` [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).

1. **`$uri`**: Nginx проверяет, существует ли файл, точно соответствующий URI.
2. **`$uri/`**: Проверяет, существует ли такая директория.
3. **`@backend`** или **`/index.html`**: Если ничего не найдено, выполняется финальное действие — переход в именованный `location` (к FastAPI) или отдача главной страницы (для SPA) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

##### Решение задачи SPA (React/Vue/Angular)

В SPA-приложениях роутинг выполняется на стороне клиента. Если пользователь обновит страницу на пути `/user/profile`, сервер вернет 404, так как такого файла нет на диске. `try_files` решает это элегантно:

```nginx
location / {
    root /var/www/frontend/dist;
    try_files $uri $uri/ /index.html;
}
```

Nginx попробует отдать реальный файл (например, картинку), а если его нет — всегда будет отдавать `index.html`, позволяя JavaScript-роутеру перехватить управление [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

##### Фоллбэк на FastAPI/Uvicorn

В нашем сквозном примере высоконагруженного стека `try_files` позволяет защитить бэкенд от лишних запросов:

```nginx
location /api/ {
    try_files $uri @uvicorn;
}

location @uvicorn {
    proxy_pass http://unix:/run/uvicorn.sock;
    include proxy_params;
}
```

Если в папке API случайно окажется статический файл, Nginx отдаст его мгновенно, не нагружая Event Loop бэкенда.

> [!warning]  Актуализация синтаксиса
> В старых конфигурациях часто использовалась проверка `if (!-f $request_filename)`. В современном Nginx 1.29+ использование `if` внутри `location` для проверки существования файлов считается небезопасным и неэффективным. Необходимо использовать `try_files` [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
