В данном разделе собраны фундаментальные термины, определяющие логику маршрутизации запросов и взаимодействия Nginx с файловой системой и бэкенд-приложениями.

- **Virtual Host (Server Block)** — механизм логического разделения одного физического сервера на несколько независимых веб-ресурсов, различаемых по IP-адресу, порту или заголовку `Host` [Configuring NGINX as a Web Server](https://docs.nginx.com/nginx/admin-guide/web-server/web-server/).
- **Catch-all Server** — конфигурация блока `server` с флагом `default_server`, предназначенная для перехвата и обработки (или сброса) запросов, которые не соответствуют ни одному явно указанному `server_name` [Как nginx обрабатывает запросы](https://nginx.org/ru/docs/http/request_processing.html).
- **Location Modifiers** — специальные символы (` = `, `^~`, `~`, `~*`), определяющие тип сопоставления URI и приоритет выбора конкретного блока `location` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **Prefix Match** — стандартный метод поиска `location`, при котором Nginx ищет наиболее длинное совпадение начала URI со строкой, указанной в конфигурации [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
- **Regex Match** — сопоставление URI с использованием регулярных выражений (чувствительных или нечувствительных к регистру), выполняемое после проверки префиксных совпадений [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).
- **Root Directive** — директива, формирующая путь к файлу путем простой конкатенации значения `root` и полного URI запроса [Руководство для начинающих](https://nginx.org/ru/docs/beginners_guide.html).
- **Alias Directive** — директива, которая заменяет часть URI, совпавшую с `location`, на указанный путь в файловой системе [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).
- **try_files Fallback** — механизм последовательной проверки существования файлов или директорий, завершающийся внутренним перенаправлением на указанный URI или именованный `location` [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

## Практическое упражнение (Точная настройка маршрутизации для SPA-фронтенда и FastAPI/Uvicorn бэкенда)

**Сценарий:** Вам необходимо развернуть высокопроизводительный контур для приложения `app.example.com`. Система состоит из React-фронтенда (SPA), API на FastAPI и внешнего хранилища медиа-файлов.

### Техническое задание:

1. **Безопасность:** Запросы по прямому IP-адресу или с неверным `Host` должны мгновенно обрываться (код 444) [Как nginx обрабатывает запросы](https://nginx.org/ru/docs/http/request_processing.html).
2. **SPA:** Статика фронтенда лежит в `/var/www/frontend`. Необходимо обеспечить работу клиентского роутинга (все несуществующие пути отдают `index.html`) [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
3. **API:** Запросы `/api/v1/` должны передаваться на асинхронный бэкенд Uvicorn через именованный `location` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
4. **Медиа:** Запросы `/media/` должны отображаться на папку `/var/data/uploads/` с использованием `alias` [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).
5. **Оптимизация:** Использовать ` = ` для корня и `^~` для статических путей, чтобы исключить лишние проверки регулярных выражений [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).

### Итоговый файл конфигурации (`/etc/nginx/conf.d/app.conf`):

```nginx
# 1. Catch-all сервер для защиты от мусорного трафика
server {
    listen 80 default_server;
    server_name _;
    return 444; # Немедленный разрыв TCP-соединения
}

# 2. Основной виртуальный хост приложения
server {
    listen 80;
    server_name app.example.com;

    # Оптимизация обработки корня
    location = / {
        root /var/www/frontend;
        try_files /index.html =404;
    }

    # SPA Фронтенд: отдача статики и клиентский роутинг
    location / {
        root /var/www/frontend;
        # Если файл не найден, отдаем index.html для JS-роутера
        try_files $uri $uri/ /index.html;
    }

    # API Бэкенд (FastAPI/Uvicorn)
    location /api/v1/ {
        # Сначала ищем файл (например, документацию), если нет - на бэкенд
        try_files $uri @backend;
    }

    location @backend {
        proxy_pass http://unix:/run/uvicorn.sock;
        include proxy_params;
    }

    # Медиа-хранилище через alias
    # Модификатор ^~ отключает проверку Regex для этого пути
    location ^~ /media/ {
        alias /var/data/uploads/;
        access_log off;
        expires 30d;
    }
}
```

### Валидация и тестирование:

1. **Проверка синтаксиса:** `sudo nginx -t` [Руководство для начинающих](https://nginx.org/ru/docs/beginners_guide.html) _Ожидаемый вывод:_ `syntax is ok`, `test is successful`.
    
2. **Тест защиты (запрос по IP):** `curl -I 127.0.0.1` _Ожидаемый результат:_ `curl: (52) Empty reply from server` (соединение сброшено кодом 444) [Как nginx обрабатывает запросы](https://nginx.org/ru/docs/http/request_processing.html).
    
3. **Тест SPA-роутинга:** `curl -I http://app.example.com/user/profile` _Ожидаемый результат:_ `HTTP/1.1 200 OK`, при этом реально будет отдан контент `/index.html` [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    
4. **Тест API:** `curl -I http://app.example.com/api/v1/users` _Ожидаемый результат:_ Заголовок `Server: uvicorn` (или ваш кастомный) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
