В данном разделе систематизированы ключевые понятия, определяющие производительность и эффективность механизмов временного хранения и передачи данных в Nginx.

- **Proxy Cache Keys Zone** — выделенная область в разделяемой памяти сервера, предназначенная для хранения метаданных и ключей закэшированных ответов бэкенда [NGINX Content Caching](https://docs.nginx.com/nginx/admin-guide/content-cache/content-caching/).
- **X-Cache-Status** — стандартная переменная `$upstream_cache_status`, выводимая в HTTP-заголовки для мониторинга состояния кэша (HIT, MISS, EXPIRED и др.) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **Zero-Copy (sendfile)** — технология ядра Linux, позволяющая копировать данные напрямую из дискового буфера в сетевой сокет, полностью минуя пространство пользователя (User-Space) [Оптимизация производительности Nginx/Angie / YouTube](https://www.youtube.com/watch?v=...).
- **tcp_nopush / tcp_nodelay** — сетевые опции сокетов, где первая накапливает данные для отправки полными пакетами, а вторая отключает алгоритм Нагла для мгновенной передачи мелких пакетов [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).
- **Client-side Caching (Cache-Control)** — набор директив, инструктирующих браузер пользователя сохранять статические файлы локально для исключения повторных запросов к серверу [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **Gzip Compression** — классический алгоритм сжатия текстовых данных «на лету», снижающий объем трафика до 70-80% [Модуль ngx_http_gzip_module](https://nginx.org/ru/docs/http/ngx_http_gzip_module.html).
- **Brotli Algorithm** — современный алгоритм сжатия от Google, обеспечивающий более высокую плотность упаковки текстовых ресурсов по сравнению с Gzip при сопоставимых затратах CPU [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
- **Cache Lock** — механизм сериализации запросов к бэкенду, предотвращающий «кэш-шторм» путем пропуска только одного запроса на обновление протухшего элемента [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

## Практическое упражнение (Комплексная оптимизация Nginx: Кэширование ответов FastAPI, Zero-Copy отдача статики и Gzip/Brotli сжатие)

**Сценарий:** Нагрузочное тестирование показало, что при 1000 RPS бэкенд на FastAPI потребляет 100% CPU из-за генерации тяжелых JSON-ответов каталога и отдачи JS-бандлов фронтенда. Необходимо внедрить многоуровневое кэширование и оптимизировать сетевой стек ядра Linux.

### Техническое задание:

1. **Backend Cache:** Настроить `proxy_cache` с зоной 100 МБ. Кэшировать только GET-запросы эндпоинта `/api/v1/catalog` на 5 минут. При падении бэкенда отдавать старые данные (`STALE`).
2. **Static Zero-Copy:** Включить `sendfile` и `tcp_nopush` для секции `/static/`. Установить срок жизни браузерного кэша — 1 год.
3. **Compression:** Настроить Gzip и Brotli (степень 4-6) для JSON и CSS.
4. **Monitoring:** Вывести статус кэша в заголовок `X-Cache-Status`.

### Итоговый файл конфигурации (`/etc/nginx/conf.d/optimized_app.conf`):

```nginx
# 1. Глобальная зона кэша (в http контексте)
proxy_cache_path /var/cache/nginx/api levels=1:2 keys_zone=API_ZONE:100m inactive=60m max_size=1g;

server {
    listen 443 ssl;
    server_name market.example.com;

    # Общие настройки сжатия
    gzip on;
    gzip_comp_level 5;
    gzip_types application/json text/css;

    brotli on; # Требует установленного модуля
    brotli_comp_level 4;
    brotli_types application/json text/css;

    # Кэширование каталога (FastAPI)
    location /api/v1/catalog {
        proxy_cache API_ZONE;
        proxy_cache_valid 200 5m;

        # Fallback на старый кэш при сбоях бэкенда
        proxy_cache_use_stale error timeout updating http_500 http_502 http_503 http_504;

        # Защита от кэш-шторма
        proxy_cache_lock on;

        # Мониторинг
        add_header X-Cache-Status $upstream_cache_status;

        proxy_pass http://unix:/run/uvicorn.sock;
        include proxy_params;
    }

    # Оптимизация статики фронтенда
    location /static/ {
        root /var/www/frontend;

        # Zero-Copy отдача через ядро
        sendfile on;
        tcp_nopush on;
        tcp_nodelay on;

        # Браузерный кэш "навсегда"
        expires 365d;
        add_header Cache-Control "public, no-transform, immutable";

        access_log off;
    }
}
```

### Результаты проверок и измерений:

1. **Валидация кэша:** `curl -I https://market.example.com/api/v1/catalog` _Первый запрос:_ `X-Cache-Status: MISS` _Второй запрос:_ `X-Cache-Status: HIT` (TTFB снизился с 200мс до 5мс).
    
2. **Тест сжатия:** `curl -H "Accept-Encoding: br" -I https://market.example.com/api/v1/catalog` _Ожидаемый результат:_ `Content-Encoding: br`.
    
3. **Нагрузочный тест (`wrk`):** `wrk -t12 -c400 -d30s https://market.example.com/api/v1/catalog` _Результат до оптимизации:_ 150 RPS, CPU бэкенда 100%. _Результат после:_ 8500+ RPS, CPU бэкенда < 5% (запросы обрабатываются Nginx из памяти).
