В данном разделе систематизированы ключевые понятия, определяющие современные подходы к сбору телеметрии и обеспечению наблюдаемости (Observability) высоконагруженных систем на базе Nginx.

- **log_format JSON** — механизм структурирования журналов доступа в формате объектов JSON с использованием параметра `escape=json` для корректной обработки спецсимволов и автоматизации парсинга внешними системами аналитики [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **Conditional Logging (Условное логирование)** — технология фильтрации записей в `access_log` на основе логических условий (параметр `if`), позволяющая исключать неинформативный трафик, такой как Health Checks, для экономии ресурсов [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **Upstream Response Time** — метрика (переменная `$upstream_response_time`), фиксирующая чистое время обработки запроса бэкендом (FastAPI/Uvicorn), что критично для разделения сетевых задержек и проблем в бизнес-логике [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **stub_status Module** — встроенный модуль Nginx, предоставляющий базовые счетчики состояния соединений и запросов в реальном времени через текстовый эндпоинт [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **Active/Waiting Connections** — показатели модуля мониторинга, где `Active` отражает общее количество открытых сессий, а `Waiting` — число простаивающих Keep-Alive соединений [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **nginx-prometheus-exporter** — вспомогательный сервис (агент), преобразующий сырые данные из `stub_status` в формат OpenMetrics для сбора системой Prometheus [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **OpenMetrics Standard** — современный промышленный стандарт представления метрик в виде временных рядов, используемый экосистемой Prometheus и Grafana [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **PromQL Scrape Job** — конфигурационная единица в Prometheus, определяющая периодичность и целевые адреса (targets) для сбора телеметрии с экспортера Nginx [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

## Практическое упражнение (Построение сквозной системы Observability: JSON-логирование Nginx + Uvicorn, stub_status и экспорт метрик в Prometheus)

**Сценарий:** Вы работаете над инфраструктурой высоконагруженного API на FastAPI. Для оперативного реагирования на инциденты необходимо настроить детальный мониторинг, позволяющий отслеживать производительность каждого запроса и состояние сетевого стека Nginx.

### Техническое задание:

1. **JSON Logging:** Создать формат `json_analytics` с экранированием. Включить `$upstream_response_time`, `$request_id` и `$request_time`.
2. **Log Optimization:** Включить буферизацию `access_log` и настроить `map` для исключения запросов к `/healthz`.
3. **Monitoring Endpoint:** Настроить `/stub_status` с ограничением доступа только для `localhost`.
4. **Prometheus Integration:** Подготовить параметры запуска `nginx-prometheus-exporter` и конфигурацию Scrape Job.

### Шаг 1: Конфигурация Nginx (`/etc/nginx/conf.d/observability.conf`)

```nginx
http {
    # Определение логики фильтрации логов
    map $request_uri $loggable {
        ~^/healthz    0;
        default       1;
    }

    # Структурированный формат логов для ELK/Vector
    log_format json_analytics escape=json '{'
        '"timestamp":"$time_iso8601",'
        '"request_id":"$request_id",'
        '"remote_addr":"$remote_addr",'
        '"method":"$request_method",'
        '"uri":"$request_uri",'
        '"status":$status,'
        '"size":$body_bytes_sent,'
        '"request_time":$request_time,'
        '"upstream_time":"$upstream_response_time",'
        '"upstream_addr":"$upstream_addr"'
    '}';

    server {
        listen 80;
        server_name api.example.com;

        # Буферизованный лог с условием
        access_log /var/log/nginx/access.json json_analytics buffer=32k flush=5s if=$loggable;

        location / {
            proxy_pass http://unix:/run/uvicorn.sock;
            # Передача ID запроса бэкенду для трассировки
            proxy_set_header X-Request-ID $request_id;
        }
    }

    # Изолированный сервер для метрик (внутренний порт)
    server {
        listen 8080;
        location /stub_status {
            stub_status;
            allow 127.0.0.1;
            deny all;
            access_log off;
        }
    }
}
```

### Шаг 2: Структура генерируемого JSON-лога
При выполнении запроса в файл будет записан объект:
```json
{
  "timestamp":"2026-07-27T10:15:30+03:00",
  "request_id":"5f9b3a2e7c1d4e8f9a0b1c2d3e4f5a6b",
  "remote_addr":"192.168.1.10",
  "method":"GET",
  "uri":"/api/v1/users",
  "status":200,
  "size":1024,
  "request_time":0.045,
  "upstream_time":"0.042",
  "upstream_addr":"unix:/run/uvicorn.sock"
}
```

### Шаг 3: Запуск экспортера и настройка Prometheus
Запуск Docker-контейнера экспортера для сбора данных с Nginx Open Source:
```bash
docker run -p 9113:9113 \
  nginx/nginx-prometheus-exporter:latest \
  -nginx.scrape-uri http://127.0.0.1:8080/stub_status
```.

Добавление задачи в `prometheus.yml`:
```yaml
scrape_configs:
  - job_name: 'nginx_edge'
    static_configs:
      - targets: ['localhost:9113']
```

### Шаг 4: Аналитические PromQL-запросы
1.  **Текущий RPS:** `rate(nginx_http_requests_total[1m])`.
2.  **Доля ошибок 5xx (требует логов или Nginx Plus):** В OSS версии через `stub_status` коды не видны, поэтому используем экспорт логов в Grafana Loki.
3.  **Среднее число запросов на соединение:** `nginx_http_requests_total / nginx_connections_handled`.

### Интерактивный тест для самопроверки

1. **Какой параметр `log_format` предотвращает "разлом" JSON-структуры, если в User-Agent клиента содержатся кавычки?**
    <details>
    <summary>Ответ</summary>
    Параметр `escape=json`. Он автоматически экранирует все недопустимые в JSON-строках символы.
    </details>

2. **Может ли `nginx-prometheus-exporter` собирать данные, если на целевом Nginx НЕ настроен `location /stub_status`?**
    <details>
    <summary>Ответ</summary>
    Нет. Экспортер является внешним агентом, который должен "скрейпить" (опрашивать) страницу статуса Nginx для получения данных.
    </details>

3. **Что означает метрика `Reading` в выводе `stub_status`?**
    <details>
    <summary>Ответ</summary>
    Количество соединений, в которых Nginx в данный момент вычитывает HTTP-заголовки запроса от клиента.
    </details>

4. **Как полностью отключить логирование для конкретного URI (например, статических картинок)?**
    <details>
    <summary>Ответ</summary>
    Использовать директиву `access_log off;` внутри соответствующего блока `location`.
    </details>

5. **Какая переменная в лог-файле показывает время, затраченное исключительно бэкендом (FastAPI) на ответ?**
    <details>
    <summary>Ответ</summary>
    Переменная `$upstream_response_time`.
    </details>
