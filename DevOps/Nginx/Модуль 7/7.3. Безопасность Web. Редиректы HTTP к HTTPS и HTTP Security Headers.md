В современной DevSecOps-практике Nginx рассматривается не только как точка входа для трафика, но и как первая линия обороны веб-приложения. Настройка безопасности на уровне протокола HTTP позволяет защитить пользователей от широкого спектра атак: от перехвата сессий (MITM) до внедрения вредоносного кода (XSS) и кражи кликов (Clickjacking).

#### 7.3.1. Принудительный переход на HTTPS: Организация редиректов

Обеспечение безопасности начинается с гарантированного перевода всех незашифрованных запросов (порт 80) на защищенный протокол (порт 443).

##### Сравнение методов: return 301 vs. 308

Традиционно для постоянного перенаправления использовался код `301 Moved Permanently`. Однако в контексте современных API на базе FastAPI/Uvicorn этот подход имеет критический недостаток: согласно спецификации, браузеры могут изменить метод запроса с `POST`/`PUT` на `GET` при выполнении редиректа 301 [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).

- **`return 301 https://$host$request_uri;`** — подходит для статических сайтов и простых страниц.
- **`return 308 https://$host$request_uri;`** — современный стандарт (появился в Nginx 1.13.0), который гарантирует сохранение исходного HTTP-метода и тела запроса при перенаправлении [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/). Это критично для мобильных приложений и фронтендов, взаимодействующих с API.

> [!warning] Актуализация синтаксиса 
> В устаревших руководствах часто встречается использование директивы `rewrite ^ https://$host$request_uri? permanent;` для редиректов. Однако использование `return` является более производительным и безопасным, так как оно не требует запуска движка регулярных выражений и немедленно прекращает обработку запроса.

#### 7.3.2. HTTP Security Headers: Защитные заголовки

Директива `add_header` позволяет внедрять в HTTP-ответ специфические инструкции для браузера, которые активируют встроенные механизмы защиты.

- **HSTS (Strict-Transport-Security)** — сообщает браузеру, что к данному домену (и поддоменам) следует обращаться исключительно по HTTPS в течение заданного времени.
    
    - `max-age=31536000` — срок действия (1 год).
    - `includeSubDomains` — защита всех поддоменов.
    - `preload` — включение домена в глобальный список предзагрузки HSTS [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    
    ```nginx
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
    ``` 
    [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    
- **CSP (Content-Security-Policy)** — мощный инструмент предотвращения XSS-атак за счет создания «белого списка» источников, из которых разрешено загружать скрипты, стили и изображения. По умолчанию рекомендуется ограничивать источники текущим доменом (`'self'`) [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
    
- **X-Frame-Options** — защита от Clickjacking. Заголовок запрещает отображение сайта внутри тегов `<iframe>`, предотвращая ситуации, когда злоумышленник накладывает прозрачный слой вашего сайта поверх своего [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
    
    - `DENY` — полный запрет фреймов.
    - `SAMEORIGIN` — разрешено только для страниц на том же домене [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **X-Content-Type-Options: nosniff** — отключает механизм «угадывания» (MIME-sniffing) типа контента браузером. Это предотвращает исполнение загруженных пользователем файлов (например, картинок) как исполняемых скриптов [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
    
- **Referrer-Policy** — контролирует объем информации о предыдущей странице, передаваемой в заголовке `Referer` при переходах по ссылкам, что критично для приватности пользователей [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    
- **Permissions-Policy** — современная замена `Feature-Policy`, позволяющая запретить использование функций устройства (камера, микрофон, геолокация) скриптами на странице, если они не требуются приложению [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
    

#### Пример эталонного блока безопасности:

```nginx
server {
    listen 80 default_server;
    server_name _;
    # Редирект с сохранением метода для API
    return 308 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name app.example.com;

    # SSL настройки (из 7.1 и 7.2) ...

    # Security Headers
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "no-referrer-when-downgrade" always;
    add_header Content-Security-Policy "default-src 'self' http: https: data: blob: 'unsafe-inline'" always;

    location / {
        proxy_pass http://uvicorn_backend;
    }
}
```

### Интерактивный тест для самопроверки

1. **В чем заключается архитектурная разница между кодами редиректа 301 и 308 при передаче данных на FastAPI?**
    <details>
    <summary>Ответ</summary>
    Редирект 301 может привести к потере данных `POST`-запроса, так как браузер вправе сменить метод на `GET`. Код 308 строго предписывает браузеру повторить запрос с тем же методом и телом. [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/)
    </details>

2. **Зачем в HSTS-заголовке использовать параметр `preload`, если уже указан `max-age`?**
    <details>
    <summary>Ответ</summary>
    `max-age` работает только после первого посещения сайта. Параметр `preload` позволяет включить домен в жестко прошитый список браузера, гарантируя использование HTTPS даже при самом первом обращении. [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>

3. **От какой конкретно атаки защищает установка заголовка `X-Frame-Options "DENY"`?**
    <details>
    <summary>Ответ</summary>
    От Clickjacking (угона клика) — атаки, при которой ваш интерфейс скрыто встраивается в другой сайт для обманного получения кликов пользователя. [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>

4. **Что произойдет, если Nginx отдаст файл `.txt` с JavaScript-кодом и заголовком `X-Content-Type-Options: nosniff`?**
    <details>
    <summary>Ответ</summary>
    Браузер откажется исполнять этот файл как скрипт, так как заголовок запрещает «угадывать» тип файла, отличный от того, что указан в `Content-Type`.
    </details>

5. **Какая директива Nginx позволяет настроить CSP таким образом, чтобы разрешить загрузку скриптов только с основного домена и домена `scripts.cdn.com`?**
    <details>
    <summary>Ответ</summary>
    Директива `add_header Content-Security-Policy "script-src 'self' scripts.cdn.com";`. [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>
