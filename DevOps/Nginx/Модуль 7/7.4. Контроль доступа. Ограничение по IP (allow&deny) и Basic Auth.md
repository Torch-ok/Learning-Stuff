Безопасность высоконагруженного веб-приложения не ограничивается только шифрованием трафика. Для Middle DevOps инженера критически важно обеспечить эшелонированную защиту (Security in Layers), создавая несколько фильтров на пути к чувствительным данным [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/). Nginx предоставляет два фундаментальных механизма контроля доступа на уровне протокола HTTP: ограничение по сетевым адресам и базовую аутентификацию.

#### 7.4.1. Модуль ngx_http_access_module: Ограничение по IP

Этот модуль позволяет разрешать или запрещать доступ к ресурсам на основе IP-адреса клиента или целых подсетей [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Механика работы:**

- **Директивы:** `allow` (разрешить) и `deny` (запретить) [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html).
- **Параметры:** Могут принимать конкретный IPv4/IPv6 адрес, CIDR-диапазон (например, `192.168.1.0/24`), ключевое слово `all` или путь к Unix-сокету [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **Порядок обработки (First Match Wins):** Nginx проверяет правила строго последовательно, сверху вниз. Как только найдено первое совпадение для IP-адреса клиента, проверка прекращается, и решение применяется немедленно [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

**Практический кейс: Защита служебных эндпоинтов FastAPI** Для FastAPI-приложений эндпоинты `/metrics` (для Prometheus) или автогенерируемая документация Swagger (`/docs`) не должны быть доступны всему интернету.

```nginx
location /metrics {
    allow 10.0.5.0/24;   # Разрешить только подсеть мониторинга
    allow 127.0.0.1;     # Разрешить локальный доступ
    deny all;            # Запретить всем остальным
    proxy_pass http://uvicorn_backend;
}
``` 
[NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

> [!warning] Актуализация синтаксиса
> При использовании Nginx за балансировщиком нагрузки или NAT, стандартный `$remote_addr` может содержать IP самого прокси [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/). В этом случае необходимо использовать модуль `ngx_http_realip_module` для восстановления реального IP клиента из заголовка `X-Forwarded-For`, иначе правила `allow/deny` будут работать некорректно [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).

#### 7.4.2. Модуль ngx_http_auth_basic_module: Basic Auth

Базовая HTTP-аутентификация — это простейший способ ограничить доступ к ресурсу по логину и паролю [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

**Принцип действия под капотом:**
1.  Клиент запрашивает защищенный URL.
2.  Nginx возвращает статус `401 Unauthorized` и заголовок `WWW-Authenticate: Basic realm="Restricted Area"` [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
3.  Браузер показывает окно ввода. Учетные данные склеиваются в строку `login:password`, кодируются в Base64 и отправляются в заголовке запроса `Authorization: Basic ...` [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
4.  Nginx декодирует заголовок и сверяет хэш пароля с файлом, указанным в `auth_basic_user_file` [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

**Управление паролями:**
Для генерации файла `.htpasswd` используется утилита из состава `apache2-utils`. Рекомендуется использовать стойкие алгоритмы хэширования, такие как `bcrypt` или `apr1` [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
```bash
# Создание файла с первым пользователем (хэш apr1)
htpasswd -c /etc/nginx/.htpasswd admin_user
``` 
[NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

**Конфигурация Nginx:**
```nginx
location /admin {
    auth_basic "Admin Panel";
    auth_basic_user_file /etc/nginx/.htpasswd;
    proxy_pass http://uvicorn_backend;
}
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

#### 7.4.3. Синергия: Директива satisfy

Nginx позволяет комбинировать несколько методов контроля доступа (IP-фильтр, Basic Auth, JWT) с помощью директивы `satisfy` [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

*   **`satisfy all`** (по умолчанию) — клиент должен пройти **все** проверки (и IP должен быть разрешен, и пароль введен верно) [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
*   **`satisfy any`** — достаточно выполнения **любого** одного условия [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

**Пример сценария "Офисный доступ":**
Разрешить сотрудникам из офисной сети (VPN) заходить в админку без пароля, а всем остальным — требовать аутентификацию.
```nginx
location /admin/ {
    satisfy any;

    allow 192.168.10.0/24; # Офисная подсеть
    deny all;              # Остальных блокируем по IP (но satisfy any позволит зайти по паролю)

    auth_basic "Restricted Access";
    auth_basic_user_file /etc/nginx/.htpasswd;
}
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

### Интерактивный тест для самопроверки

1. **Какой будет результат, если в конфиге указано сначала `deny 1.1.1.1;`, а следующей строкой `allow 1.1.1.1;`?**
    <details>
    <summary>Ответ</summary>
    Доступ будет запрещен. Nginx работает по принципу "First Match Wins": первое совпавшее правило (`deny`) прекращает проверку. [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>

2. **Почему Basic Auth КАТЕГОРИЧЕСКИ запрещено использовать без HTTPS в Production?**
    <details>
    <summary>Ответ</summary>
    Потому что логин и пароль передаются в заголовке `Authorization` в кодировке Base64, которая не является шифрованием. Любой злоумышленник может легко перехватить и декодировать их. [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>

3. **Что делает директива `auth_basic off;` внутри блока `location`, если на уровне `server` настроена аутентификация?**
    <details>
    <summary>Ответ</summary>
    Она отменяет действие аутентификации для данного конкретного `location`, делая его публичным. [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536)
    </details>

4. **В чем разница между `satisfy any` и `satisfy all` при наличии правил `allow` и `auth_basic`?**
    <details>
    <summary>Ответ</summary>
    При `any` доступ разрешается, если IP в списке разрешенных ИЛИ введен верный пароль. При `all` IP должен быть разрешен И пароль должен быть введен верно. [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>

5. **Какой код ошибки возвращает Nginx, если IP-адрес клиента попал под директиву `deny`?**
    <details>
    <summary>Ответ</summary>
    Код ошибки 403 Forbidden. [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/)
    </details>
