В данном разделе систематизированы ключевые понятия, описывающие механизмы взаимодействия Nginx с вышестоящими серверами приложений и управление контекстом сетевых запросов.

- **Reverse Proxy (Обратный прокси)** — сервер, который терминирует входящие соединения от клиентов и инициирует новые запросы к бэкенд-серверам (Upstreams) для выполнения задачи.
- **proxy_pass URI rewrite** — механизм трансформации пути запроса, зависящий от наличия завершающего слэша в директиве `proxy_pass`: при его наличии Nginx заменяет часть URI, совпавшую с `location`, на путь из директивы.
- **X-Forwarded-For** — стандартный HTTP-заголовок, используемый для передачи цепочки IP-адресов клиента и промежуточных прокси-серверов бэкенду.
- **Unix Domain Socket** — механизм межпроцессного взаимодействия (IPC), позволяющий Nginx и Uvicorn обмениваться данными через файл сокета в оперативной памяти, минуя сетевой стек ядра.
- **HTTP Upgrade Header** — заголовок, инициирующий смену протокола (например, с HTTP/1.1 на WebSocket), требующий явного проброса через настройки Nginx.
- **Proxy Buffering** — механизм сохранения ответа бэкенда во временных буферах Nginx, позволяющий освободить ресурсы сервера приложений до того, как клиент полностью вычитает данные.
- **504 Gateway Timeout** — код ошибки, возвращаемый Nginx, когда вышестоящий сервер не прислал ответ в течение времени, установленного директивой `proxy_read_timeout`.

## Практическое упражнение (Интеграция Nginx с асинхронным FastAPI / Uvicorn сервисом через Unix Socket и настройка WebSocket)

**Сценарий:** Нам необходимо развернуть Production-контур для высоконагруженного API. Приложение должно поддерживать стандартные REST-запросы, Real-time уведомления через WebSocket и потоковую отдачу данных (Streaming).

### Техническое задание:

1. **IPC:** Использовать Unix Domain Socket для минимизации Latency.
2. **Контекст:** Обеспечить прозрачность IP-адресов для FastAPI.
3. **WebSocket:** Реализовать поддержку полнодуплексного соединения с таймаутом 1 час.
4. **Streaming:** Отключить буферизацию для эндпоинта `/api/v1/stream`.
5. **Troubleshooting:** Решить проблему обрыва «тяжелых» запросов (симуляция 504 ошибки).

### Шаг 1: Запуск Uvicorn

Приложение FastAPI запускается с привязкой к файлу сокета и созданием необходимых директорий.

```bash
# Создаем директорию для сокета и даем права пользователю nginx
sudo mkdir -p /run/uvicorn
sudo chown -R www-data:www-data /run/uvicorn

# Запуск приложения (пример через CLI)
uvicorn main:app --uds /run/uvicorn/uvicorn.sock --workers 4
```

### Шаг 2: Конфигурация Nginx (`/etc/nginx/conf.d/fastapi.conf`)

```nginx
# Динамическое определение типа соединения для WebSocket
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

upstream uvicorn_backend {
    server unix:/run/uvicorn/uvicorn.sock; # Использование UDS
    keepalive 32; # Пул постоянных соединений с бэкендом
}

server {
    listen 443 ssl;
    server_name api.example.com;

    # Стандартные заголовки проксирования
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # 1. Основной API (симуляция тяжелого запроса)
    location /api/v1/ {
        proxy_pass http://uvicorn_backend;

        # Решение проблемы 504 Gateway Timeout для долгих расчетов
        proxy_read_timeout 300s;
        proxy_connect_timeout 5s;
    }

    # 2. WebSocket эндпоинт
    location /ws/ {
        proxy_pass http://uvicorn_backend;
        proxy_http_version 1.1; # Обязательно для Upgrade

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        # Удержание соединения при отсутствии трафика
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # 3. Streaming эндпоинт (отключение буферизации)
    location /api/v1/stream {
        proxy_pass http://uvicorn_backend;
        proxy_buffering off; # Мгновенная передача чанков клиенту
        proxy_max_temp_file_size 0; # Запрет записи на диск
    }
}
```

### Шаг 3: Проверка и симуляция 504 ошибки

1. **Валидация:** `sudo nginx -t` и `sudo systemctl reload nginx`.
2. **Тест API:** `curl -I https://api.example.com/api/v1/users` (проверка заголовка `X-Forwarded-For`).
3. **Тест WebSocket:** `wscat -c wss://api.example.com/ws/events`.
4. **Симуляция 504:** Установите `proxy_read_timeout 1s;` и вызовите эндпоинт FastAPI, который выполняет `time.sleep(5)`. Nginx вернет 504 через 1 секунду, не дождавшись ответа.
