В экосистеме Nginx 2026 года умение управлять трансформацией URI является обязательным навыком для проектирования API-шлюзов и микросервисных архитектур [10 Tips for Deploying NGINX as an API Gateway / YouTube](https://www.youtube.com/watch?v=...). Директивы `return` и `rewrite` представляют собой основные инструменты модуля `ngx_http_rewrite_module`, позволяющие изменять логику обработки запроса «на лету» [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).

#### 8.2.1. Директива return: Лаконичность и производительность

Директива `return` — это наиболее эффективный способ немедленно прекратить обработку запроса и вернуть клиенту специфический HTTP-статус или выполнить редирект [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Преимущества перед rewrite:**

1. **Производительность:** `return` не задействует механизм регулярных выражений PCRE. Она обрабатывается значительно быстрее, так как Nginx просто считывает статус и (опционально) URL [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
2. **Безопасность:** Отсутствие сложных правил исключает риск создания бесконечных циклов внутри сервера (internal redirection cycle) [Как nginx обрабатывает запросы](https://nginx.org/ru/docs/http/request_processing.html).
3. **Прозрачность:** Намерение инженера понятно сразу, в то время как логику сложного `rewrite` приходится «дешифровать» [Nginx — Простым языком на понятном примере / YouTube](https://www.youtube.com/watch?v=...).

**Типовые сценарии использования:**

- `return 301 https://$host$request_uri;` — постоянный редирект на HTTPS [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- `return 308 https://$host$request_uri;` — современный стандарт редиректа для API (FastAPI / Uvicorn), гарантирующий сохранение HTTP-метода (например, POST) [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
- `return 403;` — явный запрет доступа [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- `return 444;` — специальный код Nginx, который немедленно закрывает соединение без отправки заголовков ответа, что крайне эффективно при отражении атак сканеров [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).

> [!warning] Актуализация синтаксиса 
> Для простых редиректов (например, с `example.com` на `www.example.com`) всегда используйте `return` вместо `rewrite`. Это экономит ресурсы CPU и предотвращает лишние вызовы обработчика регулярных выражений [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### 8.2.2. Директива rewrite: Гибкость регулярных выражений

Директива `rewrite` предназначена для сложной трансформации URI на основе регулярных выражений PCRE [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html). Она позволяет захватывать части пути в переменные `$1..$9` и использовать их в новом адресе [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

Синтаксис: `rewrite regex replacement [flag];` [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).

#### 8.2.3. Флаги выполнения rewrite

Флаги определяют поведение Nginx после того, как URI был успешно изменен [Configuring NGINX and NGINX Plus as a Web Server](https://docs.nginx.com/nginx/admin-guide/web-server/web-server/).

1. **`last`**: прекращает обработку текущего набора директив `rewrite` и инициирует **новый цикл** поиска `location` с измененным URI [Configuring NGINX and NGINX Plus as a Web Server](https://docs.nginx.com/nginx/admin-guide/web-server/web-server/).
    - _Риск:_ Если правила составлены некорректно, может возникнуть цикл. Nginx ограничивает такие циклы 10 итерациями, после чего возвращает `500 Internal Server Error` [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).
2. **`break`**: прекращает обработку директив `rewrite` в текущем контексте и продолжает обработку запроса в **этом же** `location` без повторного поиска [Configuring NGINX and NGINX Plus as a Web Server](https://docs.nginx.com/nginx/admin-guide/web-server/web-server/). Обычно используется внутри `location`, чтобы избежать зацикливания [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
3. **`redirect`**: возвращает клиенту временный редирект (код 302) [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).
4. **`permanent`**: возвращает клиенту постоянный редирект (код 301) [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).

#### 8.2.4. Механика работы с аргументами ($args)

По умолчанию Nginx автоматически добавляет исходные аргументы запроса (все, что после `?`) к новому URI после выполнения `rewrite` [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).

Если вам необходимо **отсечь** старые параметры и оставить только новые (или сделать URI «чистым»), необходимо поставить символ `?` в самом конце строки замены [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

_Пример:_

```
# Исходные аргументы добавятся автоматически
rewrite ^/users/(.*)$ /api/v1/profile/$1;

# Исходные аргументы будут отсечены благодаря '?' в конце
rewrite ^/legacy-search/(.*)$ /new-search/$1? last;
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).

### Интерактивный тест для самопроверки

1. **Какая директива работает быстрее при необходимости простого перенаправления запроса?**
    <details>
    <summary>Ответ</summary>
    Директива `return`, так как она не требует запуска движка регулярных выражений PCRE [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
    </details>

2. **Что произойдет, если директива `rewrite` с флагом `last` создаст бесконечную цепочку перенаправлений?**
    <details>
    <summary>Ответ</summary>
    Nginx прекратит обработку после 10 циклов и вернет клиенту ошибку `500 Internal Server Error` с записью «rewrite or internal redirection cycle» в логах [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).
    </details>

3. **В чем разница между флагами `last` и `break` в директиве `rewrite`?**
    <details>
    <summary>Ответ</summary>
    Флаг `last` инициирует новый поиск подходящего `location` для измененного URI, а флаг `break` останавливает трансформации и заставляет Nginx остаться в текущем `location` [Configuring NGINX and NGINX Plus as a Web Server](https://docs.nginx.com/nginx/admin-guide/web-server/web-server/).
    </details>

4. **Как запретить Nginx добавлять старые Query-аргументы при перезаписи URL?**
    <details>
    <summary>Ответ</summary>
    Нужно поставить символ `?` в конце нового URI в директиве `rewrite` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
    </details>

5. **Что делает статус `return 444;`?**
    <details>
    <summary>Ответ</summary>
    Это нестандартный код Nginx, который заставляет сервер немедленно закрыть соединение, не отправляя клиенту никаких данных и заголовков [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).
    </details>
