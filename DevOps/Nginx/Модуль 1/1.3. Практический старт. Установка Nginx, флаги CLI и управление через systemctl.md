Для обеспечения максимальной производительности и безопасности в высоконагруженных окружениях Middle DevOps специалист должен использовать только официальные репозитории разработчика, так как пакеты в стандартных репозиториях дистрибутивов часто устаревают,,. Установка из официальных источников гарантирует наличие актуальных модулей, таких как `ngx_http_v2_module` или `ngx_http_ssl_module`, необходимых для работы современных протоколов,.

#### Установка из официальных репозиториев

**Для Ubuntu/Debian:** Для начала необходимо импортировать GPG-ключ для проверки подлинности пакетов и создать файл `/etc/apt/sources.list.d/nginx.list`, указав кодовое имя вашей версии (например, `jammy`, `focal` или `bookworm`),. После обновления индекса пакетов выполняется стандартная установка,:

```bash
wget http://nginx.org/keys/nginx_signing.key
apt-key add nginx_signing.key
apt-get update
apt-get install -y nginx
```

**Для RHEL/Rocky Linux:** В семействе RHEL (включая современные Rocky Linux и AlmaLinux) настройка производится через создание файла репозитория `/etc/yum.repos.d/nginx.repo`,. В параметре `baseurl` следует указать версию ОС (6 или 7 для старых систем или актуальную версию для новых),:

```bash
[nginx]
name=nginx repo
baseurl=http://nginx.org/packages/mainline/OS/OSRELEASE/$basearch/
gpgcheck=0
enabled=1
```

Установка завершается командой `yum install nginx`,.

> [!warning] Актуализация синтаксиса 
> В некоторых дистрибутивах до сих пор используется структура каталогов `sites-available` / `sites-enabled`, однако современным стандартом считается использование директории `/etc/nginx/conf.d/` с автоматическим включением всех `.conf` файлов в блоке `http` основного конфига,.

#### Работа с бинарным файлом: Ключи CLI

Утилита `nginx` предоставляет мощный интерфейс для управления рантаймом и отладки конфигурации,.

- **`nginx -v`**: Выводит только версию установленного бинарного файла,.
- **`nginx -V`**: Показывает версию, информацию о сборке и, что наиболее критично, все скомпилированные модули (`configure arguments`),. Это позволяет быстро проверить, поддерживает ли текущая сборка `Brotli`, `OpenSSL` или `AIO`,,.
- **`nginx -t`**: Проверка синтаксиса конфигурации,. Команда валидирует все файлы, включая `include`, и сообщает о найденных ошибках (например, пропущенной точке с запятой) без остановки текущего процесса,,.
- **`nginx -T`**: Аналогично `-t`, но дополнительно выводит полное содержимое всех подключенных файлов в консоль,. Это незаменимый инструмент при отладке сложных иерархий конфигураций, когда нужно увидеть итоговый «плоский» конфиг, который видит `Master`-процесс,.

#### Управление сигналами и рантаймом

Для управления работающим сервером используется ключ `-s` (send signal), который отправляет команды `Master`-процессу,.

1. **`nginx -s reload` (SIGHUP)**: Запускает механизм `Graceful Reload`,. `Master`-процесс перечитывает конфиг, проверяет его на ошибки и, в случае успеха, порождает новые `Worker`-процессы с обновленными параметрами,. Старым воркерам отправляется сигнал на завершение: они перестают принимать новые соединения и закрываются только после того, как дообслужат текущих клиентов,. Это позволяет обновлять конфигурацию в продакшене без потери пакетов,.
2. **`nginx -s stop` (SIGTERM)**: Немедленное завершение всех процессов сервера,. Соединения обрываются без ожидания.
3. **`nginx -s quit` (SIGQUIT)**: Плавное завершение работы,. Сервер дожидается окончания обработки активных запросов перед выходом,.
4. **`nginx -s reopen` (SIGUSR1)**: Переоткрытие лог-файлов, что критично для корректной ротации логов без перезапуска всего сервера,.

#### Управление через systemd

В современной инфраструктуре управление осуществляется через `systemctl`, который оборачивает сигналы бинарного файла в стандартные команды системного юнита,.

- `systemctl start nginx`: Запуск `Master`-процесса под пользователем `root`,,.
- `systemctl stop nginx`: Остановка сервера.
- `systemctl restart nginx`: Полная перезагрузка (сначала `stop`, затем `start`). Рекомендуется только в случае смены версии бинарного файла,.
- `systemctl reload nginx`: Отправка сигнала `reload` для горячего обновления конфига,.
- `systemctl status nginx`: Проверка состояния службы и просмотр последних строк из `error_log`,.
- `systemctl enable nginx`: Добавление сервера в автозагрузку при старте ОС,,.
