
В ежедневной практике DevOps-инженера лог-файлы Nginx являются «первоисточником истины» (source of truth) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536). Когда асинхронный стек на базе FastAPI / Uvicorn и PostgreSQL начинает давать сбои, именно `error_log` позволяет мгновенно локализовать проблему [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/). Понимание семантики HTTP-статусов и соответствующих им сообщений в логах — критический навык для минимизации MTTR (Mean Time To Recovery) [Troubleshooting Techniques / Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### 12.2.1. 502 Bad Gateway (Плохой шлюз)

Ошибка `502` означает, что Nginx, выступая в роли `proxy_pass`, получил недопустимый ответ или не смог установить соединение с апстримом [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Основные причины:**

1. **Бэкенд не запущен:** Процесс Uvicorn упал из-за `unhandled exception` или не стартовал [Troubleshooting Techniques / Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
2. **Проблемы с Unix-сокетом:** Файл `.sock` отсутствует, либо у пользователя `nginx` нет прав на чтение/запись в этот файл [Using the Mail Module / Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
3. **Некорректный протокол:** Nginx настроен на общение по FastCGI, а бэкенд ожидает HTTP (или наоборот) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Локализация в `error_log`:**

```text
[error] 6338#0: *1 connect() failed (111: Connection refused) while connecting to upstream, client: 127.0.0.1, upstream: "http://127.0.0.1:8000"
[error] 6338#0: *1 upstream prematurely closed connection while reading response header from upstream
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Алгоритм действий:**
*   Проверить статус сервиса: `systemctl status uvicorn`.
*   Проверить наличие сокета: `ls -la /run/uvicorn.sock` и права доступа к нему [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).

#### 12.2.2. 504 Gateway Timeout (Шлюз не отвечает)

Ошибка `504` возникает, когда бэкенд принял запрос, но не успел отдать ответ в рамках установленных лимитов времени [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Основные причины:**
1.  **Тяжелые запросы:** PostgreSQL выполняет сложную выборку дольше, чем позволяет `proxy_read_timeout` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
2.  **Зависание воркеров:** Все воркеры Uvicorn заняты длительными операциями (например, генерацией PDF или тяжелой математикой) [Основы NGINX глазами разработчика / YouTube](https://www.youtube.com/watch?v=...).

**Локализация в `error_log`:**
```text
[error] 2589#0: *1 upstream timed out (110: Connection timed out) while reading response header from upstream
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Алгоритм действий:**
*   Временно увеличить `proxy_read_timeout` (по умолчанию 60s) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
*   Проанализировать `slow_query_log` в PostgreSQL.

#### 12.2.3. 403 Forbidden (Доступ запрещен)

Nginx понял запрос, но категорически отказывается его выполнять [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Основные причины:**
1.  **Права доступа POSIX:** У пользователя `nginx` нет прав на выполнение (`+x`) для всех родительских папок пути или прав на чтение (`+r`) файла [Знакомство с Nginx / YouTube](https://www.youtube.com/watch?v=...).
2.  **Отсутствие индекса:** В `location` не найден файл, указанный в директиве `index` (например, `index.html`), а `autoindex` выключен [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
3.  **IP-блокировка:** Сработала директива `deny` или модуль `ngx_http_access_module` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Локализация в `error_log`:**
```text
[error] 2632#0: *1 directory index of "/var/www/static/" is forbidden
[error] 2632#0: *1 access forbidden by rule
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### 12.2.4. 413 Request Entity Too Large (Размер тела запроса слишком велик)

Ошибка возникает при попытке загрузить файл или отправить JSON, размер которого превышает установленный лимит [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Причина:** Тело запроса больше значения `client_max_body_size` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

**Локализация в `error_log`:**
```text
[error] 2589#0: *6437 client intended to send too large body: 13106010 bytes
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

> [!warning] Актуализация синтаксиса
> Учитывайте оверхед при кодировании (Base64/Multipart). Если нужно разрешить файл 12 МБ, устанавливайте `client_max_body_size 16m`, так как итоговое тело запроса будет примерно на 30% больше самого файла [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### 12.2.5. ERR_TOO_MANY_REDIRECTS (Цикл перенаправлений)

Эта ошибка видна в браузере, когда клиент попадает в бесконечную петлю редиректов.

**Основные причины:**
1.  **Петля HTTPS:** Nginx делает редирект HTTP -> HTTPS, но не видит заголовка `X-Forwarded-Proto` от внешнего балансировщика (Cloudflare/AWS ALB) и считает, что запрос все еще идет по HTTP [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
2.  **Rewrite loop:** Директива `rewrite` с флагом `last` внутри `location` совпадает сама с собой. Nginx ограничивает такие циклы 10 итерациями, после чего возвращает 500 ошибку [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html#internal).

**Алгоритм действий:**
*   Включить `rewrite_log on;` и проверить `error_log` на уровне `notice` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
*   Проверить корректность настройки `X-Forwarded-Proto` за прокси [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

### Интерактивный тест для самопроверки

1. **В чем ключевое отличие ошибки 502 от 504 при работе с бэкендом Uvicorn?**
    <details>
    <summary>Ответ</summary>
    502 означает, что Nginx вообще не смог договориться с Uvicorn (сервис упал или закрыл соединение), а 504 — что Uvicorn принял запрос, но «задумался» дольше разрешенного таймаута [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
    </details>

2. **Какую директиву нужно изменить, чтобы устранить ошибку 413 при загрузке тяжелых медиафайлов?**
    <details>
    <summary>Ответ</summary>
    `client_max_body_size`. Рекомендуется устанавливать значение с 30% запасом относительно ожидаемого размера файла [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
    </details>

3. **Сколько циклов внутренних перенаправлений (internal redirects) допускает Nginx до возврата ошибки 500?**
    <details>
    <summary>Ответ</summary>
    Максимум 10 циклов [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html#internal).
    </details>

4. **Что означает ошибка в логе "directory index of ... is forbidden"?**
    <details>
    <summary>Ответ</summary>
    Клиент запросил каталог (путь заканчивается на `/`), в котором нет индексного файла (например, `index.html`), а автоматическое перечисление файлов (`autoindex`) отключено [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
    </details>

5. **Какой нестандартный код Nginx можно использовать в `return` для немедленного разрыва соединения с атакующим ботом без передачи заголовков?**
    <details>
    <summary>Ответ</summary>
    Код `444` [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html#return).
    </details>
