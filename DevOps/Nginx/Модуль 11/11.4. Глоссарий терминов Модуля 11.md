В данном разделе собраны фундаментальные понятия, касающиеся расширения базовой функциональности Nginx через транспортный уровень проксирования и программируемые интерфейсы.

- **Stream Context (L4 Proxying)** — контекст конфигурации на транспортном уровне (OSI Layer 4), предназначенный для проксирования и балансировки пакетов TCP и UDP без разбора прикладного протокола (HTTP, SMTP и др.) [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
- **load_module Directive** — директива основного контекста (`main`), предназначенная для загрузки бинарных динамических модулей (`.so`) в оперативную память сервера во время старта [Основная функциональность](https://nginx.org/ru/docs/ngx_core_module.html#load_module).
- **Dynamic Module Binary Compatibility** — требование полной идентичности версии Nginx и флагов компиляции при сборке динамического модуля для предотвращения аварийного завершения (`segfault`) мастер-процесса [Development guide](https://nginx.org/en/docs/dev/development_guide.html#Modules), [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
- **OpenResty / LuaJIT** — программная платформа, объединяющая ядро Nginx с JIT-компилятором языка Lua, превращающая веб-сервер в высокопроизводительный программируемый API-шлюз [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Оптимизация производительности Nginx/Angie / YouTube](https://www.youtube.com/watch?v=...).
- **Cosockets (Coroutine Sockets)** — технология асинхронных неблокирующих сокетов в Lua, позволяющая выполнять сетевые запросы к базам данных (Redis, PostgreSQL) без остановки основного событийного цикла (`Event Loop`) рабочего процесса Nginx [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **access_by_lua_block** — фаза обработки запроса в Lua-модуле, предназначенная для реализации кастомных проверок прав доступа и авторизации перед передачей запроса контент-хендлеру или бэкенду [Setting up JWT Authentication](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-jwt-authentication/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **JWT Validation at Edge** — практика проверки цифровой подписи и срока действия токенов (JSON Web Token) непосредственно на стороне Nginx, что позволяет отсекать неавторизованный трафик до того, как он нагрузит бэкенд FastAPI [10 Tips for Deploying NGINX as an API Gateway / YouTube](https://www.youtube.com/watch?v=...), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
- **TCP Load Balancing** — распределение входящих TCP-соединений между группой серверов (например, кластером PostgreSQL) на основе алгоритмов балансировки (Round Robin, Least Conn) [TCP Load Balancing / NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

## Практическое упражнение (Построение гибридного Gateway: TCP-балансировка PostgreSQL через Stream и валидация JWT-авторизации на Lua)

**Сценарий:** Архитектура проекта 2026 года требует, чтобы Nginx выполнял две роли одновременно: выступал в качестве балансировщика для базы данных PostgreSQL и работал как интеллектуальный шлюз (Edge Gateway) для API на FastAPI, проверяя JWT-токены пользователей.

### Шаг 1: Конфигурация TCP-балансировщика (блок stream)

Конфигурация `stream` выносится за пределы блока `http`.

```nginx
# В файле /etc/nginx/nginx.conf
load_module modules/ngx_http_lua_module.so; # Динамическая загрузка Lua

stream {
    upstream postgres_cluster {
        least_conn; # Алгоритм для длинных сессий БД
        server 10.0.0.1:5432 max_fails=3 fail_timeout=30s; # Нода 1
        server 10.0.0.2:5432 max_fails=3 fail_timeout=30s; # Нода 2
    }

    server {
        listen 5432;
        proxy_pass postgres_cluster; # Проксирование на уровне L4
        proxy_connect_timeout 5s;
        proxy_timeout 1h; # Длительное удержание сессий БД
    }
}
``` 
[TCP Load Balancing / NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [ngx_stream_proxy_module](https://nginx.org/ru/docs/stream/ngx_stream_proxy_module.html).

### Шаг 2: Настройка JWT-валидации на Lua (блок http)
Реализуем проверку заголовка `Authorization` прямо на входе в защищенный эндпоинт.
```nginx
http {
    server {
        listen 443 ssl;
        server_name api.example.com;

        location /api/v1/secure/ {
            access_by_lua_block {
                local headers = ngx.req.get_headers()
                local auth_header = headers["Authorization"]

                -- Проверка наличия Bearer токена
                if not auth_header or not string.match(auth_header, "Bearer%s+.+") then
                    ngx.status = ngx.HTTP_UNAUTHORIZED
                    ngx.header.content_type = "application/json"
                    ngx.say('{"error": "Unauthorized: Bearer token missing"}')
                    return ngx.exit(ngx.HTTP_UNAUTHORIZED)
                end

                -- Здесь может быть вызов lua-resty-jwt для проверки подписи
                -- Для упражнения: проверяем только структуру (непустой токен)
            }

            proxy_pass http://fastapi_uvicorn;
            include proxy_params;
        }
    }
}
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [10 Tips for Deploying NGINX as an API Gateway / YouTube](https://www.youtube.com/watch?v=...), [Setting up JWT Authentication](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-jwt-authentication/).

### Шаг 3: Верификация работы
1.  **TCP Прокси:** Проверяем доступность порта: `nc -zv api.example.com 5432`. Должен вернуться статус `succeeded`.
2.  **SQL Тест:** `psql -h api.example.com -U user -d database`. Соединение будет прозрачно переброшено на одну из нод в `upstream postgres_cluster`.
3.  **Lua Тест:**
    *   `curl -i https://api.example.com/api/v1/secure/` -> Ожидаемый ответ: `HTTP 401 Unauthorized`.
    *   `curl -i -H "Authorization: Bearer mytoken" https://api.example.com/api/v1/secure/` -> Ожидаемый ответ: `HTTP 200 OK` (проксирование на FastAPI).

### Интерактивный тест для самопроверки

1. **Где должна располагаться директива `load_module` для корректной работы сервера?**
    <details>
    <summary>Ответ</summary>
    Строго на верхнем уровне файла `nginx.conf` (в Main Context), до начала блоков `http` или `stream` [Основная функциональность](https://nginx.org/ru/docs/ngx_core_module.html#load_module).
    </details>

2. **Какой алгоритм балансировки НЕ поддерживается в контексте `stream` (Layer 4)?**
    <details>
    <summary>Ответ</summary>
    Методы, основанные на содержимом HTTP-заголовков (например, привязка по Cookies), так как на уровне L4 данные заголовков недоступны [TCP Load Balancing / NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    </details>

3. **Что делает функция `ngx.exit()` в Lua-скрипте Nginx?**
    <details>
    <summary>Ответ</summary>
    Немедленно завершает текущую фазу обработки запроса и возвращает указанный HTTP-статус клиенту [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
    </details>

4. **Какая команда используется для сборки только динамических модулей из исходного кода Nginx?**
    <details>
    <summary>Ответ</summary>
    Команда `make modules` после выполнения `./configure --add-dynamic-module=...` [Development guide](https://nginx.org/en/docs/dev/development_guide.html#Modules).
    </details>

5. **Может ли Nginx в режиме Stream балансировать трафик UDP (например, DNS или NTP)?**
    <details>
    <summary>Ответ</summary>
    Да, при использовании параметра `udp` в директиве `listen` блока `server` внутри контекста `stream` [UDP Load Balancing / NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    </details>
