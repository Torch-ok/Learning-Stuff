В архитектуре современных высоконагруженных систем Nginx перестал быть просто статическим веб-сервером, превратившись в полноценную платформу доставки приложений (Application Delivery Platform) [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/). Концепция программируемого веб-сервера реализуется через встраивание интерпретатора Lua (обычно в виде высокопроизводительного JIT-компилятора LuaJIT) непосредственно в событийный цикл (Event Loop) Nginx [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [ngx_http_lua_module / Nginx Docs](https://github.com/openresty/lua-nginx-module). Платформа OpenResty и модуль `ngx_http_lua_module` позволяют инженерам описывать сложную императивную логику внутри декларативного конфигурационного файла, превращая прокси в "умный" API-шлюз (API Gateway) [10 Tips for Deploying NGINX as an API Gateway / YouTube](https://www.youtube.com/watch?v=...), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

#### 11.3.1. Интеграция в Event Loop и фазы обработки запроса

Nginx обрабатывает каждый HTTP-запрос, проходя через строго определенную последовательность фаз [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html), [Development guide](https://nginx.org/en/docs/dev/development_guide.html#http_phases). Модуль Lua предоставляет специфические директивы для встраивания кода в большинство этих фаз [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).

- **`rewrite_by_lua_block`** (фаза `REWRITE`) — выполняется до того, как Nginx окончательно выберет `location` для запроса [Модуль ngx_http_core_module](https://nginx.org/ru/docs/http/ngx_http_core_module.html), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536). Здесь удобно реализовывать динамическую трансформацию URI, извлечение аргументов или установку переменных на основе сложной логики, которую невозможно описать стандартной директивой `map` [10 Tips for Deploying NGINX as an API Gateway / YouTube](https://www.youtube.com/watch?v=...), [Nginx для начинающих / Хабр](https://habr.com/ru/companies/gnivc/articles/977196/).
- **`access_by_lua_block`** (фаза `ACCESS`) — критическая точка для безопасности API-шлюза [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/). На этом этапе Lua может выполнять проверку прав доступа, валидировать JWT-токены или обращаться к Redis для проверки сессий [Setting up JWT Authentication](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-jwt-authentication/), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/). Это позволяет отсекать неавторизованные запросы на уровне Nginx, не нагружая асинхронный Event Loop бэкенда FastAPI / Uvicorn [Основы NGINX глазами разработчика / YouTube](https://www.youtube.com/watch?v=...), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
- **`content_by_lua_block`** (фаза `CONTENT`) — используется для полной генерации HTTP-ответа непосредственно внутри Nginx без проксирования на внешние серверы [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536). Идеально подходит для реализации легковесных микросервисов или моков для тестирования [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Основы NGINX глазами разработчика / YouTube](https://www.youtube.com/watch?v=...).
- **`header_filter_by_lua_block`** и **`body_filter_by_lua_block`** — фазы фильтрации, позволяющие динамически изменять заголовки или тело ответа, полученного от бэкенда, перед его отправкой клиенту [Development guide](https://nginx.org/en/docs/dev/development_guide.html#http_response_body_filters), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536). Например, здесь можно удалять чувствительные заголовки вроде `X-Powered-By` или инжектировать отладочную информацию [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

#### 11.3.2. Преимущества асинхронных сокетов (Cosockets)

Ключевым преимуществом Lua в экосистеме Nginx является использование **cosockets** (coroutine-based sockets) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536). Традиционные скриптовые языки при сетевом вызове (например, запрос к PostgreSQL) блокируют весь поток выполнения. В Nginx это означало бы остановку всего `worker_process`, обрабатывающего тысячи других соединений [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Оптимизация производительности Nginx/Angie / YouTube](https://www.youtube.com/watch?v=...).

Lua-скрипты в Nginx работают асинхронно: когда скрипт инициирует сетевую операцию, выполнение текущей корутины приостанавливается (`yield`), и Nginx переключается на обработку других событий [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Development guide](https://nginx.org/en/docs/dev/development_guide.html#event_loop). Как только данные от внешней системы получены, Nginx возобновляет выполнение скрипта (`resume`) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536). Для разработчика этот процесс выглядит как обычный синхронный код, но под капотом он использует неблокирующий I/O ядра Linux (`epoll`), обеспечивая экстремальную масштабируемость [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Development guide](https://nginx.org/en/docs/dev/development_guide.html#i_o_events).

#### 11.3.3. Прикладной пример: Валидация JWT перед проксированием на FastAPI

В данном сценарии Nginx выступает в роли "щита", который проверяет наличие и валидность токена в заголовке `Authorization`, прежде чем передать запрос на "тяжелый" бэкенд Uvicorn [10 Tips for Deploying NGINX as an API Gateway / YouTube](https://www.youtube.com/watch?v=...), [Setting up JWT Authentication](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-jwt-authentication/).

```nginx
location /api/v1/private {
    access_by_lua_block {
        local jwt = require "resty.jwt"
        local auth_header = ngx.var.http_Authorization

        if not auth_header then
            ngx.status = ngx.HTTP_UNAUTHORIZED
            ngx.say('{"error": "Missing Authorization header"}')
            return ngx.exit(ngx.HTTP_UNAUTHORIZED)
        end

        -- Пример извлечения токена и проверки через секрет
        local _, _, token = string.find(auth_header, "Bearer%s+(.+)")
        local jwt_obj = jwt:verify("SUPER_SECRET_KEY", token)

        if not jwt_obj.verified then
            ngx.status = ngx.HTTP_FORBIDDEN
            ngx.say('{"error": "Invalid token"}')
            return ngx.exit(ngx.HTTP_FORBIDDEN)
        end

        -- Передаем идентификатор пользователя из JWT в заголовке на FastAPI
        ngx.req.set_header("X-User-ID", jwt_obj.payload.sub)
    }

    proxy_pass http://uvicorn_backend;
}
``` 
[Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Setting up JWT Authentication](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-jwt-authentication/), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).

> [!warning] Актуализация синтаксиса
> Хотя Lua позволяет гибко управлять логикой, для базовой JWT-авторизации в Nginx Plus рекомендуется использовать встроенную директиву `auth_jwt`, которая оптимизирована на уровне C-кода и работает быстрее любого скрипта [Setting up JWT Authentication](https://docs.nginx.com/nginx/admin-guide/security-controls/configuring-jwt-authentication/).

### Интерактивный тест для самопроверки

1. **В чем заключается главное архитектурное преимущество LuaJIT в Nginx по сравнению со стандартным встроенным модулем Perl?**
    <details>
    <summary>Ответ</summary>
    Lua в Nginx (через cosockets) является полностью неблокирующим и асинхронным, в то время как Perl-модуль часто приводит к блокировкам Worker-процесса при выполнении I/O операций [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Complete-NGINX-Cookbook-2019](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    </details>

2. **Какая директива Lua позволяет прервать обработку запроса и вернуть клиенту специфический HTTP-код (например, 403)?**
    <details>
    <summary>Ответ</summary>
    Функция `ngx.exit(status_code)` [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [ngx_http_lua_module / Nginx Docs](https://github.com/openresty/lua-nginx-module).
    </details>

3. **Можно ли использовать Lua для модификации URI запроса так, чтобы Nginx заново начал поиск подходящего `location`?**
    <details>
    <summary>Ответ</summary>
    Да, для этого используется директива `rewrite_by_lua_block` совместно с функцией `ngx.req.set_uri(uri, true)`, где второй параметр `true` инициирует внутреннее перенаправление (аналог флага `last` в `rewrite`) [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [Модуль ngx_http_rewrite_module](https://nginx.org/ru/docs/http/ngx_http_rewrite_module.html).
    </details>

4. **Что такое OpenResty?**
    <details>
    <summary>Ответ</summary>
    Это полноценная программная платформа, объединяющая стандартное ядро Nginx, LuaJIT и большой набор высококачественных Lua-библиотек (для работы с Redis, MySQL, JSON и др.) для построения масштабируемых веб-приложений [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536), [NGINX_Cookbook-final](https://www.nginx.com/resources/library/complete-nginx-cookbook/).
    </details>

5. **Где хранятся переменные Nginx, к которым обращается Lua через `ngx.var`?**
    <details>
    <summary>Ответ</summary>
    Они хранятся в контексте текущего запроса и доступны во всех фазах его обработки внутри Nginx [Development guide](https://nginx.org/en/docs/dev/development_guide.html#http_variables), [Mastering Nginx](https://www.packtpub.com/product/mastering-nginx/9781785283536).
    </details>
